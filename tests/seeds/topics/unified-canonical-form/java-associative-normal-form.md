# Hello World：交换输入后的唯一加法形式

## 设计意图

检验纯全域加法／乘法在排列和不同结合树下得到同一式子。减法和文本拼接是对照，不能因符号相似而排序或消去效果。

## 输入原始代码

入口把两个业务数值相加，参数顺序与结果的唯一表达形式分开观察。

```java
class Order {
    static int total(int base, int value) {
        return value + base;
    }
}
```

## AI 预处理结果

**原样通过。** 加法是 Java 原生表达式，操作数排序交给统一定形规范。

## 归一化最终结果

```yaml
schema: normalizer.pers/1

entry:
  function: src/Order.java#Order.total
  returns: number

P:
  parameters:
    base:
      position: 0
      type: number
    value:
      position: 1
      type: number

R: base + value
```

### 同形与异形的判别

- 精确加法：`(value + 2) + base` 和 `2 + (base + value)` 均归到 `base + value + 2`。证明来自同一加法族的交换、结合律；常量处在该规则指定的位置。
- 精确乘法：`value * (base * value)` 和 `(value * value) * base` 均归到 `base * value * value`。同一个因子出现两次仍表示乘两次，不采用 Boolean 的幂等去重。
- 加法和乘法不互相归并；例如 `base = 3, value = 2` 时，两组扩展分别得到 7 和 12。
- 单个完整 CASE 与一个简单、已取得的操作数相减时，只有进入两臂可证明最终更简单，才把减法分到两臂；被减数和减数不能换边。`base - (value > 0 ? 3 : 7)` 与 `(value > 0 ? 3 : 7) - base` 都不会因此消去减法，唯一结果分别保持减法在 CASE 外的原方向。两边都为 CASE 时，不为分配而交叉展开分支。

### 常量先按已取得的领域执行

整数取负在同一精确数值域内执行，不因表达式内部使用紧凑整数或大整数存储而改变。对没有具体取值的整数输入仍保留求负；布尔取反属于独立规则，不引入某门语言的数字真值转换。已被业务显式观察的机器行为按《业务至上》处理，不由普通常量折叠猜测。

### 已取得精确值的同项相减

- 直接入口整数 `value - value` 对每个输入都等于 `0`。两个参数仍留在 P，不因结果不再引用它们而改变入口契约；不产生 E、S 或异常。
- `(value > 0 ? value : value + 2) - value` 只在两条原有首命中域里做减法：正数域为 `0`，零和负数域为 `2`。先按取得域算出分支值，再按完整 CASE 比较，两向同复杂度时此处的 `>` 排在补守卫的 `<` 前；唯一结果是 `CASE WHEN value > 0 THEN 0 ELSE 2 END`，不新增观察。这个结论依赖同一个已经取得的精确数值；不允许合并两次求值或把条件取得的东西挪出保护域。

**预处理要点**：交换律和唯一排序属于内核统一定形，预处理不介入可直接解析的表达式。

**PERS 验收要点**：等价表达式必须收敛到唯一形式，expected 才能直接比较而不依赖字符串写法。

已取得的精确整数无论来自入口还是同一关系行，都用同一套代数规则合并常量偏移。若行值尚未取得、可能为空或缺少精确整数的证据，则不删保护或套用整数结论。例如在已取得的精确整数域，`x + 1 > x` 恒真，`x - 1 > x` 恒假；不能因为两个操作都有常量 1 就当作同一偏移。

CASE 上单边探查受节点总数和树深度预算约束；无法证明净化简时保持 CASE。部分 CASE 只能在自身已有的正常域内探查，不能补默认，也不能把减数和被减数换边。

已取得的精确整数入参没有求值缺口，`0 * (value * 5)` 归约为 0。这个值简化本身不授权删除原本有序的调用或读取。

两个偏移量围绕同一个已经取得的精确整数时，可以先相减偏移量。例如 `(x + 1) - (x + 2)` 归约为 -1，`(x - 4) - (x - 2)` 归约为 -2。若两个基值分别是 `x` 和 `y`，只能消去共同的字面量偏移，不把两个入参当成一项。
