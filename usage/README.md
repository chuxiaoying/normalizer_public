# 使用 Normalizer

**第一次用？先跑通一个例子，再分析自己的项目。** Normalizer 从选定的程序入口提取业务逻辑，输出 PERS：描述入参、环境、正常返回、业务异常和可观察副作用的 YAML。它符号化描述真实调用和写入，不启动原应用，不向真实服务发请求。

1. **先试用。** 按[新手入门](getting-started.md)运行 Java 或 TypeScript 的最小例子，也可以试前端 VO 生产和消费。所有示例已经准备好，不需要先做 AI 预处理。
2. **换成自己的项目。** 按[输入清单](kernel-input.md)确定需要交付的文件。已符合纯净、强类型和有界要求的 Java 可以原样交付；需要理解框架、根据证据恢复类型或重组入口时，把源码、真实入口和观察范围连同[AI 预处理 Skill](skills/normalizer-preprocess/SKILL.md)交给 agent。CLI 不替你调用 AI，也不读取原始模板、配置或框架工程来补出运行步骤。
3. **运行并看结果。** 用 [CLI 参考](cli.md)选命令。退出码为 0 时读标准输出中的 PERS；非零时读标准错误中的诊断。没有 PERS 不等于业务返回了空值。CLI 只分析交给它的源码。如果副本为了通过分析删掉了原有业务动作，这次输出必须作废。验收时从原入口核对完整结果；有 T 时，也要核对返回值或动作引用的纯定义。

## 用户说「把这张欠费单页面归一化」

先弄清用户想知道什么。「点查询后，页面发了什么请求、把结果写到哪里」对应**前端生产**；「欠费金额怎么显示、还款按钮什么时候可点」对应**前端消费**。两种问题都有，就分别做两侧。

再定入口范围。用户说「只看还款按钮为什么不可点」，就选这个按钮的可用性属性；说「做整页生产」，就找全这页实际的业务回调。只给了页面、方向或范围还不清楚时，可以拿真实绑定和用户商量，例如「看查询和还款触发了什么，还是看金额和按钮怎样显示？你关心其中几项，还是这一侧全部？」已经说清的直接办理。[按页面装配查候选入口](skills/normalizer-preprocess/SKILL.md#前端整页归一化)

范围确定后，每个入口按第九章对应场景做 AI 预处理，再按使用手册逐入口运行 CLI。拿到 YAML 后，参数从哪里来、发生过哪些动作、最后怎样结束，按第七章读。[第九章《场景归一》](../design/chapters/09-场景归一.md#规则区) · [前端 CLI 命令](cli.md#前端-vo-场景) · [第七章《PERS登场》](../design/chapters/07-PERS登场.md)

运行整个仓库的正式回归，见[测试区](../tests/README.md)。
