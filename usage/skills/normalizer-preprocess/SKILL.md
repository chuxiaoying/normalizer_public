# Normalizer AI 预处理

这一步发生在调用 CLI **之前**，由人指导 AI 或由工作 agent 独立完成。输入是原业务工程、待分析入口及可用的依赖和配置证据；输出是**可交给 Normalizer 的分析工程**和交付说明。原工程和取证材料放在分析工程之外，只用于复核，不把分析副本投入部署。CLI 不调用 AI。

先读[第四章《AI 救赎》](../../../design/chapters/第四章%20·%20AI%20救赎.md)。本指南组织工作顺序；规则和指令拼写以所链接的一级、二级设计为准。[种子](../../../design/examples/README.md)用来找有完整原件和改写的对照，不自行扩大支持范围。

## 1. 从入口找证据

- 先确定从哪一刻开始、调用哪个入口、到何时算完成，确认真实入参、返回或异常。边界确定后，保留范围内所有可达的业务观察，不能为了方便删去解析失败、回调或状态读取。若只交付局部入口，明确列出未覆盖部分，不称整页或原入口已归一化。
- 从入口沿可达调用查源码、构造和注入、实际配置和依赖合同。核对字段、泛型、输入输出和异常绑定。对外部接口同时核对接收者、签名和完成合同；若本地实现可见则保留本地实现。
- 分开入口入参、入口已有状态和执行中取得的值。已有状态不能变成调用参数，同一次分析入口执行中取得的外部回执，不能提前变成该入口的已知值或用预先算好的常量替代。观察时点、别名和写入顺序须有原工程证据。例如等待后的可变状态不能提前读，初始化时的值不能冒充每次入口的值；已确认是本次调用传入的固定参数，也不能当成每次读取都可能变化的宿主状态。见[第七章](../../../design/chapters/第七章%20·%20PERS%20登场.md)和[观察身份](../../../design/secondary/观察身份与稳定编号.md)。

## 2. 只改需要闭合的地方

已满足纯净工程约定的原生代码原样交付，包括普通分支和 `switch`；未知次数循环另证有界或给出等价的已定义整体表达。AI 不替内核选分支、折叠表达式、压成最终公式或生成新的业务结果入参。

| 遇到的情况 | 处理时对照 |
|---|---|
| 外壳可直接还原为原语言计算 | [换成原语言标准原生](../../../design/chapters/第四章%20·%20AI%20救赎.md#换成原语言标准原生)。核对空值、求值时点和失败，不能只换一个同名函数。 |
| 值操作要换成统一的已定义操作 | [标准操作与声明标记](../../../design/secondary/标准操作与声明标记.md)。认官方 `N` 的真实绑定和签名；精度、舍入、可空和时间读取按实际合同。 |
| SQL、集合或循环适合关系表达 | [第五章](../../../design/chapters/第五章%20·%20关系代数：让%20SQL%20和集合运算一起化简.md)及[关系指令](../../../design/secondary/关系指令的统一写法.md)。保留行来源、重复、顺序、空值、初值、早停及写操作；不能把有状态递推硬套为独立聚合。 |
| 可能与业务无关的宿主机制 | [直接删减业务无关代码](../../../design/chapters/第四章%20·%20AI%20救赎.md#直接删减业务无关代码)。只有宿主机制不符合纯净工程规范，且确实只服务实现、不改变业务观察时，才可删除；已符合纯净工程的计算，即使是优化代码，也留给内核执行。仍须保留实参的效果、异常和实际发生顺序。见[第六章](../../../design/chapters/第六章%20·%20业务至上.md)。 |
| 入口、已有状态或对象装配藏在框架里 | [入口重组](../../../design/chapters/第四章%20·%20AI%20救赎.md#入口函数重组)、[状态重组](../../../design/chapters/第四章%20·%20AI%20救赎.md#内存状态重组)、[隐藏执行过程](../../../design/chapters/第四章%20·%20AI%20救赎.md#把隐藏的执行过程写出来)。显式交付找到接收者的方式及真实生效的装配；不要用新对象替换入口已有状态。 |
| 本地实现不可见 | 按[第四章](../../../design/chapters/第四章%20·%20AI%20救赎.md)找依赖源码或可核实的定义。DTO 的签名、字段、序列化约定与用途一致时才按普通访问器还原。无从确认逻辑时报告缺口，不能仅凭签名把本地方法伪装成外部端口。 |
| 真正调用外部系统，或读取环境 | 端口按[外部调用约定](../../../design/chapters/第四章%20·%20AI%20救赎.md#重组和标记外部调用)交付实际接收者、接口及可核实的正常与失败合同。时钟等环境读取保留真实读取时点，参见[标准操作](../../../design/secondary/标准操作与声明标记.md)和[当前实现限制](../../cli.md#当前实现限制)；不支持就报告缺口，不改成另一类观察。 |

## 3. 做交付前检查

按[分析副本校验](../../../design/secondary/分析副本怎样通过校验.md)逐项核对：

1. **入口可唯一定位。** 提供工程相对路径加 `#入口调用`，不填调用实参；Java 实例入口有静态可达接收者，仅在需要区分重载时列源码参数类型。TS 从模块导出入口；设计上可通过已装配的对象方法定位，不能把真实接收者换成新对象来适配 CLI。要交给当前 CLI 时，按[当前实现限制](../../cli.md#当前实现限制)准备其接受的入口，不用设计范围推断当前适配器已经支持。
2. **类型清楚。** Java 的可达类型绑定只能来自工程源码、Normalizer 内置类型或设计约定的原生值类型，不能靠删导入绕过。JavaScript 根据构造点、调用链和消费点的全工程证据改成严格 TypeScript；仅为适配当前 CLI，且能证明不改变绑定、初始化或观察时，才将交付整理成一个模块；设计允许的多文件工程如果不能无损适配，就报告缺口。全模块不准显式、隐式或解析得到的 `any`，不压制类型检查。未知外部数据先用 `unknown`，原有校验、失败和有效收窄都保留。
3. **扩展闭合。** 用[第五章的语法表](../../../design/chapters/第五章%20·%20关系代数：让%20SQL%20和集合运算一起化简.md#六扩展语义语法表)核对标记和指令的放置、绑定、取得域和确定赋值。未知指令、未声明关系、无依据的失败合同不能用默认值或空实现补齐。闭合不了时保留原件，记录文件和位置、缺少的证据与受影响的观察，不产出猜测的分析工程。
4. **重组前端观察，不交付框架原件。** Vue、小程序等原件只作预处理证据；CLI 只收准备好的严格 TypeScript。生产入口保留真实等待、读取时点、失败与有序写入；消费入口交付同步无参的导出函数，用标记保留原属性身份，读取已有状态而不是重新渲染。不能把不等待的动作擅自改成等待。见[生产对照](../../../design/examples/topics/language-entries/frontend-vo-production-vue.md)与[消费对照](../../../design/examples/topics/language-entries/frontend-vo-consumption-vue.md)。

## 4. 交付并独立验收

交付完整分析工程、入口及观察范围；如需提供改写对照，使用保留未改行的 Git diff，并说明每处改写依赖的证据。如有缺口，把缺口与已交付范围分开，不把分析拒绝当作业务异常。不要把 PERS 结果混进分析工程。

准备好后由[正式 CLI](../../cli.md)运行。从原源码独立推导一份定形后的完整 PERS 或具体拒绝预期。核对 P、E、R、S 和业务异常（包括动作条件、顺序和回执），不只看返回值。不得用实际输出反填预期，也不得在验收侧先化简实际值再声称通过。[测试区](../../../tests/README.md)执行已交付的完整案例，不重放种子补丁、不运行 AI，也不证明 AI 的实时改写质量。
