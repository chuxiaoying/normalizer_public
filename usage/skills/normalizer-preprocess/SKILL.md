# Normalizer AI 预处理

这一步发生在调用 CLI **之前**，由人指导 AI 或由工作 agent 独立完成。输入是原业务工程、待分析入口及可用的依赖和配置证据；输出是**可交给 Normalizer 的分析工程**和交付说明。原工程和取证材料放在分析工程之外，只用于复核，不把分析副本投入部署。CLI 不调用 AI。

按[场景归一](../../../design/chapters/09-场景归一.md)选定原场景的函数入口，再按[AI救赎](../../../design/chapters/04-AI救赎.md)准备分析副本。本指南组织工作顺序，规则和指令拼写以对应的设计章节为准。[种子](../../../design/examples/README.md)用来找有完整原件和改写的对照，不自行扩大支持范围。

**为了通过分析而删改业务逻辑，再用结果代表原入口，属于作弊，这份交付必须作废。** 比如，删掉创单调用后，程序照样能返回一个数，却永远不会创单。遇到无法处理的语句，先核对删去它会不会改变返回值、状态、对外动作、失败路径或先后关系。省略须同时满足两个前提：这段代码不符合纯净工程规范，而且只服务于实现，去掉后业务观察不变。业务行为必须保留；缺乏等价改写的依据就报告具体缺口。见[《业务至上》BF-01 的创单反例](../../../design/chapters/06-业务至上.md#bf-01-省略的两个前提)。

## 前端整页归一化

先按[用户说法选择场景和范围](../../README.md#用户说把这张欠费单页面归一化)。方向可以是生产、消费或两侧，范围可以是点名的入口或该侧全部。已有明确要求就照办；有歧义时，用下面查到的实际回调或属性和用户商定。选全部时按原工程查齐，选局部时按选定入口交付。范围确定后按[第九章相应场景](../../../design/chapters/09-场景归一.md#规则区)逐入口准备分析副本。

**先确定是哪一页。** 从路由、页面注册和模板出发，沿实际挂载展开自有子组件、条件分支、列表和插槽，跟到它们绑定的状态、事件和外部接口。相同组件用在两处，要能说清实例、父级供值和绑定差别；循环实例用模板位置和实例范围表达。第三方组件追到实际传入的属性、对接的事件和可核实的合同。缺少组件实现或绑定证据时，标明受影响的使用点。未被这页装配的同目录文件不计入范围。

### 辨识 VO

从两个方向核对同一份状态。先从页面、组件实例、共享 store 和跨回调存续的闭包找**业务值由谁持有、何时写、何处读**；再从模板、交互、请求实参和生命周期判断反查来源。保留初始化、整包替换、合并、别名写入、重置后的可达取值，包括有意义的缺键和空值。能枚举的用源码证明取值，开放值保留实际类型和约束。动态键未能解析的范围如实记录。

| 源码中的值 | 判定与保留方式 |
|---|---|
| 选中的账单 ID 存在页面实例中，下次提交时读取 | 属于该实例的 VO，即使模板从未展示 ID。按持有者、实例范围、字段路径定位，并保留写入和提交读点。 |
| 子组件的 prop 直接转交同一账单；模板即时计算含税金额 | 沿 prop、别名和表达式追到原值。若另存提交快照，随后修改草稿不会改变已存金额，两者分别定位。 |
| 路由传入 ID、请求刚返回的对象、局部变量、固定属性 | 分别保留真实入参、调用回执、计算或固定规则。沿实际保存和业务使用认定 VO；变量名、类型、框架容器本身都不足以认定。 |

只作容器的父对象不与叶字段重复计数；若对象是否存在本身控制挂载，就同时保留整值观察。相同定义的不同挂载实例要能区分，真正共享的状态沿用同一身份。按已有标记标出分析模块里的真实状态绑定。生产和消费都做时，把字段的来源、生产写点和消费读点对应起来；只在请求中使用、只由宿主供值等情形按真实用途解释。

### 生产从宿主回调查起

入口是浏览器或小程序宿主直接或经框架向应用派发的业务回调。查实际监听、模板事件、页面及组件生命周期，以及定时、订阅等自动触发。对组件转发、observer 和异步 continuation，追到实际注册点、触发源和接收实例；同一调用链内的内部方法随所属入口分析。比如按钮绑定 `onTap → store.submit → api.save`，从 `onTap` 开始，保留里面阻止重复提交的判断。只有源码证明宿主直接注册了 `store.submit`，它才可在该绑定上充当入口。

每个入口沿实际分支追到完成，保留事件实参、已有 VO 读取、RPC 发起及实参、回执如何影响后续状态、可观察的顺序、异常和清理。未等待的任务保留原入口的返回时点，另追后续回调及其触发条件；不得将独立完成的任务串行等待。失败前已生效的写入也要保留。一次触发仅发请求或只在某分支写 VO，仍按实际效果处理。

### 消费从实际属性反查

一次观察定位到**某次渲染、某个实例、某一项属性或文本**。从页面逐节点查动态属性、文本、显隐、列表、插槽和影响实际交互的声明（例如固定的输入类型）；纯静态装饰可按依据排除。自有子组件内继续追到实际出口；第三方按公开边界说明交给哪个属性。将观察准备成同步无参导出函数，按已有 `@N componentProp` 标记保留属性身份，由该次求值实际已有的状态导出 R。消费可直接分析，不要求先跑查询或模拟一次点击。

每项保留祖先挂载条件、前序互斥分支、列表成员身份、props 的父级供值及默认覆盖、短路读点。例如 `v-if="ready"` 内一行的 `:disabled="row.paid"`，要同时交代 ready 成立且该行存在时才观察该行的 disabled。未挂载时没有这次属性求值；不能填一个 `false` 当结果。节点还在但仅被隐藏时按真实更新语义处理。若当前入口形式不能表达挂载与取值的区别，交付已核实的属性范围和具体缺口。

### 怎样判定整页做完

先选一条贯穿页面主要业务的路径检验预处理。例如查询页从页面加载追到请求、成功显示或失败提示；滚动、关闭等入口随后按同一标准处理。先试代表路径只决定处理顺序。

从源码独立列出分母，再将每个回调或属性定位到**源位置和绑定 → 分析入口 → 实跑 PERS 或具体缺口**。同一处理器的多处绑定可复用已证明等价的分析模块，同时保留每个使用点。对同一触发的成功／失败路径或同一属性的可达取值，从原件独立核 PERS。用同一段转换逻辑生成分析函数和 expected，只能核 CLI 对这份函数的计算，还要回源核这次转换本身；重点看调用和写入有没有消失、实例和条件有没有换掉。逐项保留能复跑的分析输入、命令及输出或诊断。源码可闭合的独立项继续做，遇到共享阻塞可合并说明原因并列出受影响项。

核对结果时要说明这次命令证明了什么。例如弹窗标题函数输出常量“确认付款”，只证明已挂载的弹窗收到这段文字。弹窗何时挂载要按同一实例核对相应条件。两者可分别分析，再核其对应关系；只有属性值通过时，标为“已核属性值，挂载条件待核”。普通 `module` 的通过记录也不能充当页面 `scenario` 的通过记录。

报告分别给出已核对结果、已实跑但拒绝或语义不符、缺证据或尚未处理的项目；有据排除项写明依据。分母尚未查全就写“分母尚未查全”。只有指定范围内每个应分析项都有经源级核对的正式结果，才称该页该侧已完成；代表入口试跑和工具能力探针只说明其实际覆盖的部分。

## 1. 从入口找证据

- 先确定从哪一刻开始、调用哪个入口、到何时算完成，确认真实入参、返回或异常。边界确定后，保留范围内所有可达的业务观察，不能为了方便删去解析失败、回调或状态读取。若只交付局部入口，明确列出未覆盖部分，不称整页或原入口已归一化。
- 从入口沿可达调用查源码、构造和注入、实际配置和依赖合同。核对字段、泛型、输入输出和异常绑定。对外部接口同时核对接收者、签名和完成合同；若本地实现可见则保留本地实现。
- 分开入口入参、入口已有状态和执行中取得的值。已有状态不能变成调用参数，同一次分析入口执行中取得的外部回执，不能提前变成该入口的已知值或用预先算好的常量替代。观察时点、别名和写入顺序须有原工程证据。例如等待后的可变状态不能提前读，初始化时的值不能冒充每次入口的值；已确认是本次调用传入的固定参数，也不能当成每次读取都可能变化的宿主状态。见[PERS登场](../../../design/chapters/07-PERS登场.md)和[观察身份](../../../design/chapters/07-PERS登场.md#pers-08-观察身份先于显示编号)。

## 2. 只改需要闭合的地方

已满足纯净工程约定的原生代码原样交付，包括普通分支和 `switch`；原生循环能证明可分析边界就保留；必须替换时，只交付已定义、可证明等价的数学操作。

输入未知时保留原来的判断和各条可达路径，不能把一次样本走过的分支写死在副本里。即使两条路径返回相同，也要核对各自的写入、调用和异常。分支的分裂与坍缩、算式能否化简，都交给内核；预处理不能提前选路或把业务结果改成新的入参。见[符号执行](../../../design/chapters/01-符号执行.md#se-02-执行覆盖与缺口)、[多重宇宙](../../../design/chapters/02-多重宇宙.md#mv-02-共同后续才坍缩)和[数学化简](../../../design/chapters/03-数学化简.md)。

| 遇到的情况 | 处理时对照 |
|---|---|
| 外壳可直接还原为原语言计算 | [换成原语言标准原生](../../../design/chapters/04-AI救赎.md#换成原语言标准原生)。核对空值、求值时点和失败，不能只换一个同名函数。 |
| 值操作要换成统一的已定义操作 | [标准操作与声明标记](../../../design/chapters/04-AI救赎.md#ai-02-标准操作的合同)。认官方 `N` 的真实绑定和签名；精度、舍入、可空和时间读取按实际合同。 |
| SQL、集合或循环适合关系表达 | [关系代数](../../../design/chapters/05-关系代数.md)及[关系指令](../../../design/chapters/05-关系代数.md#六扩展语义语法表)。保留行来源、重复、顺序、空值、初值、早停及写操作；不能把有状态递推硬套为独立聚合。 |
| 可能与业务无关的宿主机制 | [直接删减业务无关代码](../../../design/chapters/04-AI救赎.md#直接删减业务无关代码)。只有宿主机制不符合纯净工程规范，且确实只服务实现、不改变业务观察时，才可删除；已符合纯净工程的计算，即使是优化代码，也留给内核执行。仍须保留实参的效果、异常和实际发生顺序。见[业务至上](../../../design/chapters/06-业务至上.md)。 |
| 入口、已有状态或对象装配藏在框架里 | [入口重组](../../../design/chapters/04-AI救赎.md#入口函数重组)、[状态重组](../../../design/chapters/04-AI救赎.md#内存状态重组)、[隐藏执行过程](../../../design/chapters/04-AI救赎.md#把隐藏的执行过程写出来)。显式交付找到接收者的方式及真实生效的装配；不要用新对象替换入口已有状态。 |
| 本地实现不可见 | 按[AI救赎](../../../design/chapters/04-AI救赎.md)找依赖源码或可核实的定义。DTO 的签名、字段、序列化约定与用途一致时才按普通访问器还原。无从确认逻辑时报告缺口，不能仅凭签名把本地方法伪装成外部端口。 |
| 真正调用外部系统，或读取环境 | 端口按[外部调用约定](../../../design/chapters/04-AI救赎.md#重组和标记外部调用)交付实际接收者、接口及可核实的正常与失败合同。时钟等环境读取保留真实读取时点，参见[标准操作](../../../design/chapters/04-AI救赎.md#ai-02-标准操作的合同)和[当前实现限制](../../cli.md#当前实现限制)；不支持就报告缺口，不改成另一类观察。 |

## 3. 做交付前检查

按[分析副本校验](../../../design/chapters/04-AI救赎.md#ai-11-分析副本先通过静态校验)逐项核对：

1. **入口可唯一定位。** 提供工程相对路径加 `#入口调用`，不填调用实参；Java 实例入口有静态可达接收者，仅在需要区分重载时列源码参数类型。TS 从模块导出入口；设计上可通过已装配的对象方法定位，不能把真实接收者换成新对象来适配 CLI。要交给当前 CLI 时，按[当前实现限制](../../cli.md#当前实现限制)准备其接受的入口，不用设计范围推断当前适配器已经支持。
2. **类型清楚。** Java 的可达类型绑定只能来自工程源码、Normalizer 内置类型或设计约定的原生值类型，不能靠删导入绕过。JavaScript 根据构造点、调用链和消费点的全工程证据改成严格 TypeScript；独立模块可保留 CLI 支持的项目相对导入。确实需要合并文件时，先证明绑定、初始化和业务观察不变；无法无损适配就报告具体缺口。全模块不准显式、隐式或解析得到的 `any`，不压制类型检查。未知外部数据先用 `unknown`，原有校验、失败和有效收窄都保留。
3. **扩展闭合。** 用[关系代数的语法表](../../../design/chapters/05-关系代数.md#六扩展语义语法表)核对标记和指令的放置、绑定、取得域和确定赋值。未知指令、未声明关系、无依据的失败合同不能用默认值或空实现补齐。闭合不了时保留原件，记录文件和位置、缺少的证据与受影响的观察，不产出猜测的分析工程。
4. **重组前端观察，不交付框架原件。** Vue、小程序等原件只作预处理证据；CLI 只收准备好的严格 TypeScript。生产入口保留真实等待、读取时点、失败与有序写入；消费入口交付同步无参的导出函数，用标记保留原属性身份，读取已有状态而不是重新渲染。不能把不等待的动作擅自改成等待，也不能用异步包装改变原入口的完成合同；遇到当前适配器不能表达的合法观察，按[CLI 当前限制](../../cli.md#前端-vo-场景)报告。见[生产对照](../../../design/examples/topics/language-entries/frontend-vo-production-vue.md)与[消费对照](../../../design/examples/topics/language-entries/frontend-vo-consumption-vue.md)。

## 4. 交付并独立验收

交付完整分析工程、入口及观察范围；如需提供改写对照，使用保留未改行的 Git diff，并说明每处改写依赖的证据。如有缺口，把缺口与已交付范围分开，不把分析拒绝当作业务异常。不要把 PERS 结果混进分析工程。

准备好后由[正式 CLI](../../cli.md)运行。从原源码独立推导一份定形后的完整 PERS 或具体拒绝预期。核对改写时，选能区分两种业务结果的情形，例如端口抛错时，抛错之前的写入是否仍然发生。若能从原件指出一个可达反例，撤下这份副本及其结果，按原逻辑修正后再验收。

核对 P、E、R、S 和业务异常（包括动作条件、顺序和回执），不只看返回值。有 T 时，还要核对纯定义本身及其引用、依赖和顺序；引用名相同不代表定义相同。按[统一定形的完整 PERS 验收规则](../../../design/chapters/08-统一定形.md#cf-06-完整-pers-验收)直接比较完整结构。不得用实际输出反填预期，也不得在验收侧先化简实际值再声称通过。[测试区](../../../tests/README.md)执行已交付的完整案例，不重放种子补丁、不运行 AI，也不证明 AI 的实时改写质量。
