# Normalizer AI 预处理

这一步发生在调用 CLI **之前**，由人指导 AI 或由工作 agent 独立完成。输入是原业务工程、待分析入口及可用的依赖和配置证据；输出是**可交给 Normalizer 的分析工程**和交付说明。保留原工程，不把分析副本投入部署。CLI 不调用 AI。

先读[第四章《AI 救赎》](../../../design/chapters/第四章%20·%20AI%20救赎.md)。本指南组织工作顺序；规则和指令拼写以所链接的一级、二级设计为准。[种子](../../../design/examples/README.md)用来找有完整原件和改写的对照，不自行扩大支持范围。

## 1. 从入口找证据

- 先确定从哪一刻开始、调用哪个入口、有哪些真实入参、返回或异常，以及要观察哪些状态和外部动作。不要为了方便删去入口本来可观察的解析失败、回调或状态读取。
- 从入口沿可达调用查源码、构造和注入、实际配置和依赖合同。核对字段、泛型、输入输出和异常绑定。对外部接口同时核对接收者、签名和完成合同；若本地实现可见则保留本地实现。
- 分开入口入参、入口已有状态和执行中取得的值。观察时点、别名和写入顺序须有原工程证据。例如等待后的可变状态不能提前读，初始化时的值不能冒充每次入口的值。见[第七章](../../../design/chapters/第七章%20·%20PERS%20登场.md)和[观察身份](../../../design/secondary/观察身份与稳定编号.md)。

## 2. 只改需要闭合的地方

能按原生语义执行的代码原样交付，包括普通分支和 `switch`；未知次数循环另证有界或给出等价的已定义整体表达。AI 不替内核选分支、折叠表达式、压成最终公式或生成新的业务结果入参。

| 遇到的情况 | 处理时对照 |
|---|---|
| 外壳可直接还原为原语言计算 | [换成原语言标准原生](../../../design/chapters/第四章%20·%20AI%20救赎.md#换成原语言标准原生)。核对空值、求值时点和失败，不能只换一个同名函数。 |
| 值操作要换成统一的已定义操作 | [标准操作与声明标记](../../../design/secondary/标准操作与声明标记.md)。认官方 `N` 的真实绑定和签名；精度、舍入、可空和时间读取按实际合同。 |
| SQL、集合或循环适合关系表达 | [第五章](../../../design/chapters/第五章%20·%20关系代数：让%20SQL%20和集合运算一起化简.md)及[关系指令](../../../design/secondary/关系指令的统一写法.md)。保留行来源、重复、顺序、空值、初值、早停及写操作；不能把有状态递推硬套为独立聚合。 |
| 可能与业务无关的宿主机制 | [直接删减业务无关代码](../../../design/chapters/第四章%20·%20AI%20救赎.md#直接删减业务无关代码)。只有证明不影响观察才能删；仍须保留实参的效果、异常和实际发生顺序。 |
| 入口、已有状态或对象装配藏在框架里 | [入口重组](../../../design/chapters/第四章%20·%20AI%20救赎.md#入口函数重组)、[状态重组](../../../design/chapters/第四章%20·%20AI%20救赎.md#内存状态重组)、[隐藏执行过程](../../../design/chapters/第四章%20·%20AI%20救赎.md#把隐藏的执行过程写出来)。显式交付找到接收者的方式及真实生效的装配；不要用新对象替换入口已有状态。 |
| 本地源码不可见，或真正调用外部系统 | 见第四章的[外部调用](../../../design/chapters/第四章%20·%20AI%20救赎.md#重组和标记外部调用)。本地定义只按证据还原；DTO 的签名、字段、序列化约定与用途一致时才按普通访问器还原。真正的端口交付接口、DTO、可核实的返回与失败类型；标记本身不发调用。时钟等环境读取的设计见[标准操作](../../../design/secondary/标准操作与声明标记.md)。交付时核对[当前实现限制](../../cli.md#当前实现限制)；不支持就报告缺口，不把读取改写成另一类观察。 |

## 3. 做交付前检查

按[分析副本校验](../../../design/secondary/分析副本怎样通过校验.md)逐项核对：

1. **入口可唯一定位。** 提供工程相对路径加 `#入口调用`，不填调用实参；Java 实例入口有静态可达接收者，仅在需要区分重载时列源码参数类型。TS 从模块导出入口。要交给当前 CLI 时，按[当前实现限制](../../cli.md#当前实现限制)准备其接受的入口，不用设计范围推断当前适配器已经支持。
2. **类型清楚。** Java 的可达类型绑定只能来自工程源码、Normalizer 内置类型或设计约定的原生值类型，不能靠删导入绕过。JavaScript 根据构造点、调用链和消费点的全工程证据改成严格 TypeScript；不准显式、隐式或解析得到的 `any`，不压制类型检查。未知外部数据先用 `unknown`，原有校验、失败和有效收窄都保留。
3. **扩展闭合。** 用[第五章的语法表](../../../design/chapters/第五章%20·%20关系代数：让%20SQL%20和集合运算一起化简.md#六扩展语义语法表)核对标记和指令的放置、绑定、取得域和确定赋值。未知指令、未声明关系、无依据的失败合同不能用默认值或空实现补齐。闭合不了时保留原件，记录文件和位置、缺少的证据与受影响的观察，不产出猜测的分析工程。
4. **Vue 保留两份输入。** 保留原始 `.vue` 和准备好的严格 `.ts`。生产入口保留等待、读取时点和有序写入；消费入口交付导出函数、原组件属性绑定和已有状态读取。见[生产对照](../../../design/examples/topics/language-entries/frontend-vo-production-vue.md)与[消费对照](../../../design/examples/topics/language-entries/frontend-vo-consumption-vue.md)。

## 4. 交付并独立验收

交付完整分析工程、入口及观察范围；如需提供改写对照，使用保留未改行的 Git diff，并说明每处改写依赖的证据。如有缺口，把缺口与已交付范围分开，不把分析拒绝当作业务异常。不要把 PERS 结果混进分析工程。

准备好后由[正式 CLI](../../cli.md)运行。从原源码独立推导一份完整 PERS 或具体拒绝预期，再核对 CLI 输出。[测试区](../../../tests/README.md)执行已交付的完整案例，不重放种子补丁、不运行 AI，也不证明 AI 的实时改写质量。
