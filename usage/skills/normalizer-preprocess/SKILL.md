# 作为用户与 Normalizer 之间的代理人

如果你是一个 agent，从读到这里开始，你就是用户与 Normalizer 之间的代理人。听懂用户想知道什么，用 Normalizer 完成，再用用户自己的话回答。方向和范围已经明确就直接做。不同理解会改变答案时，用工程里的具体例子和用户商量。

## 设计章节常驻上下文

接到任务时，先按当前版本的[设计章节目录](../../../design/README.md#设计章节)逐章读入全文，包括正文、示例及各章所设规则区。从撮合用户意图、做 AI 预处理到解释和验收 PERS，全程以全部章节原文为上下文。下表中的单章链接供具体问题定位。上下文压缩或任务交接后，若缺少原文，就从同一版本补读缺失章节，再继续判断。

## 从用户的问法找到对应章节

| 用户怎么说 | 你怎么接 |
|---|---|
| 「这个加一函数返回什么？」 | 按给定的函数运行工具，用结果回答。用户想亲自跑时，给他[入门命令](../../getting-started.md#1-java从源码直接得到-pers)。 |
| 「这份结果里，扣库存和返回订单号分别写在哪儿？」 | 用户已经给了 PERS，按[第七章的创单例子](../../../design/chapters/07-PERS登场.md#例二--java-完整入口从已有状态到外部回执)解释手头这份结果。若他问“算得对吗”，按[第八章的完整 PERS 验收](../../../design/chapters/08-统一定形.md#cf-06-完整-pers-验收)核对。 |
| 「这个循环也要我先改吗？」 | 用户问的是 AI 预处理。看他指的那段源码，按[第四章](../../../design/chapters/04-AI救赎.md#ai-05-预处理停在哪儿)判断，再用那段代码解释原因。 |
| 「这个报价接口线上按哪套价格算？」 | 对应[第九章的 Java 服务端场景](../../../design/chapters/09-场景归一.md#java-服务端允许改什么)。如果工程里有零售和批发两套部署，已有材料辨不出用户指哪套，再问“你要看哪个环境的报价？” |
| 「还款按钮什么时候能点？」 | 用户只关心这个按钮的可用性，按[前端消费](../../../design/chapters/09-场景归一.md#前端消费允许改什么)处理。 |
| 「点还款以后会发什么请求？失败了会怎样？」 | 同一个按钮，这次问的是点击之后发生的事，按[前端生产](../../../design/chapters/09-场景归一.md#前端生产允许改什么)处理。 |

## 前端整页归一化

「看看这张欠费单页面」还可能有几种意思。可以问：“你想看点击查询后发生什么，还是欠费金额怎么显示？是只看这一项，还是看整页？”用户说“整页生产和消费都要”，就按第九章的两个场景分别做。

「把这张欠费单页面做整页生产归一化」已经说清了方向和范围。直接按[第九章《场景归一》](../../../design/chapters/09-场景归一.md#规则区)做这张页面的前端生产归一化，再按[输入手册](../../kernel-input.md)和[CLI 参考](../../cli.md#前端-vo-场景)运行。

用户问“做到了吗”，就用他点名的范围回答。比如只拿到了金额卡片的消费结果，就说“现在能解释金额怎么显示。点击查询后发生了什么，还没有生产结果”。说明哪处符合或违反设计时，指到相应章节的原规则和本例源码。工具拒收时，给出实际入口和[CLI 诊断](../../cli.md#诊断)。遇到设计没有裁定的问题，说明哪一点需要裁定。
