# 准备 CLI 输入

给 Normalizer 的是一个**分析工程根目录**，不是生产工作区的任意上级目录。只放分析入口所需的纯净源码，以及源码使用的类型和显式合同，保留相对路径。框架原件、预处理对照和预期 PERS 都在分析工程外。

| 原始材料 | 准备好的输入 | 下一步 |
|---|---|---|
| 已符合设计的 Java | 可达逻辑由源码或明确合同交代，计算边界可证明；入口是可定位的静态方法或静态可达的接收者调用 | `source` |
| JavaScript / TypeScript | 闭合的严格 `.ts` 源码和适配器可定位的导出入口，可含受支持的项目相对导入，见[CLI 当前实现限制](cli.md#当前实现限制) | `module` |
| Vue、小程序等前端业务入口 | 从原工程取证并预处理；只交付符合设计和当前适配限制的纯净 TypeScript。原始模板不进入运行工程 | `scenario`，选择 VO 生产或消费 |

生产框架的配置可用来找出实际装配，但不能原封不动交给 CLI 来完成装配；应把确认会生效的逻辑写进分析副本。交付前先按[设计校验](../design/chapters/04-AI救赎.md#ai-11-分析副本先通过静态校验)检查，再核对[当前实现限制](cli.md#当前实现限制)。前者不满足要补证据，后者不能无损适配就报告工具缺口。

入口统一写作 `工程相对路径#入口调用`，不附带某次调用的实际参数。准备时先核对可见源码、边界、状态和类型；需要修改时按[AI 预处理 Skill](skills/normalizer-preprocess/SKILL.md)操作。分析副本缺少关键证据时，说明缺口后停止，不用占位值换取运行成功。

前端页面按[已选的方向和范围](README.md#用户说把这张欠费单页面归一化)，从[实际装配](skills/normalizer-preprocess/SKILL.md#前端整页归一化)定位对应入口，再为各入口准备输入。

命令和约束见 [CLI](cli.md)。`normalizer.kernel-input/1` 是适配器内部交接协议，不是第四种公开输入，CLI 使用者不需要手写；维护者查[实现区](../implementation/contracts/normalized-source-contract.md)。
