# 规范输入

从 Java 源目录开始时，提交已闭合的入口与依赖源文件，并给出 `src/Entry.java#Entry.run` 或 `src/Beans.java#Beans.SERVICE.run` 这样能唯一定位的入口。参数及返回类型从声明读取，端口和查询需要真实的来源与语义。最小运行示例见[入门](getting-started.md)。

语言适配器也可生成 `normalizer.kernel-input/1` 工程。工程中 `source` 指向签名载体，`source_text` 保存对应内容，`entries` 列出入口，`functions` 为所需的无实现方法提供带来源的类型化定义。`entry_contexts` 按入口声明原业务函数、返回类型、真实形参和环境。中间载体的函数和环境字段通过上下文映射回业务来源；P 使用入口声明的同名参数。形参类型和返回值载体类型分别由 `parameter_value_types` 和 `result_value_types` 声明，不共用类型别名。签名载体只有声明，没有 Java 方法体；所有方法都绑定到类型化 IR。需要执行 Java 方法体的输入只能走源码入口，先完成源码准入。

适配器的 `local_ir` 动作只接受关系查询（`source` 字段仍传 AIR 文本）。读取工程时即检查语法和动作种类，执行器直接使用结构化查询；进入执行器后的行绑定和类型约束仍按查询上下文校验。

Java 源码入口中已证明的数组元素形态不能给适配工程的结果载体自动补业务类型。适配器须显式声明向量等不可变值；整数下界也只在可达且蕴含取得条件的路径可用。内部延迟记录和整数定义分属不同身份，不按显示名互相代用。

任务句柄只由已验证的任务启动创建，不能通过文本类型声明。 即使多次调用同一端口，每个已保存的任务出现点也由自己的直接等待消费；外层、try 正常体和 catch 处理体的出现点保持独立，不会因端口名相同而合并。Vue 动作层 catch 处理已声明的仅类型异常，并可原样重抛；合法外部回执的异常载荷不变。工程参数声明接收名称和执行类型，参数怎样被观察由端口合同约定。

适配器以 `vector<T>` 表达不可变向量，以 `number` 表达精确业务数值。规范工程不接受 `i32`／`i64` 作为数值载体类型；Java 签名中的 `int`／`long` 不改变业务数值域。生产输入载体不可空，也不会静默丢弃可空性。Java 源码数组仍由源码声明及其读写、越界和异常合同处理；它们不是规范工程里另一种 `list<T>?` 载体。

读取宿主输入和写入状态只依据当前所选入口的 P／E 声明。若入口缺少上下文、字段或参数，内核报错，不从同一工程的其他入口借用同名声明。

适配器提供的入口标识包含源文件和函数，形参位置从零连续编号，不依赖 JSON 键顺序。状态路径只能穿过声明的记录字段；external 的不可变值类型必须闭合，不能把递归类型当成完整记录值。

P 是本次调用绑定的入口快照。等待前后重复读取同一个 P 仍取得同一个值；与时间相关的可变状态或边界观察应另行建模，不能悄悄替换成第二个 P。

Vue 的投影与事件输入可在[生产示例](../design/examples/topics/language-entries/frontend-vo-production-vue.md)及[消费示例](../design/examples/topics/language-entries/frontend-vo-consumption-vue.md)中对照。术语和输出字段遵循[业务 PERS](../implementation/contracts/business-pers.md)。
