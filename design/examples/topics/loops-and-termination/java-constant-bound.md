# Hello World：常量边界循环由内核处理

## 设计意图

交换循环条件的两侧要翻转比较方向，并保持是否包含端点。终止返回之后不存在剩余迭代，不消耗这些迭代的执行预算。给外层变量赋值的计数器在任何分支上都不能被循环体改写，否则不能使用同一个递增证明。

对照初始条件为假、正向或逆向迭代和包含端点的比较。循环方向要推进终止，首尾元素按源码计入；常量实际执行后再化简，不猜循环次数。比较两侧互换时须同时反向；循环体 return 只观察已执行前缀，也不得执行本轮的循环后步进。

外层已初始化的 long 计数器与 int 共用循环头赋值和终止规则，并在循环后保留末次步进。

同样的小范围赋值式循环也可用 `short` 计数器：对 0、1、2 逐步递增，无窄化越界，业务结果不变。若计数器可能达到载体边界，先核对窄化或回卷是否为原程序可观察的行为，再选择证明。

条件和更新必须分别观察和改变同一归纳变量，不能拿另一局部变量凑证明。对象字段的赋值、比较和更新是合法 Java，但不能仅以局部计数器的条件证明；必须另外证明字段更新、别名和读取不破坏终止。逐项求和不加偏移时只观察实际元素，空数组仍归零。

## 输入原始代码

循环边界是源码常量，工程可以直接展开并化简，不需要 AI 预处理。

```java
class SmallLoop {
    static int total() {
        int sum = 0;
        for (int i = 0; i < 3; i++) sum += i;
        return sum;
    }
}
```

## AI 预处理结果

**原样通过。** 循环次数由常量边界确定，AI 不替换循环片段。

`i = 0; i <= 2; ++i`、`i = 2; i >= 0; i--` 都遍历本例的三个整数。保持同一业务累加时，求和结果相同，但不据此对任意有副作用的循环重排迭代。`i = 1; i < 0; i++` 初始条件是假，累加量保持为 0。边界即使都是常量，若步进朝远离退出条件的方向，例如以 0 开始，在 `i < 3` 下 `i--`，也不能假定一个有限次数。

**预处理要点**：循环是否需要预处理由次数是否可证明决定，常量循环直接交给符号化执行内核。

**PERS 验收要点**：内核负责常量循环的展开和数学化简，AI 只处理未知次数或不可闭合的循环。

头部也可以给外层已初始化的可变 `int`／`long` 局部计数器赋值，仍须经过同一源码赋值规则，再证明次数。让初始值为 `99`、头部赋值 `i = 0`、循环执行 `i < 3`，最后读取 `sum * 10 + i` 得到 `33`；若头部赋值 `i = 4` 后条件 `i < 4` 已为假，虽然不执行循环体和步进，循环外读取 `i` 也必须得到 `4`。循环头不能掩盖前面非法的普通赋值。

直接绑定的 `int[] items` 也有有限的元素次序：用 `long sum = 0L` 和 `for (int v : items) sum += v + 1L` 逐项累加，结果为 `COALESCE(SUM(SELECT value + 1 FROM items), 0)`。空数组返回 `0`，`[1, 2]` 返回 `5`；不按 Java 存储位宽回绕，也不把数组当成数据库访问。

已证明是精确整数时，`sum = (1 + v) + sum` 和 `sum += v + 1` 是同一个逐项加法；交换写法不能把另一变量或对循环元素的赋值识别成合法累加器。
