# Hello World：业务 number 不受 Java 位宽限制

## 设计意图

对照精确小数取负和比较。未知入参取负仍是符号表达式；已知负数的大小、不同来源字面量的等值和比较端点，应以精确业务值确定，而不是靠宿主浮点近似。

对照宿主字长边界内外的业务整数，常量和符号都按精确值域运算。超过 int 或 long 上限不回卷；只有源码明确的位宽或回卷业务才另走其合同。

## 输入原始代码

入口把费用加到余额上。Java 方法声明为 `int`，业务规则要求结果使用 Normalizer 的无固定上限 number。调用 `balance = 2147483647`、`fee = 1` 时，业务结果仍是 2147483648。

```java
class Balance {
    static int addFee(int balance, int fee) {
        return balance + fee;
    }
}
```

## AI 预处理结果

**原样通过。** 源码没有写出回卷、溢出或截断规则。AI 不把 Java 位宽算法改写进源码，Normalizer 按业务 number 合同处理加法。

**预处理要点**

- 宿主语言的机器整数实现属于工程底层细节，业务源码没有表达时不进入归一化规则。
- 归一化关注业务逻辑，数值位宽只有在源码显式写成业务规则时才需要单独建模。

## 归一化最终结果

```yaml
schema: normalizer.pers/1

entry:
  function: src/Balance.java#Balance.addFee
  returns: number

P:
  parameters:
    balance:
      position: 0
      type: number
    fee:
      position: 1
      type: number

R: balance + fee
```

`R` 描述业务加法，不携带 Java `int` 的 32 位回绕。显式业务回卷由[业务流水号回卷](java-explicit-rollover.md)这个已有种子承担。

**PERS 验收要点**

- PERS 不模拟计算机底层实现，内核使用面向业务的无限 number 域。
- 常量路径也不能因为中间值超过宿主的 64 位或 128 位而改变结果。把本例方法返回类型改为 Java `long`，方法体先绑定 `long base = 9223372036854775807L`，再返回 `base * base * base`。这样源码无需隐式缩窄，数学结果为 `(2⁶³−1)³`，PERS 的 R 应保留完整十进制整数 `784637716923335095224261902710254454442933591094742482943`。原有两个 P 参数保持不变，结果不依赖它们。
- 业务规则和宿主实现分别承担职责，只有业务代码明确写出的边界才进入 PERS。

## 原生浮点写法直接进入业务 number

按「业务至上」执行数值：Java 源码里的 `float`、`double` 是合法的源码类型，入口要读它们；进入归一化后，只有一个对外的业务 `number`，不复刻二进制舍入。AI 不需要改写字面量。`0.1 + 0.2` 直接得到 `0.3`。这是按业务语义执行，不是声称结果与 Java 的机器浮点计算相同。

[Java 的数值词法](https://docs.oracle.com/javase/specs/jls/se25/html/jls-3.html#jls-3.10.2)决定拼法是否合法：`.25`、`1.`、带符号的十进制指数、`f/F/d/D` 后缀都可以用；十六进制浮点的 `p/P` 指数按 2 的幂解释，`0x1.fp2` 精确为 `7.75`。`0x1e3` 仍是整数 483。没有指数数字或没有有效数字、非法下划线、相互冲突的后缀，以及 Java 不允许的隐式窄化在源码入口拒绝。非零字面量若在 Java 编译期会舍入为无穷或零，也不是合法源码；这项入口检查与通过入口后不模拟 IEEE 舍入是两件事。

本例覆盖直接常量、正负号、混合整数与小数的加减乘比较，以及同一个业务 `number` 在方法参数和 PERS 中的展示。不定默认小数位。非终止小数的精确商可保留为比例；源码规定的整数趋零商、舍入或可观察窄化按各自业务合同保留，不能用浮点近似替代。外部已经带来的近似数也不被猜成某个精确原值。

同一个精确值在数学层要有同一个结构。例如两侧都按 `balance > 0` 选 `0.1` 或 1，左侧写 `0.10`、`1.0`，右侧写 `.1`、`1`，两侧仍是同一个 CASE。两边完成求值后相减得到 0，不把两个显示相同的 CASE 留到 PERS。类似地，`(balance + 1.0) - (balance + 1)` 也得到 0。

`-2147483648` 的整型最小值特例不能提前截断一个更长的浮点字面量。`-2147483648f` 与 `-2147483648.0` 分别完整读取为带负号的 float 和 double 写法；都按业务数值求得 `-2147483648`，并保留原有两个数值入参。

精确负号对已知有限小数直接翻转符号，例如 `1.25` 变为 `-1.25`；对未知的直接小数入参保留符号负号，不伪造一个系数。内核单测对照这两个方向。

**已取得的整数相消**　普通入参 `fee - fee` 恒为零，原 P 保持不变，不产生 E、S 或异常。如果先按 `balance > 0` 取得 `balance` 或 `balance + 2`，再减去同一个 `balance`，正数臂为零，其余为二。完整 CASE 以 `balance > 0` 为基准；不能把相消推到还没有完成读取的不同边界。
