# 统一定形

`a + b` 和 `b + a` 在精确数值域里是同一个计算。Normalizer 对同一组带类型和来源的值，应交付同一种表达式写法，不因源码顺序或所用语言而变。**先化简，再定形。** 在已定义的规则范围内，只要还能证明有更简单的等价形式，就继续化简。到不能再降时，才在复杂度相同的等价形式里选唯一写法。若按规范 `a` 在 `b` 前，两种输入就都写成 `a + b`。

定形不要求内核判定任意两个程序是否等价。它要求对**有明确归一规则的范围**作出唯一选择。能否交换、合并或重排，要先由类型、运算合同和当前路径事实证明。证据不够时保留区别，不把猜测当成规范。

## 为什么一定要在执行中统一

看这个入口。两个局部变量分别由两次分支取得；两组加法的书写次序不同。

```java
class CompareTotals {
    static int run(boolean p, int a, int b, int c, int d) {
        int left;
        if (p) left = b + a;
        else left = d + c;

        int right;
        if (p) right = a + b;
        else right = c + d;

        return left - right;
    }
}
```

`p` 未知时，执行并坍缩会得到两个条件值。这里的操作数都是已取得的精确业务整数；相同的 `p` 在两处之间也没有被改写。

| 执行走到哪里 | 内核里的值 |
| --- | --- |
| 刚形成两个条件值 | 左边是 `CASE WHEN p THEN b + a ELSE d + c END`；右边是 `CASE WHEN p THEN a + b ELSE c + d END` |
| 按同一条规则统一各臂里的加法 | 左右都变成 `CASE WHEN p THEN a + b ELSE c + d END` |
| 执行减法 | 左右已经是同一个结构；用 `x - x → 0` |
| 交付结果 | `R: '0'` |

如果只在最后对输出做排版，减法已经看过两棵不同的树，发现不了两边原本一样。**定形是为了让内核在下一步就认出同一个值。** 发生时点见[执行中定形不搬动动作](#cf-10-执行中定形不搬动动作)。

## 算法：先划定等价范围，再选唯一代表

定形所比较的输入不是一串源码，而是一个**已经按源顺序取得的有类型值**，以及它此刻成立的路径条件。内核还必须知道：每个变量绑定到哪个参数、状态快照或回执；某个值是所有路径都已取得，还是只有在特定条件下才有。值的身份和取得范围先确定，排序不能替代这一步。

### 第一步：定合同，确认能动哪里

先问两个候选在哪些路径上、以什么合同等价，接着再选代表。依据见[等价候选的准入](#cf-01-等价候选的准入)。

#### 选代表不替代等价证明

一种规范代表负责统一已证等价的值，不负责把不同观察判成等价。普通比较的换边、有序关系的首项，都先按各自的合同确定等价域，再决定表示。例如[关系代数的第零项与首项](05-关系代数.md#第零项何时就是首项)：在已证相同的正常完成域，统一成同一个首项观察结构，不保留两种只因源码写法而异的结构。缺省、异常和已发生的动作若有差别，仍须能从完整 PERS 看出来。打印由接口说明，不能反过来决定合同。验收要有等价对照，也要用首项为 null、空集完成不同或提前停止改变观察等反例守住边界。

### 第二步：先处理子式，再处理父节点

值从子节点向父节点定形；已有条件域始终有效。统一构造的细节见[共享结构与顺序](#cf-02-共享结构与顺序)。

### 第三步：同一套排序键，P 和 E 的名字最后裁决

公开名字只处理同类型、同合同、同结构之后的平局，不能盖过真实来源和身份。比较层级见[共享结构与顺序](#cf-02-共享结构与顺序)。

### 化简与定形的优先级：先降至最简，再统一写法

先把确有把握能消掉的运算做掉，不能为排序保留较复杂的结构。精确比较、返工与停止条件见[化简与候选优先级](#cf-03-化简与候选优先级)。

## CASE WHEN：统一结构，不交换程序的执行顺序

对完整的二分值表达式，下列两个写法可以考虑归到同一方向：

```text
CASE WHEN p      THEN left  ELSE right END
CASE WHEN NOT(p) THEN right ELSE left  END
```

条件取反、两臂同时交换，才保持原来的真值与结果对应。只有条件的互补已知、两臂各自的可读取范围不变时，才建立这对候选。守卫和结果臂必须作为一个整体选方向，不能各自排序。

二分可以比较两个方向；选哪一边见[完整二分 CASE](#cf-04-完整二分-case)。

这不是让所有 CASE 都按条件字母表排序。看这个三臂例子：

```text
CASE WHEN x >= 0 THEN 1 WHEN x >= 10 THEN 2 ELSE 0 END
```

当 `x = 12`，第一臂先命中，结果是 1；交换两臂之后就会变成 2。可以按首个命中规则证明第二臂在这个位置永远不会执行，但不能直接重排。没有 ELSE 的部分表达式也不能为了整齐擅自补一个默认值。

## 能排的是值，不能搬的是动作

`port.readA() + port.readB()` 和 `port.readB() + port.readA()` 先调用的是不同端口。即使成功时得到同一个加法形状，失败时是否会调用另一个端口也已经不同了。

同样，只在已取得回执后才能读的值，不会因为换一种布尔写法就提前存在。见[执行中定形不搬动动作](#cf-10-执行中定形不搬动动作)。

## 定形前、定形后：把关键变形走一遍

这里的「定形前」是**按源码顺序执行后取得的表达式**，不是让 AI 把原程序改成右列。数值例采用精确整数；同类型、同来源种类的符号在前几级排序打平时，按公开名字排序。比较例中若两端其他优先级相同，也用同一个结构键确定方向。本节加法示例按符号项在前、常量项在后构造；有多个常量时按精确值排序，但不在定形阶段合并。

### 1. 先统一表示：排序、括号、方向

| 定形前 | 定形后 | 关键变形 |
| --- | --- | --- |
| `b + a` | `a + b` | 两个 P 参数的结构优先级打平，最后按公开名称排。 |
| `quota.used + quota.limit` | `quota.limit + quota.used` | 同一 E 状态快照里的两个字段，前级打平才比公开字段路径。 |
| `c + (b + a)`、`(a + c) + b` | `(a + b) + c` | 展开同族加法、排序、固定左结合；两条路用同一个构造器。 |
| `c * (a * b)` | `(a * b) * c` | 精确乘法的结合与交换；不顺手套分配律。 |
| `b > a`、`a < b` | `a < b` | 当规范键选 `a` 在左边，交换两端就要同时反转比较符。 |
| `q AND (p AND r)` | `(p AND q) AND r` | 三项都已取得、总有定义且无副作用，才允许交换并固定括号。 |
| `$e_10 + $e_2` | `$e_2 + $e_10` | 两个数值回执都已取得；比数值编号，不比字符串，也不移动 S 中的调用。 |
| `CASE WHEN count <= 0 THEN 0 ELSE count END` | `CASE WHEN count > 0 THEN count ELSE 0 END` | 完整二分且比较互补；同时取反和交换两臂。选统一方向，不删任何一臂。 |

### 2. 分清定形与化简

下表把定形和化简分开。**中间列只展示同复杂度的结构变化，不是内核要先做一遍定形才允许化简。** 实际执行时，已能证明更简单的就优先化简。

| 原式 | 只做定形 | 再做数学化简 |
| --- | --- | --- |
| `(b + 2) + (a + 3)` | `((a + b) + 2) + 3` | 合并两个常量，得到 `(a + b) + 5`。 |
| `(b + a) - (a + b)` | `(a + b) - (a + b)` | 两端是同一子式，相减得 `0`。 |
| `(q AND p) OR (p AND q)` | `(p AND q) OR (p AND q)` | 两个总布尔子式相同，去掉重复项，得到 `p AND q`。 |
| `CASE WHEN p THEN b + a ELSE a + b END` | `CASE WHEN p THEN a + b ELSE a + b END` | 守卫已取得、两臂都是同一已定义的值，化为 `a + b`。 |
| 在 `a > 10` 的路径上，`CASE WHEN a > 0 THEN b ELSE c END` | 保留两臂；本例的比较已是规范方向 | 当前路径只会命中真臂，化为 `b`；不能把这个结论带到其他路径。 |

### 3. 反例：表面上能排，实际上不能动

| 定形前 | 定形后 | 为什么不动 |
| --- | --- | --- |
| `b - a` | `b - a` | 减法的两端有各自的位置，不按加法规则排序。 |
| `"B" + "A"` | `"B" + "A"` 的拼接次序 | 可以在值层折叠成 `"BA"`，但不能交换成 `"AB"`。 |
| `CASE WHEN x >= 0 THEN 1 WHEN x >= 10 THEN 2 ELSE 0 END` | 不按守卫排序 | 保持首个命中。可以另行证明第二臂不可达，但不能把它挪到第一臂前面。 |
| `CASE WHEN hasReply THEN reply.ok ELSE false END` | 保留这个保护结构 | 没取得回执的路径不能读 `reply.ok`；不能做成可任意重排的两个布尔项。 |
| 第一次调用后写状态，再发第二次调用 | S 仍是「调用、写入、调用」 | 回执编号可以用于比较已取得的值，不能反过来重排产生它们的动作。 |

这三组例子合起来才是规范：**能化简的优先化简，复杂度相同的必须统一，该保序或受保护的必须保留。**

## 经典案例：PERS 加了 LET，就要规定唯一写法

**设计一种 PERS 机制，要同时设计它的规范形。** 只规定「这个格式能表达什么」不够；还要规定在哪些条件下必须用、哪些情况下必须不用、多种候选怎么选，以及名称和位置怎样确定。否则每个用例都能独立找出一个语义正确的 `expected`，它们却未必是同一个规范答案。

看这个返回值：对已取得的数值数组求和。每行加多少由 `enabled` 决定，最后把总和平方。假设数学化简已经结束，两个乘数仍是同一个含 CASE 的聚合。下面两种写法只展示 `R`：

```text
COALESCE(SUM(SELECT value + CASE WHEN enabled THEN extra ELSE 0 END FROM values), 0)
* COALESCE(SUM(SELECT value + CASE WHEN enabled THEN extra ELSE 0 END FROM values), 0)
```

```text
LET $l_0 = COALESCE(SUM(SELECT value + CASE WHEN enabled THEN extra ELSE 0 END FROM values), 0)
IN $l_0 * $l_0
```

如果只写「这里允许提取 LET」，A 用例就可能期待第一种，B 用例期待第二种。一加上提取，A 变红；为了让 A 继续绿，再按入口或源码写法开例外。最后，同一个值是否带 LET 取决于哪个用例先写了断言，而不是值本身。这就是规范盲区带来的补丁循环。

本例少了一份 CASE，因此必须输出第二种。什么时候不能提取、遇到多个候选如何处理，见[LET 的提取边界](#cf-05-let-的提取边界)。

## 测试断言：一份预期，直接 equals

要断言完整结果，如果同一个值允许好几种写法，测试就得接受多个答案，或先自己证明它们等价。前者说不清哪一种是标准，后者把内核该做的工作又做了一遍。统一定形让测试可以**手写一份独立的预期，用 `equals` 比较完整 PERS**。它既能发现业务行为变了，也能抓到「值没算错，但合法化简没做完」或「同样的值没统一成规范形」的回归。

例如把下面两份代码分别放到各自测试工程的 `src/Add.java`。入口名、参数名和位置完全一致，只互换加法的两个操作数。

```java
class Add {
    static int run(int value, int delta) {
        return value + delta;
    }
}
```

```java
class Add {
    static int run(int value, int delta) {
        return delta + value;
    }
}
```

两边都应该与下面**同一份**预期相等（示例省略导出版本字段）。`delta` 和 `value` 的类型与来源种类相同，由公开参数名决定加法的写法；`position` 仍按原始签名，不能随表达式一起调换。

```yaml
entry:
  function: src/Add.java#Add.run
  returns: number
P:
  parameters:
    value: { position: 0, type: number }
    delta: { position: 1, type: number }
R: delta + value
```

这两份源码各自直接比较同一份完整预期。哪些差别参与比较以及如何验收，见[完整 PERS 验收](#cf-06-完整-pers-验收)。

## 修复测试用例：先修规范，再修断言

**定形规范决定 `expected`，不能让 `expected` 反过来决定规范。** 两个用例在同一合同下，对同一个值各认一种写法，而规范又没规定选哪一种，问题就不在某条断言写错了，而在规范还没有给出唯一答案。即使两个用例现在都绿，也必须先补规范。

比如两个用例的参数和行为完全相同，只有完整二分的守卫方向不同。假设规范当时只说「可以同时取反并交换两臂」，却没写该选哪一边。这里只列出两条断言的 `R`：

| 用例 | 各自写下的旧预期 |
| --- | --- |
| A | `CASE WHEN p THEN left ELSE right END` |
| B | `CASE WHEN NOT(p) THEN right ELSE left END` |

对同一个已取得的总布尔值 `p`，它们在 `p` 为真时都返回 `left`，为假时都返回 `right`。如果为过 A 加一条「翻成正向」的补丁，B 就可能变红；再为 B 加例外，内核就得看源码先写了哪条臂，才能决定输出。每多一类等价写法，就可能再逼出一个补丁。**测试看似都能过，内核却被要求对同一个值交付不同结构，定形失去了意义。**

要先回到源码与合同核实差异，不能迎合两份旧答案。修订顺序也见[完整 PERS 验收](#cf-06-完整-pers-验收)。

**统一定形让同一个业务值在内核里可直接比较，也让完整 PERS 在测试里有一份可直接断言的答案。**

## 规则区

以下条例挑出能体现本章主张、便于引用和继续细化的情形，不穷举所有写法。没有列出的情形仍按本章主张和已确立的业务合同判断。

### CF-01 等价候选的准入

**规则：**

每个运算族先写清适用域、允许的变换、禁止的变换，以及怎样选唯一代表。比如精确数值的加法可以交换、结合；字符串拼接不可以。一个守卫已经判过真假，不代表它保护的回执在其他路径也能读。业务值相等、可读取的路径相同、可观察动作不变，三项都满足，候选才能进来。

用已有的路径事实时，只在那条路径上用。比如 `p` 成立时才有 `reply`，不能在该分支证明了某项化简，就把结果缓存起来给没有 `reply` 的路径用。排序或化简若依赖来源名与取得事实，缓存也必须区分这些上下文。

**示例：**

只有 `p` 成立时才取得 `reply`，不能把在这个分支证明的化简用到没有 `reply` 的分支。

**说明：**

取值、动作、失败和取得域都一致才进入候选；正常值选成同一代表不代表完整 PERS 等价。

### CF-02 共享结构与顺序

**规则：**

对已取得的普通运算子值，自底向上处理。对条件值则分别在各臂自己的已知条件和取值范围内处理，不能为定形提前读取某一臂。精确加法的构造器把同族节点展开，按同一结构键排序，再固定左结合。于是 `c + (b + a)` 和 `(a + b) + c` 都直接构造出 `(a + b) + c`，不需要反复试着交换相邻项。减法、参数列表之类没有这个合同，就保持各操作数的位置。

比较也直接构造代表：例如 `a > b` 与 `b < a` 来自同一对换边候选。先按结构键确定两端哪一端在左；交换两端时同时换比较符号。CASE 使用这里得到的比较结构，输出也不再换边。

结构比较逐级进行；**只有前面各级全部相同，才用公开名字排先后。**

| 优先级 | 比什么 |
| --- | --- |
| 1 | 运算合同和类型：精确整数、普通布尔等各用自己的规则；不能把合同不同的计算当成同类。 |
| 2 | 已发布的语义优先级：例如比较的运算族、极性和比较方向。适用于当前运算族的才参与。 |
| 3 | 表达式结构与载荷：比较节点种类、运算符、子结构、字面量的精确值和来源种类。用有类型的结构键，不拿拼好的显示字符串来比较。 |
| 4 | 仍打平才按稳定身份：P 用声明的参数名，E 用声明的状态名、表名及字段路径；名称逐段按 Unicode 码点序比较，不随系统语言环境而变。已编号的回执按数字比较，`$e_2` 在 `$e_10` 前。 |

比如 `b + a` 的两个操作数都是同类型的参数，前三级打平，最后才由 P 名决定写成 `a + b`。同一个对象的 `quota.used` 和 `quota.limit` 若前三级也打平，则按 E 的字段路径排序，`quota.limit` 在前。P 和 E 都叫 `value` 时，来源种类本来就不同；同名也不等于同一份值。不同时间取得的状态快照，还要保留各自的读取身份，不能只凭路径把它们合并。

**名字稳定不等于使用局部变量名。** `tmp`、堆地址和线程探索顺序都不能决定输出。在绑定稳定的来源之后再比较：同一个参数改了局部别名，结构不变；公开参数或状态名真的变了，P/E 的来源声明本身就不同。内部绑定按作用域和绑定位置识别；观察回执先按有序动作及其发生条件确立身份，再给显示编号。先凭真实依赖和有序动作绑定区分回执与快照，再建立表达式键；显示编号取自这个稳定身份，不参与自身的分配。无法区分的不同对象或事件不是平局，应该补足稳定身份，不用内存地址破局。

**示例：**

`c + (b + a)` 与 `(a + b) + c` 同形。只有前三级打平时，才用公开名字；已取得的 `$e_2` 在 `$e_10` 前。

**说明：**

结构键决定已取得的值怎么写，不改变产生该值时 S 的执行顺序。

### CF-03 化简与候选优先级

**规则：**

统一写法和消去计算是两项工作。`b + a → a + b` 只统一写法；`x - x → 0` 才消去计算，而且仅对当前域内两边确实是同一个已取得值、减法合同允许时成立。每次化简产生新节点，都通过同一个规范构造器重建，并把受影响的父节点加回待处理队列。

**复杂度是第一排序条件。** 对符合语义和观察条件的候选，先比较定义好的复杂度，例如对本章的标量规则，先看条件臂数，再看表达式里的运算次数；两项按这个顺序比较，不因内部是否共享节点而变。这里度量的是值的表示，不是 S 里真实发生的动作。只要已证明有更小的候选，就先化简，不能因为较复杂的写法字典序更靠前就选它。只有复杂度相等，才按前面的结构键裁决。有相同加数的结合括号不算新运算，因此可用定形统一；消掉 0 和把 2、3 合成 5 则确实减少运算，属于化简。这个优先级比较的是已定义的变形和可证明的候选，不是穷举世界上所有等价程序。

有些化简要先认出两个子式相同，例如 `(b + a) - (a + b)`。匹配时可以用同一套纯结构键识别两边，也可以直接消费子节点早已取得的定形结构。这不是先把父节点定成一个较复杂的代表；一旦证据表明能化成 0，就优先选 0。

```text
按源码执行，取得带类型和来源的值
→ 在当前路径条件下把子值化简并定形
→ 找有证明、且严格降复杂度的化简；若有，先用它，再处理受影响的节点
→ 无更小候选时，从同复杂度的有限候选中按结构键选唯一代表
→ 如果新结构暴露了可降的规则，回到化简；规则不再推进时交付
→ 超出预算则报告未完成
```

停止不能靠「多跑几遍应该会停」。一组规则只能选一个方向：同类排序一次就选定代表；消去规则每次必须让预先定义的度量严格下降。定形后若露出新的化简机会，再进入下一轮，这一轮必须实际降复杂度，不能在同一层来回换写法。若有需要临时展开的规则，必须限制在一个阶段内，交回比进入时更小的结果；不能让反向规则把成果再展开。超出资源预算报告未完成，不拿半成品叫规范形。

**固定顺序和能停止，还不能证明只有一种结果。** 对承诺统一的运算族，要验证从任意一对允许的输入变体出发，是否到达同一结构。对会在同一个子式上相遇的两条规则，还要检查先走哪条能否汇到同一结果。例如已取得的纯数值式 `(2 + 3) * 0`，向内折叠得 `5 * 0` 再归到 `0`；如果先在外层识别乘零，也直接到 `0`。相反，若两个允许的起点只能各自停在不同结构，固定规则顺序并没有解决问题。若无法证明汇合，就用直接构造整个等价族的办法，或收窄规则范围；不能用「目前先跑某条」掩盖两个终态。

**示例：**

`(b + a) - (a + b)` 在证明两边是同一个已取得的精确值后，优先化成 `0`。

**说明：**

能停止和顺序固定都不是收敛证明；等价输入须验到同形，完成不够就明示。

### CF-04 完整二分 CASE

**规则：**

对于本章的总布尔守卫，用「基准谓词＋取反标志」表示。直接布尔值以自身为基准；已证明互补的 `>`／`<=` 比较对，在比较两端的位置确定以后，以 `>` 为基准。交换两臂只翻转标志，不增加一次谓词求值。对同复杂度的直接布尔值或简单比较，优先不带取反标志的方向；其他守卫按[二分的比较基准](#cf-08-二分的比较基准)裁决。从选定的结果再生成候选，必须得到同一对，不能依赖源码先写了哪一臂。比如对精确计数，`count <= 0` 返回 0、否则返回原计数，定形成：

```text
CASE WHEN count > 0 THEN count ELSE 0 END
```

**示例：**

`CASE WHEN p THEN left ELSE right END` 与 `CASE WHEN NOT(p) THEN right ELSE left END` 均采用前者；取反却不交换两臂则不等价。

**说明：**

只适用于已证互补、取得域不变的完整二分。部分 CASE 不补 ELSE；多臂不得按守卫直接排序。

### CF-05 LET 的提取边界

**规则：**

**本例必须输出第二种。** 先做完数学化简；剩下的两次引用处于同一个输出值内，绑定不跨取得域，不移动动作，提取后表示确实更小。反过来，只返回一次总和、被重复的子式本身不含 CASE、或必须跨过外层保护条件才能共享时，都保留内联。选法与计数统一见[LET 的整值比较](#cf-09-let-的整值比较)，不能在输出时临时决定。

这条要求不限于 LET。PERS 新增字段、绑定或结构时，都要随设计交付**适用边界、唯一代表、稳定命名和两类验收**：等价输入收敛到同一份完整预期，有业务区别的输入仍能断言出区别。规则没定全，先补规则，再纠正所有受影响的 `expected`；不接受「带 LET 或不带都算对」，也不按用例特判。

**示例：**

已取得的同一含 CASE 聚合在单个结果里还出现两次，且提取后更小，才用同一个安全 LET；只有一次时保持内联。

**说明：**

LET 不新增一次执行或跨保护域取值。发布名与位置必须稳定，不以源码变量名和遍历偶然性定形。

### CF-06 完整 PERS 验收

**规则：**

断言比较解析后的完整交付结构：YAML 缩进和映射键的书写顺序不参与比较；字段有无、表达式内容、动作顺序、写入快照和异常条件都参与。局部等价的式子不能作为第二个答案，测试也不能重排 S、重写表达式，或把本次实际输出抄成预期。跨语言时，规范表达式可以相同，但不同文件的入口定位仍应不同，所以各自对完整预期断言，不抹掉入口来凑相等。

只跑一条 `equals` 还不够。规则验收再做三类检查：

| 检查 | 它能抓到什么 |
| --- | --- |
| 不同写法都命中同一预期 | 两种输入都跑；只比较两次实际输出，可能放过两个结果恰好犯了同一个错。 |
| 再做一次不变 | 对同一上下文里的规范结构再次执行值级化简和定形，比较整个结构，防止第一遍只排了顺序、第二遍才改括号。 |
| 业务差异不能被抹平 | 字符串拼接的两种顺序、两次外部调用互换、回执有无等反例要分别与正确预期比较。例如只断言 R，可能看不出两次调用已经颠倒。 |

遇到这种冲突，按下面的顺序修：

1. **先确认究竟是不是同一个业务结果。** 回到源码和业务合同，核对结果、取值条件、动作顺序和异常。行为不同就保留区别；已有明确规范的，也不因为某个旧用例写了别的答案就重开规则。
2. **同一结果而规范有漏洞，先修规范。** 写明适用前提、化简优先级和同复杂度时的唯一选法，再加上哪些情况不能套用。这个例子按本章的选向规则，以 `p` 为基准，选不取反的方向；未知回执的保护不能为此被删掉。
3. **按修订后的规范重新推导所有受影响的预期。** A 和 B 的 `R` 都应是 `CASE WHEN p THEN left ELSE right END`，以完整 PERS 重跑断言；另用只取反而不交换两臂的反例，确认测试仍能识别真正的行为差异。如果内核不满足新规范，修共享规则，不为个别用例开分支。

可以纠正 `expected`，但依据是源码、业务合同和明确后的定形规则，不是本次 `actual` 恰好怎么写。规范补齐之前，不把任一旧预期当作标准，也不把接受两个答案当成修复。

**示例：**

`value + delta` 和 `delta + value` 分别通过同一份完整预期；两个外部动作反过来执行，即使 R 相同也应断言出差异。

**说明：**

独立推导的 expected 是验收证据；不能抄 actual、改写 actual 或允许两个答案绕过规范。

### CF-07 整数守卫的代表

**规则：**

依据[整数区间证明](03-数学化简.md#ma-06-用整数区间证明守卫)得到真集后，从相同真集生成相同的候选。空集与全域对应 false 和 true；单点可以用等于，只缺单点可以用不等于；连续范围可以用上下界表达。允许同值的严格和非严格端点写法，统一在精确整数域计算端点。按整个表达式的复杂度、再按共享结构键选代表，不保留只因输入写法不同而额外得到的候选。

**示例：**

`x <= -1 OR x >= 1` 与 `x != 0` 都定形为 `x != 0`：一次比较比分别比较两个区间再用 OR 更小。

**说明：**

区间展开是候选之一，不是强制输出。若无法证明整数域、总性或同一来源，不能利用这个候选集。需要作为完整二分 CASE 守卫时，由[二分的比较基准](#cf-08-二分的比较基准)比较整值。

### CF-08 二分的比较基准

**规则：**

先按共享结构键固定比较两端，交换操作数时同时换向。两端固定后，对已证互补的比较，`> / <=` 取 `>`，`< / >=` 取 `<`，`== / !=` 取 `==` 为基准。分别化简守卫及其互补守卫，比较两种完整 CASE 候选的复杂度；相同时，直接布尔值取自身方向，简单比较取基准方向，复合守卫按共享结构键确定基准。用选定的代表重建候选，仍应得到同一对。

**示例：**

结构键把 x 排在 y 前时，`CASE WHEN y <= x THEN B ELSE A END` 先换边为 `CASE WHEN x >= y THEN B ELSE A END`，再定形为 `CASE WHEN x < y THEN A ELSE B END`。只取反不换臂，x=1、y=2 时会错误返回 B。

**说明：**

只作用于完整二分。若守卫的两种方向不互补（例如可能出现 NaN），或交换改变了取值域、异常、动作，就不生成另一候选。

### CF-09 LET 的整值比较

**规则：**

先化简，并从同一个内联基准寻找合格 LET 候选。子式自身含 CASE、同一安全域内至少出现两次、依赖均已取得，且不改变观察。度量先数条件臂，再数运算；每个 LET 声明和每次绑定引用各加一项，定义体只计一次。提取后的整值须严格小于内联基准，持平则不提。候选相互影响时比较最终合格的整值，不能把各自的节省相加，也不规定首步降幅最大的必胜。多个同复杂度的合格整值由共享结构键裁决。

**示例：**

令 `C = CASE WHEN enabled THEN a ELSE b END`，各值均已取得。`(C + p) * (C - q)` 提取 C，条件臂由两组变一组。`C * C` 则先化成 `CASE WHEN enabled THEN a*a ELSE b*b END`，不再提取。若两处候选仅是同一重复大子式内部的小 CASE，提取大子式后它只在定义里出现一次，不能再按原来的两次计省。

**说明：**

比较范围是一个输出值，不跨 R、其他 S 动作、行绑定、守卫或回执取得域。已有安全绑定与内联的等价变体必须收敛到同一份完整 PERS。这里只比较同一值可证明的安全提取，不穷举任意等价程序。

### CF-10 执行中定形不搬动动作

**规则：**

如果只在最后对输出做排版，减法执行时看到的是两棵不同的树，这次能直接使用的化简就错过了。**定形是为了让内核在下一步能认出「这是同一个值」，不只是为了让人看见相同的字符串。** 所以新表达式进入局部变量、堆状态或分支合并结果时，就要按这个规则形成可比较的结构；不能等到序列化 PERS 才做。

`port.readA() + port.readB()` 和 `port.readB() + port.readA()` 不是同一个执行。即使两次成功后的相加可以统一，**先调谁、谁失败就不再调另一个**，都可能不同。正确的分工是：先按原顺序执行并记录外部调用，再对已经取得而且允许重排的值做运算。不能重排 S，也不能把两次调用合成一次。出 PERS 时，P/E 的声明可以按稳定规则呈现，P 的 `position` 仍是原调用顺序；S 仍是有序动作，不能对动作列表做字典序。输出只序列化已经确定的结构，不再发明一套排序或化简规则。

**示例：**

`port.readA() + port.readB()` 仍按源码先读 A；若 A 先失败便不能补一次 B。定形只处理两次成功后已经取得的数值。

**说明：**

同理，`ready && reply.ok` 如果只允许在 `ready` 为真时读回执，就不能为了布尔项排序而先读取 `reply.ok`。未执行的调用没有回执，不等于已经取得一个值为 null 的回执。文本拼接、序列位置、实参顺序也不是集合，不能套用精确加法的交换规则。
