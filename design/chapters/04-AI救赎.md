# AI救赎

**AI 预处理只处理杂质。对已经纯净、有界的原语言工程，必须原样交付。** 各语言的解析器负责把原生程序翻译成统一 IR，内核负责在设计约定的业务语义下等价模拟原程序。分支怎样走、对象读写了什么、异常由谁捕获，都由工程按源码执行。AI 无须先把这些写成另一种更好分析的样子。[符号执行](01-符号执行.md) · [业务数值的合同](06-业务至上.md#bf-02-业务数值的精确合同)

## 交给 Normalizer 的是什么

**Normalizer 能分析的是纯净、有界的原生程序。** 原生，是计算仍用 Java 或严格的 TypeScript 表达。纯净，是从选定入口走进去，凡要在内核执行的逻辑，都能在源码里找到，或由标准操作、扩展语义给出明确的定义。真正的外部操作按声明的边界建模，不在内核执行其实现。有界，是循环、递归等计算有可证明的边界，或有可以整体求值的等价表达，不需要无限地逐步展开。输入值可以未知，程序也可以读写状态；不能不清楚的是这些动作怎么发生。

**AI 预处理交付的是零包依赖的强类型分析工程。** TypeScript 的 `package.json` 和 Java 的 `pom.xml` 都不能声明包依赖。原工程可以用 Minifish 注册 action、用 Spring 装配服务；如果交付物还要安装这些库，内核就得懂得各个库如何把控制权交回业务代码。例如 `this.$store.dispatch("init", query)` 背后的绑定经核实后，应让原来的本地初始化逻辑在分析工程里可达。只删掉包名、再给 `dispatch` 补一个空声明，会把初始化业务一并丢掉。[动态调用与本地依赖](#动态调用与本地依赖) · [预处理交付校验](#ai-11-分析副本先通过静态校验)

**本章以下五类都是杂质。** 从选定入口沿原码走，哪一处缺了原生程序独立分析所需的事实，或哪段计算无法有界执行，杂质就在哪里。源码很长、分支很多、算式可以化简，都不能据此认定有杂质。

例如，已有的 Java 入口里，只有加法藏在 JDK 的 `Integer.sum` 调用里。让加法回到原生表达式，这一处预处理就结束了。

```diff
 static int adjust(boolean reverse, int x, int y) {
-    if (reverse) return Integer.sum(y, x);
+    if (reverse) return y + x;
     return x + y;
 }
```

即使两条路径的结果显然相等，`if` 也要留给内核执行和化简。[AI-05](#ai-05-预处理停在哪儿)规定了每一笔改动的授权边界。

## 一、入口或接收实例藏在宿主里

已导出的 TypeScript 函数可以直接调用，Java 也可以从已有静态字段取得实例后调用它的方法。轮到 Spring 替应用选择实例、浏览器替应用派发事件、模板替组件求值时，单凭函数签名就找不准这一次调用。怎样从真实系统选择入口，见[场景归一](09-场景归一.md)。

### AI-03 入口和接收者可定位

**交给 Normalizer 的入口，必须能从 Java 类名或 TypeScript 模块导出直接找到并调用。** 要说清从哪里找到入口、调用哪个方法、传哪些参数。实例方法还要说清接收对象从哪里来；不能只给方法名，让模拟器去猜怎么创建 `this`。

- **Java 从类名出发。** 可以调用 `Entry.run(x)` 这样的静态方法，也可以从静态字段取得已装配实例，再调用 `Beans.QUOTE_CONTROLLER.quote(units)`。后者的 `quote` 仍是实例方法。原程序若复用实例，就保留复用；若每次调用都创建实例，就在源码里写明，不由模拟器代选。
- **严格 TypeScript 从模块导出出发。** 指定模块后，可以直接调用它导出的 `run(x)`，也可以从模块取出已装配的 `controller`，再调用 `controller.run(x)`。需要 `this` 时保留对象上的调用，不把方法单独取出来执行。

闭合 TypeScript 工程中的项目相对导入，按目标模块实际导出的绑定解析。显式导出的 `default` 是可以静态定位的导出，`import { default as step } from "./helper.js"` 与 `import step from "./helper.js"` 都绑定到该默认导出，不按本地别名猜一个同名具名导出。目标源码、类型、依赖闭合及初始化证据要求不变；实际没有 `default` 时应拒绝，不能回退到同名函数。

原入口已经满足这条规则就不改。如果入口由框架注册，AI 把调用方式和缺失的装配写清楚。形参接收的是这次调用的输入，接收对象上原有的状态不挪进形参。

**例如：**

`Beans.QUOTE_CONTROLLER.quote(units)` 从静态根取现有接收对象；不能换为临时 new 的控制器。

TypeScript 的 `controller.run(x)` 同理：保留接收者，不能把方法单独取出另调，也不能把 controller 的已有状态改作参数。

### 入口函数重组

框架替程序找到的入口、接收对象和装配，在分析工程里都要写得看得见。规则见[入口和接收者可定位](#ai-03-入口和接收者可定位)。

### AI-07 把隐含绑定写成显式调用

看到一份注册文件里只有一行，还不能断定整个部署只看得到一个实现。如果确认不了 `findFirst()` 会选谁，或者注册缺失、加载失败本身会影响执行，就不能用这个改法。

**例如：**

在实际部署中已确认 ServiceLoader 只会发现 AddOne 且构造正常，才把发现过程写成 `new AddOne()`；调用 `op.apply(x)` 由内核执行。

例如反射查找还有一条可观察的失败路径时，直接写成方法调用会绕过该路径。没有能保留查找失败和异常包装的等价交付，就报告不支持。

## 二、沿调用走下去，源码或定义断了

同样写成 `f(x)`，工程里有方法体就可以走进去；碰到只存在于 JDK、第三方 JAR 或框架里的运算，内核没有依据执行。先核对实际绑定和合同，再看原语言的一个操作、Normalizer 的标准函数或局部扩展能否说清它。

### 换成原语言原生写法

章首的 `Integer.sum` 只需还原为加法。若业务协议明定整数回卷，还要保留协议的回卷规则。[业务数值的精确合同](06-业务至上.md#bf-02-业务数值的精确合同)

布尔值也是一样。`@N.Nullable` 说明入参可能为空，短路判断让 null 时不拆箱。只有 true 返回 true，不把数字或文本转成布尔值。[BooleanUtils 的空值约定](https://commons.apache.org/proper/commons-lang/apidocs/org/apache/commons/lang3/BooleanUtils.html#isTrue(java.lang.Boolean))。

```diff
diff --git a/Flag.java b/Flag.java
--- a/Flag.java
+++ b/Flag.java
@@ -1,7 +1,7 @@
-import org.apache.commons.lang3.BooleanUtils;
+import normalizer.intrinsics.N;

 class Flag {
-    static boolean run(Boolean flag) {
-        return BooleanUtils.isTrue(flag);
+    static boolean run(@N.Nullable Boolean flag) {
+        return flag != null && flag;
     }
 }
```

**取默认值。** `Optional` 只是包装一个允许为空的值，参数 `fallback` 在进方法前已经求值。把它写成原语言条件并标明可空性。如果原来写的是 `orElse(f())`，要保留 `f()` 先执行的事实，不能挪进空值分支。

```diff
diff --git a/Selection.java b/Selection.java
--- a/Selection.java
+++ b/Selection.java
@@ -1,7 +1,7 @@
-import java.util.Optional;
+import normalizer.intrinsics.N;

 class Selection {
-    static String pick(String config, String fallback) {
-        return Optional.ofNullable(config).orElse(fallback);
+    static String pick(@N.Nullable String config, String fallback) {
+        return config == null ? fallback : config;
     }
 }
```

**校验。** 已确认原重载在条件不成立时抛 `IllegalArgumentException`。把检查写回去，仍在 `x * 2` 之前执行。本例不观察异常栈；若原代码依赖错误信息或检查顺序，也要保留。

```diff
diff --git a/Checked.java b/Checked.java
--- a/Checked.java
+++ b/Checked.java
@@ -1,8 +1,6 @@
-import com.google.common.base.Preconditions;
-
 class Checked {
     static int run(int x) {
-        Preconditions.checkArgument(x >= 0);
+        if (x < 0) throw new IllegalArgumentException();
         return x * 2;
     }
 }
```

作为对照，Java 的 `switch` 已经说明每个分支怎样执行，直接交给内核即可。

### 换成 Normalizer 标准库

值运算不能用原语言运算符直接表达时，就交成 Normalizer 标准库里的普通函数。JDK 和第三方 API 可以帮助确认原代码在做什么，但不作为规范源码的第二套入口。Java 和 TypeScript 可以用不同的值载体，调用的运算合同必须相同。

#### AI-02 标准操作的合同

调用应让人一眼看懂：对哪个值做什么、用什么规则、结果是什么类型。

- **名字写动作，必要时写单位。** `plusDays` 比 `add(date, n)` 清楚，因为它说了加的是日历日，不是毫秒。不同含义不靠运行时类型或隐式转换区分。
- **先写值，再写规则。** 先传被处理的值或左右操作数，再传天数、位数或范围，最后传模式或兜底。会改变结果的选项要显式传入，不偷用宿主的时区、语言环境或舍入习惯。模式用有类型的常量，例如 `N.HALF_UP`。
- **签名和合同一起看。** 输入与结果类型、null、有效范围和失败方式都要写清。裁剪认哪些字符、日期用哪种历法、十进制在哪一步舍入，都属于运算本身，不随语言或版本暗中改变。
- **值运算可以组合，不偷偷做别的事。** `N.multiply` 不舍入，`N.round` 只在写出来的地方舍入。内核有定义可以求值，也有明确的条件可以化简。值函数不暗读时钟、环境或随机源，不写状态，也不把合同里的失败变成默认值。标准库另有明确声明的环境读取操作，例如 `N.currentTimeMillis()`；它不是值函数，不按纯函数规则化简。

| 代表签名 | 调用者可以据此知道什么 |
| --- | --- |
| `trim(value: text?) → text?` | 按固定的裁剪规则检查两端，null 仍是 null。 |
| `defaultIfBlank(value: text?, fallback: text) → text` | null、空串或符合标准空白判定时才选兜底；其他值原样返回。 |
| `multiply(left: decimal, right: decimal) → decimal` | 两个精确十进制数相乘，不设默认位数，不中途舍入。 |
| `round(value: decimal, scale: integer, mode: RoundingMode) → decimal` | 位数和模式都是显式参数；两种模式可能给出不同结果。 |
| `plusDays(value: date, days: integer) → date` | 在已取得的 ISO 日历日上加有符号天数；越界按合同失败，不读取今天。 |

Java 用 `import normalizer.intrinsics.N;`，TypeScript 用 `import * as N from "@normalizer/stdlib";`。调用写成 `N.trim(x)`，不把 `trim` 裸导入应用作用域。应用可以有自己的 `trim`；就算也写成了 `N.trim`，只要 `N` 绑定的是应用对象，它就不是标准库。内核核对官方库和具体成员签名。即使两次调用返回相同毫秒，`N.currentTimeMillis()` 也是两次环境观察，分别进入 E，不进入 S。如果应用的类型、变量或成员挡住了官方 `N`，只能在有依据保留原行为时改名，否则报冲突。

#### 标准库怎么设计，调用就怎么写

标准调用要让人一眼看出对哪个值做什么。签名、参数顺序和识别规则见[标准操作的合同](#ai-02-标准操作的合同)。下面用文本、小数和日期演示。

**文本。** 先裁剪、再给空白值选兜底，顺序没变；可空标记不是一次转换，只说明 raw 本来就可以为空。

```diff
diff --git a/src/LabelService.java b/src/LabelService.java
--- a/src/LabelService.java
+++ b/src/LabelService.java
@@ -1,7 +1,7 @@
-import org.apache.commons.lang3.StringUtils;
+import normalizer.intrinsics.N;

 class LabelService {
-    String normalizeLabel(String raw, String fallback) {
-        return StringUtils.defaultIfBlank(StringUtils.trim(raw), fallback);
+    String normalizeLabel(@N.Nullable String raw, String fallback) {
+        return N.defaultIfBlank(N.trim(raw), fallback);
     }
 }
```

一旦两个纯调用都被证明是同一项标准运算，用的又是同一个值，内核就能认出结果相同。如果合同里 null 不可能是非空白文本，那么 `isNotBlank(x) AND x == null` 的真分支也可以消掉。前提是两边在所交付的业务合同里等价，包括需要保留的字符、空值和失败行为，不能只凭方法名合并。宿主文本规则不属于业务合同时，按[业务至上的文本清理规则](06-业务至上.md#bf-05-文本清理按业务合同统一)交付同一标准操作。

**精确小数。** 原来的 `BigDecimal` 类型留下，一行写出先精确相乘、再按两位 HALF_UP 舍入。对 1.005，HALF_UP 和 HALF_EVEN 分别给出 1.01 和 1.00。小数位数如果还被比较或格式化观察，也不能丢。TypeScript 要交同样的精确值语义，不能改用普通浮点近似。

```diff
diff --git a/Scale.java b/Scale.java
--- a/Scale.java
+++ b/Scale.java
@@ -1,7 +1,7 @@
-import java.math.RoundingMode;
+import normalizer.intrinsics.N;

 class Scale {
     static java.math.BigDecimal run(java.math.BigDecimal x, java.math.BigDecimal y) {
-        return x.multiply(y).setScale(2, RoundingMode.HALF_UP);
+        return N.round(N.multiply(x, y), 2, N.HALF_UP);
     }
 }
```

**日期。** 这里 `Period` 只携带天数，直接换成 `N.plusDays`。2024-02-28 加一天是 2024-02-29。这不是给时间戳加固定毫秒数。日历日已经给出时可以算；向系统问「今天几号」才需要外部观察。[日历加日的参考合同](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/time/LocalDate.html#plusDays(long))。

```diff
diff --git a/NextDate.java b/NextDate.java
--- a/NextDate.java
+++ b/NextDate.java
@@ -1,8 +1,8 @@
 import java.time.LocalDate;
-import java.time.Period;
+import normalizer.intrinsics.N;

 class NextDate {
     static LocalDate run(LocalDate date, int days) {
-        return date.plus(Period.ofDays(days));
+        return N.plusDays(date, days);
     }
 }
```

### 集合库与 SQL

即使列表里恰好只有两项，`stream().filter(…).count()` 仍依赖库的遍历、筛选和计数合同。核实空值、重复项、次序和回调的效果后，在调用处交付相应操作。具体的[集合运算与有序选择](05-关系代数.md#关系集合与循环)由第五章定义。

#### 已知的 SQL 也交成关系

## 三、计算没有可静态展开的上界

同一份[评分重试源码](../../tests/seeds/topics/loops-and-termination/java-loop-bounded-retry.md)有两个循环。前一个最多尝试三次，内核可以逐轮执行。给真实评分端口标出身份与失败合同以后，这个循环原样交付，包括每次调用、提前返回和失败后继续。

```java

        return scoreClient.fetchScore(accountId);
    } catch (RetryableScoreError ignored) {
        // retry
    }
}
```

```diff

-        for (int credit = 0; credit < availableCredits; credit++) {

-        }

+           fallbackScore += count from [0, availableCredits) as credit
```

若每一轮还会写库存、发请求或根据上一轮结果提前退出，计数就表达不了它。按[逐项运算与等价交付](05-关系代数.md#ra-07-逐项运算与等价交付)核对能否用已定义的值操作表达。找不到等价形式时，指出循环位置和哪项行为无法保留。

## 四、普通声明没有表达业务身份

一次调用临时创建的对象、上一次请求留下的库存、能向订单服务创单的端口，都可能声明成普通字段。把三者都当作本地堆对象，程序即使能走完，也会漏掉已有库存的来源或真实发生的创单。标记实际声明，让内核在原代码读、写、调用时认出它；业务后果见[PERS 中的库存与创单](07-PERS登场.md#例二-java-完整入口从已有状态到外部回执)。

### AI-08 外部端口要有真实合同

JAR 没有源码时，AI 可以用常识理解普通 DTO：如果接口签名、字段定义或序列化约定，以及工程各处的用法都指向一个只搬数据的对象，就可以把 `setId(id)` 还原成写入 `id`，把 `getValue()` 还原成读取 `value`。不必因为看不到 getter/setter 的源码就卡住，但也不能只凭方法名猜。发现有默认值、校验或转换，就要保留；无法判断这些行为、且它们会影响结果，就报告缺口。

外部端口的成功回执须有可解析的类型合同；合同确为宽类型时，按《符号执行》处理，不替它补具体字段。失败路径见[外部异常须显式声明](#ai-09-外部异常须显式声明)。

**例如：**

已核实支付端口的合同：成功回执有 `receiptId`，余额不足时以 `InsufficientFunds` 拒绝。分析副本声明该异常类，并用 `@N rejects InsufficientFunds` 标记外部端口方法。分析入口执行：

```ts
const receipt = await payment.charge(amount);
return receipt.receiptId;
```

走到 `charge` 时，`S` 记一条支付调用及本次完成绑定。成功路径的 `R` 是同一次回执的 `receiptId`。余额不足时，`S` 里的调用仍在；源码没有捕获，`throws` 记录 `InsufficientFunds`，不会执行 `return`。

对照两次 `N.currentTimeMillis()`：到各自语句时分别取得两个以 Unix 纪元毫秒表示的符号值，记为两次 E，不补 S，也不能断言这两个值必然相等或不等。

### AI-09 外部异常须显式声明

本地异常按源码和语言语义推导。AI 预处理优先根据可核实的合同标记外部异常；合同不足时，可根据已确认的外部操作和常识标记。未标记的外部异常不产生异常路径。

**例如：**

原程序用 HTTP 查询回执。调用失败时，不区分异常类型，也不读取异常内容，一律返回 `"unavailable"`。即使拿不到服务的异常合同，AI 也能根据 HTTP 调用可能遇到网络故障，用通用外部失败来建模。预处理后的代码如下（`ExternalFailure` 是 Normalizer 内置的失败类型，不是第三方异常类）：

```ts
interface ReceiptPort {
  /** @N rejects ExternalFailure */
  fetchReceipt(id: string): Promise<{ receiptId: string }>;
}

/** @N external */
declare const receipts: ReceiptPort;

export async function readReceipt(id: string): Promise<string> {
  try {
    const receipt = await receipts.fetchReceipt(id);
    return receipt.receiptId;
  } catch {
    return "unavailable";
  }
}
```

**有标记时：** PERS 的 `S` 记录这次端口调用；`R` 在调用成功时返回回执编号，在调用失败时返回 `"unavailable"`。异常已被捕获，不向入口外传播。

**只删掉 `@N rejects ExternalFailure` 时：** `S` 仍记录端口调用，但不产生失败路径。这里的 `try` 没有其他异常来源，所以 `catch` 不可达，`R` 只保留回执编号。不报 `Panic`，照常生成 PERS。

## 五、可达代码缺少类型声明

`any` 隐去了分析需要的类型，或外部接口只留下一个找不到定义的回执名。沿原调用找参数、字段、可空性和失败合同，补回缺失的声明。例如接口已声明 `id` 为文本，JS 入口只把它原样返回。交付严格 TypeScript 只需补入参类型，返回类型可以推断，函数体原样交付。

```ts
    | { kind: "delivery"; address: string };

export function summarize(order: Fulfillment): string {
    if (order.kind === "pickup") return "门店：" + order.storeId;
    return "送达：" + order.address;
}
```

两个对象形状都明确，按 `kind` 收窄的是已知联合类型。只有选择的确实是这个已有入口，才能用它的类型合同。分析上面的请求处理器时，不能把校验和失败移出观察范围，也不能用断言冒充校验。

## 交付前的准入

前五节说明如何去除杂质。交付时再做三道检查：包清单不引入依赖；源码引用全部闭合并有准入合同；最终源码通过编译和静态校验。这三项不能互相替代。

### 零包依赖

先检查交付目录中的包清单，再检查源码。清单可以省略，已有清单可以保留工程名和版本。npm 的运行、开发、可选、同伴和打包依赖都须为空。Maven 的依赖声明（含 profile、依赖管理及插件内声明的依赖）也须为空；用到父 POM 时须能在交付目录内核实。机器已有缓存或入口没有用到所声明的包，都不改变这个要求。

例如，同一份 TypeScript 源码，带下面的清单时拒收；经预处理消除框架依赖后可以这样交付：

```diff
-{"name":"arrears-analysis","dependencies":{"@alipay/minifish-store":"^1.0.15"}}
+{"name":"arrears-analysis"}
```

### 合法引用白名单

#### AI-01 可达类型要闭合

白名单检查的是**源码实际绑定的声明和用法**，不是一份包名表。本项目定义、Normalizer 内置声明和按名单承认的宿主值载体以外，JDK、JS 标准库、浏览器、Node 和第三方模块都不自动获准。对依赖名改个别名、写成全限定名、走默认导入或直接用宿主全局名称，判定不变。声明用在形参、字段、泛型、类型注解或异常位置，同样要查。

| 允许的导入 | Java | 严格 TypeScript |
| --- | --- | --- |
| 分析工程自己的声明 | 显式导入最终解析到交付源码内的类或接口，如 `import app.model.Bill;`。 | 只导入工程内可解析的项目相对源码，不能越出根目录。具名、显式默认导入和类型导入按真实导出解析。 |
| Normalizer 内置入口 | `import normalizer.intrinsics.N;` | `import * as N from "@normalizer/stdlib";`，由 Normalizer 供给声明，不是 npm 包。 |
| 明确登记的宿主值载体 | `import java.math.BigDecimal;`、`import java.time.LocalDate;`，分别承载精确小数和日历日。 | 没有额外的宿主模块可导入。内建的 `number`、`boolean`、`string` 等用语言自身的类型。 |

工程内代码不是豁免通道：沿导入继续解析引用，实际要执行的本地逻辑要有源码；声明成类型也不能掩盖副作用导入。Java 不开放 `java.time.*`、`java.math.*`、`java.util.*` 等整包；TypeScript 不开放动态加载、宿主模块或靠副作用完成装配的导入。原始项目若确实依赖这些行为，取出可核实的语义再交付，不能删掉行为。

语言原生运算和已定义的隐式类型不需要额外导入，例如 Java 的 `String` 和 `Object`（见[宽类型值](01-符号执行.md#se-03-宽类型值按源码语义执行)），不因此开放整个 `java.lang`。允许一个值载体也不等于批准其库方法，`N` 同样只承诺[已登记的操作](#ai-02-标准操作的合同)。[业务原生类型](06-业务至上.md#bf-03-按业务值区分类型)里尚无明确宿主载体或用法的类型，不能靠业务名字推定某个库已获准。

例如，`LocalDate` 可承载已知日历日，`N.plusDays(date, 1)` 对它做已定义的运算；`LocalDate.now()` 即使用全限定名写，也不能借该类型的批准读取系统时钟和默认时区。TypeScript 的 `new Date()`、`Intl`、`fetch()` 不写 import 也不是纯净代码的原生操作。实际 HTTP 调用应交付成有[可核实合同的外部端口](#ai-08-外部端口要有真实合同)，不能把本地库调用伪装成端口。

准入发现名单外引用，拒绝执行并指出具体位置、实际绑定和未获准的用法；不在内核里猜测行为。

### 编译与静态校验

#### AI-04 强类型准入

前端交付严格 TypeScript。不接受显式、隐式或经类型解析得到的 `any`；遇到它报 `Panic: not-support`，不执行入口、不生成 PERS。`unknown` 可以原样交付，按[宽类型值按源码语义执行](01-符号执行.md#se-03-宽类型值按源码语义执行)处理；不能为了预先得到具体类型而改掉原来的检查或失败路径。

**例如：**

`handleOrder(mode: unknown, value: unknown)` 可以交付。若 `value` 不是字符串，保留 `Expected text` 异常；检查通过后，才按字符串拼接。把任一入参改成 `any` 会在准入时拒绝，而不是执行到拼接才报错。

#### AI-11 分析副本先通过静态校验

仅靠交付的源码和类型、约定的语言原生能力以及 Normalizer 内置定义，分析工程须通过强类型校验。本地业务实现随源码交付，真实外部端口按 [AI-08](#ai-08-外部端口要有真实合同) 声明合同。分析器在执行前校验入口、宿主语法、类型，以及原生语句和扩展指令的绑定与确定赋值。保留指令位置以便诊断；受保留语法约束的未知标记不能当普通注释。原模板和改写对照不是分析副本的运行前提。

**示例：** `Count.run` 先声明 `int rows;`，再以有效的 `@normalizer-ir rows = count from bill as b` 赋值，最后返回 rows，可在表合同完整时进入分析。若只在 true 臂赋值、false 臂仍返回 rows，则在执行前拒绝，不生成 PERS；不能补 `= 0` 改变该臂结果。分析副本必须通过扩展感知的校验，否则不执行入口、不生成 PERS；不要求删除指令后还能作为生产代码部署。

## 别越俎代庖

### AI-05 预处理停在哪儿

**只允许用设计明确规定的方式消除已定位的杂质，其余代码一律原样交付。** 每一笔 diff 都须说明两件事：原码在这里缺什么，以及源码、配置或依赖合同怎样证明这笔改动恰好补上了它。能单独撤回而仍可正确分析的一笔，必须撤回。即便同时处理多个杂质，也须逐处满足这条规则。省略宿主机制还须满足[业务至上的两个前提](06-业务至上.md#bf-01-省略的两个前提)。

有界的原生循环照常交付。必须替换的循环只能交付已证明等价的正式数学操作；资源预算耗尽属于分析未完成。

如果原码符合设计、当前实现却在某个原生结构上失败，应保留原码并指出工程缺口。把它改写到 CLI 通过，会掩盖解析器或内核本应支持的行为。

没有源码或可靠语义的本地调用，不得编方法体或冒充对外动作；不能等价交付时报告缺口。若仍送入分析，遇到不允许的类型或执行到无定义的调用，报 `Panic: not-support`，不输出 PERS。

下面三个反例展示：提前计算、猜测业务结果分别会丢掉什么。

**反例一：把分支和算式提前化简。** 两条路径的结果虽然相同，但这段 Java 本来就能执行。AI 不用先认出 `x + y` 和 `y + x` 等价，再替内核消掉分支。保留原代码，由内核执行并化简。

```diff
diff --git a/Branch.java b/Branch.java
--- a/Branch.java
+++ b/Branch.java
@@ -1,6 +1,5 @@
 class Branch {
     static int run(boolean reverse, int x, int y) {
-        if (reverse) return y + x;
         return x + y;
     }
 }
```

**反例二：把集合运算直接算成公式。** 下面的公式即使对这两个输入完全等价，也跳过了内核的关系运算。AI 应该交付的是：有两项的序列，从中筛选大于 0 的项，再计数。筛选和计数能化简成什么，由内核决定。

```diff
diff --git a/CountPositive.java b/CountPositive.java
--- a/CountPositive.java
+++ b/CountPositive.java
@@ -1,8 +1,5 @@
-import java.util.List;
-
 class CountPositive {
     static long run(int a, int b) {
-        List<Integer> values = List.of(a, b);
-        return values.stream().filter(v -> v > 0).count();
+        return (a > 0 ? 1L : 0L) + (b > 0 ? 1L : 0L);
     }
 }
```

**反例三：替内核决定两次环境读取的结果。** 同一个时钟调用出现两次，不代表两次读到同一个值。AI 可以把两次 JDK 调用分别换成 `N.currentTimeMillis()`，但不能合并调用或直接交一个 0。这里预处理过头，已经改变了程序行为。

```diff
diff --git a/ReadTwice.java b/ReadTwice.java
--- a/ReadTwice.java
+++ b/ReadTwice.java
@@ -1,7 +1,5 @@
 class ReadTwice {
     static long run() {
-        long first = System.currentTimeMillis();
-        long second = System.currentTimeMillis();
-        return second - first;
+        return 0L;
     }
 }
```

## 无法等价改写，就放弃治疗

无法写出等价程序时，AI 就停在这里：保留原代码，指出卡在哪个调用、缺什么信息。只知道签名，不能编方法体，也不能因为看不见实现就标成 `External`。

下面是两个**保持原样的输入**，没有改写后的版本。第一个只知道 JAR 里的 `OpaqueEngine.compute(int)` 的签名，不知道它实际做什么。

```java
import vendor.plugin.OpaqueEngine;

class Entry {
    static int run(int x) {
        return OpaqueEngine.compute(x);
    }
}
```

第二个类型是工程自己的，但 `native` 方法没有交付可执行实现，也没有已知的外部合同。

```java
class NativeEntry {
    static native int apply(int x);

    static int run(int x) {
        return apply(x);
    }
}
```

这两例都没有可靠的改写版本。对应源码位置的拒绝及其与业务异常的区分见[预处理停在哪儿](#ai-05-预处理停在哪儿)。
