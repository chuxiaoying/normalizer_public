# 符号执行

给普通 JVM 一个具体参数，它会执行程序，算出这次的结果。给 Normalizer 一个未知参数，它也执行同一个程序，只是先用符号代表这个值。如果参数是 `2`，加一得到 `3`；如果参数是符号 `X`，加一得到 `X + 1`。两者都做了加法，算出的值都能存进局部变量，也都能写进对象字段。

这需要一台真正维护执行状态的模拟器：它知道程序执行到哪里，哪些局部值和对象还在，以及字段刚被谁改过。下面的六张快照展示这台模拟器如何一步步得出结果。状态处理的细节见[按源码执行](#se-01-按源码执行并维护真实状态)。

## 六行代码，六张快照

```java
class Box { int value; }

class Demo {
    static int run(int x) {
        Box box = new Box();  // ①
        int y = x + 1;        // ②
        box.value = y;        // ③
        if (x > 0) {          // ④
            box.value += 10;  // ⑤
        }
        return box.value;     // ⑥
    }
}
```

从 `run(X)` 开始，`X` 代表未知的入口参数。每个编号紧跟一张**该行执行后的完整快照**：把当前执行位置、栈帧和所有局部值、堆对象和所有字段重新列出来，即使没有变化也照样列。左边是栈，右边是堆。栈帧把入口参数和执行到当前行已经绑定的局部变量分开画：参数 `x` 一进方法就有，局部变量 `y` 到第 ② 行才出现。真实 JVM 用同一个局部变量数组存放两者；图里的分区只用来说明它们分别在何时取得值，不代表 JVM 有两块独立的存储区。箭头表示引用：槽里的 `B1` 是对象标记，不是对象本身。快照拍在一行执行完之后，临时操作数已经用完。

### ① `Box box = new Box();`

`new` 在堆上分配对象，字段 `value` 初始为 0。构造完成后，局部变量 `box` 持有它的引用。

```text

STACK                        HEAP
┌────────────────────┐
│ run() frame        │
├────────────────────┤
│ Parameters         │
│ x   = X            │
├────────────────────┤
│ Local variables    │       ┌─────────────────────┐
│ box = B1           │──────▶│ B1 : Box            │
├────────────────────┤       ├─────────────────────┤
│ operands: empty    │       │ value = 0           │
└────────────────────┘       └─────────────────────┘
```

### ⑥ `return box.value;`

两份 JVM 各自从自己的堆读出字段，弹出 `run` 的栈帧，交出返回值。这里的堆画的是入口结束那一刻。

```text
A  X > 0   return (X + 1) + 10
STACK                        HEAP
┌────────────────────┐       ┌─────────────────────┐
│ (empty)            │       │ B1 : Box            │
└────────────────────┘       ├─────────────────────┤
                             │ value = (X + 1) + 10 │
                             └─────────────────────┘

B  X <= 0   return X + 1
STACK                        HEAP
┌────────────────────┐       ┌─────────────────────┐
│ (empty)            │       │ B1 : Box            │
└────────────────────┘       ├─────────────────────┤
                             │ value = X + 1       │
                             └─────────────────────┘
```

普通 JVM 运行 `run(2)`，只走真分支，返回 13；运行 `run(-2)`，只走假分支，返回 -1。把这两个具体值代进各自的符号结果，也得到 13 和 -1。

**执行即归约。** 栈和堆里发生过的计算最后归约成结果，不用把每个执行步骤再写一遍。怎样按源码推进，以及遇到缺口怎么办，见[规则区](#规则区)。

## 规则区

以下条例挑出能体现本章主张、便于引用和继续细化的情形，不穷举所有写法。没有列出的情形仍按本章主张和已确立的业务合同判断。

### SE-01 按源码执行并维护真实状态

**规则：**

按源码求值顺序推进：调用建立栈帧，返回结束当前栈帧，创建对象分配身份，字段写入更新对应堆对象。已知常量照常执行，未知入参用有类型的符号参与同一套执行。

**示例：**

`x + 1` 在 `x = 2` 时得到 `3`，在入参为符号 `X` 时得到 `X + 1`。两种结果都能写入 `box.value`。

**说明：**

源码顺序和对象身份属于执行语义，不要求复刻某台 JVM 的字节码、内存布局或寄存器。

### SE-02 执行覆盖与缺口

**规则：**

覆盖全部合法 Java 写法是设计目标；凡影响结果的步骤都要执行。无法支持时明确拒绝，不得跳过或猜测。已完成的路径不能继续执行后续语句。

**示例：**

`return box.value` 已完成该次调用；不能继续更新这个调用已退出的栈帧。若某个会影响结果的调用无法执行，不能跳过它并照常交付结果。

**说明：**

归约会消除执行过程的写法，不会消除已发生的观察；完成路径的处理见[多重宇宙](02-多重宇宙.md#规则区)。
