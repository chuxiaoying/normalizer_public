# 符号执行

给普通 JVM 一个具体参数，它会执行程序，算出这次的结果。给 Normalizer 一个未知参数，它也执行同一个程序，只是先用符号代表这个值。如果参数是 `2`，加一得到 `3`；如果参数是符号 `X`，加一得到 `X + 1`。两者都做了加法，算出的值都能存进局部变量，也都能写进对象字段。

这需要一台真正维护执行状态的模拟器：它知道程序执行到哪里，哪些局部值和对象还在，以及字段刚被谁改过。下面的六张快照展示这台模拟器如何一步步得出结果。状态处理的细节见[按源码执行](#se-01-按源码执行并维护真实状态)。

遇到外部边界时，模拟器按已声明的合同记录动作或环境读取，并以符号化的完成结果继续分析，不访问外部系统。

## 六行代码，六张快照

```java
class Box { int value; }

class Demo {
    static int run(int x) {
        Box box = new Box();  // ①
        int y = x + 1;        // ②
        box.value = y;        // ③
        if (x > 0) {          // ④
            box.value += 10;  // ⑤
        }
        return box.value;     // ⑥
    }
}
```

从 `run(X)` 开始，`X` 代表未知的入口参数。每个编号紧跟一张**该行执行后的完整快照**：把当前执行位置、栈帧和所有局部值、堆对象和所有字段重新列出来，即使没有变化也照样列。左边是栈，右边是堆。栈帧把入口参数和执行到当前行已经绑定的局部变量分开画：参数 `x` 一进方法就有，局部变量 `y` 到第 ② 行才出现。真实 JVM 用同一个局部变量数组存放两者；图里的分区只用来说明它们分别在何时取得值，不代表 JVM 有两块独立的存储区。箭头表示引用：槽里的 `B1` 是对象标记，不是对象本身。快照拍在一行执行完之后，临时操作数已经用完。

### ① `Box box = new Box();`

### ⑥ `return box.value;`

两份 JVM 各自从自己的堆读出字段，弹出 `run` 的栈帧，交出返回值。这里的堆画的是入口结束那一刻。

```text
A  X > 0   return (X + 1) + 10
STACK                        HEAP
┌────────────────────┐       ┌─────────────────────┐
│ (empty)            │       │ B1 : Box            │
└────────────────────┘       ├─────────────────────┤
                             │ value = (X + 1) + 10 │
                             └─────────────────────┘

B  X <= 0   return X + 1
STACK                        HEAP
┌────────────────────┐       ┌─────────────────────┐
│ (empty)            │       │ B1 : Box            │
└────────────────────┘       ├─────────────────────┤
                             │ value = X + 1       │
                             └─────────────────────┘
```

把两个具体输入代回刚才的快照，可以逐项核对同一次调用：

| 输入 | 执行 `box.value = y` 后 | 是否执行 `+= 10` | 从同一对象读回 |
| --- | --- | --- | --- |
| `x = 2` | 3 | 是 | 13 |
| `x = -2` | -1 | 否 | -1 |

**执行即归约。** 栈和堆里发生过的计算最后归约成结果，不用把每个执行步骤再写一遍。怎样按源码推进，以及遇到缺口怎么办，见[规则区](#规则区)。

## 规则区

### SE-01 按源码执行并维护真实状态

**规则：**

按源码求值顺序推进：调用建立栈帧，返回结束当前栈帧，创建对象分配身份，字段写入更新对应堆对象。已知常量照常执行，未知入参用有类型的符号参与同一套执行。

保留源码语义，不复刻某台 JVM 的字节码或内存布局。

**示例：**

`x + 1` 在 `x = 2` 时得到 `3`，在入参为符号 `X` 时得到 `X + 1`。两种结果都能写入 `box.value`。

### SE-02 执行覆盖与缺口

**规则：**

在纯净、有界的输入范围内，设计目标覆盖所有合法 Java 写法；严格 TypeScript 的可分析源码也按相同原则执行。凡影响结果的步骤都要执行。已知不合规的输入在入口拒绝；执行中遇到无法分析的行为，报告缺口，不得跳过或猜测。只有完成了本调用应执行的收尾，路径才算结束。

**示例：**

没有待执行的收尾时，`return box.value` 完成该次调用。若 `return` 位于 `try` 中，则先暂存返回结果，再执行 `finally`；若 `finally` 抛出异常，最终完成是异常而不是原返回值。

若调用之前已发生可观察动作，拒绝分析不等于断言没有执行过这些动作；正常归约同样不消除已发生的观察。完成路径的区别见[多重宇宙](02-多重宇宙.md#规则区)。

### SE-03 宽类型值按源码语义执行

**规则：**

IR 用同一套宽类型值模型承接 TypeScript 的 `unknown` 和 Java 的 `Object`，保留来源语言的值域、实际类型和适用的对象身份。存储、传递、返回或抛出一个值，不要求先确定它的具体类型。遇到类型判断、转换或调用时，按源码语义和当前路径已有的证据执行；只在证据成立的路径收窄类型，保留其余可达路径及其结果或异常。

**示例：**

```ts
export function read(value: unknown): string {
    if (typeof value !== "string") throw new TypeError("Expected text");
    return value;
}
```

```java
class Entry {
    static String read(Object value) {
        if (value instanceof String text) return text;
        throw new IllegalArgumentException("Expected text");
    }
}
```

文本路径返回的都是原入参，不是新造的符号。TypeScript 的数值、`null` 和 `undefined` 走非文本路径；Java 的其他对象引用和 `null` 也走非文本路径。两者共用类型判断和收窄机制，但 Java 原始值只有装箱后才能作为 `Object` 传入。若 TypeScript 的 `catch (error)` 只是 `throw error`，就继续传递原异常值，不替换成通用 `Error`。

别名、字段声明及类型推导得出的 `unknown` 都按同一规则处理。例如 `type Payload = unknown` 不会使 `value as string` 真正执行检查；`typeof value === "string"` 才建立可按文本处理的路径。
