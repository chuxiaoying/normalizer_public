# 多重宇宙

符号执行遇到一个真假都可达的判断，就从当前状态分出两份模拟 JVM。每一份沿自己的路径走，只改自己的栈和堆。这样能算对每条路，但如果分出去的 JVM 一直各自运行，遇到下一个未知判断时，每一份又可能再分成两份。十个彼此独立的二分判断，在所有组合都可达、且一路不合并时，最多会留下 1024 份状态。这就是分支爆炸。只把分叉时的内存复制做快，并不能减少这些状态各自要做的工作。

## 分到两边做，走到一起继续

看这一小段 Java：

```java
class Box { int value; }

class Demo {
    static int run(int x) {
        Box box = new Box();
        box.value = x + 1;
        if (x > 0) {
            box.value += 10;
        }
        return box.value;         // 两条路径的共同后续
    }
}
```

用 `X` 代表还未知的入口参数。判断之前，`box` 指向已创建的对象 `B1`，它的字段值是 `X + 1`。执行 `if` 时，真分支在自己的堆上加十，假分支跳过这一行。现在两条路都来到了同一条 `return`，但还没执行它：

```text
A  X > 0    next: return box.value
STACK                        HEAP
┌────────────────────┐       ┌────────────────────────┐
│ run() frame        │       │ B1 : Box               │
│ x   = X            │       ├────────────────────────┤
│ box = B1           │──────▶│ value = (X + 1) + 10   │
└────────────────────┘       └────────────────────────┘

B  X <= 0   next: return box.value
STACK                        HEAP
┌────────────────────┐       ┌────────────────────────┐
│ run() frame        │       │ B1 : Box               │
│ x   = X            │       ├────────────────────────┤
│ box = B1           │──────▶│ value = X + 1          │
└────────────────────┘       └────────────────────────┘
```

两边的栈帧一样，`box` 指向的也是分叉前就存在的同一个对象。不同的只有 `B1.value`。于是把两份 JVM 合成一份：相同的内容只留一份，不同的字段值用 `CASE WHEN` 连同成立的条件一起存下。

```text
next: return box.value
STACK                        HEAP
┌────────────────────┐       ┌────────────────────────────────────┐
│ run() frame        │       │ B1 : Box                           │
│ x   = X            │       ├────────────────────────────────────┤
│ box = B1           │──────▶│ value = CASE                       │
│                    │       │   WHEN X > 0 THEN (X + 1) + 10     │
│                    │       │   ELSE X + 1                       │
│                    │       │ END                                │
└────────────────────┘       └────────────────────────────────────┘
```

这就是**坍缩**。两份状态不再分别往下走，模拟器只执行一次 `return box.value`，从堆里读出刚存进去的条件表达式。带入 `X = 2`，得到 13；带入 `X = -2`，得到 -1。两种结果都还在，只是不再需要两份 JVM 来装它们。

两条路恰好覆盖进入这个 `if` 的所有可能，所以这个例子里能写 `ELSE`。一般情况见[分裂与覆盖](#mv-01-分裂与覆盖)。

## 能合并的才合并

源码上画到同一行，也不一定意味着两条路都能走到那里。下面这个例子里只有一条路会继续：

```java
if (x > 0) {
    return 1;
}
return x;
```

真分支已经返回了 1，不会执行最后一行。此时可以把 1 记为真分支的完成结果，但不能把那份 JVM 拉回来执行 `return x`。只有假分支还在继续；两条路的结果在函数结束处各按自己的条件保留。

所以，**遇到未知判断就按可达性分裂，遇到能保留差异的共同后续就及时坍缩。** 否则，前一个已经处理完的判断还会带着多份 JVM 去迎接下一个判断。坍缩也不是让差异凭空消失：原先存在不同栈和堆里的值，现在可能写成同一个槽或字段里的条件表达式。少的是需要继续运行的状态，不是程序本来就有的区别。

## 规则区

### MV-01 分裂与覆盖

**规则：**

只为当前域中真实可达的分支分裂。合并出的条件值继续受原进入条件约束；只有剩余臂确实覆盖该域的其余情况时才用 ELSE。

**示例：**

若进入判断之前已知 `x > 0`，再执行 `if (x > 0)`，只走真支，不建假支。

**说明：**

不能为部分 CASE 补默认值，也不能把内层分支推论当成全域事实。

### MV-02 共同后续才坍缩

**规则：**

仅在分支有共同可执行后续，且可以保存各自的值、状态和已发生操作时合并；已返回或抛出的分支保留自己的完成结果。

**示例：**

`if (x > 0) return 1; return x;` 中，真支的 1 直接进入完成结果，只有假支执行第二个 return。

**说明：**

同一字段在两条继续执行的路径上取值不同时，可以用 CASE 保存差异；不能为合并而挪动动作、回执或异常。
