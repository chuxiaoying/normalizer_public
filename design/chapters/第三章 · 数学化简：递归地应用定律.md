# 第三章 · 数学化简：递归地应用定律

两份模拟 JVM 坍缩成一份，原先分别放在两个栈或堆里的值，成了一个 `CASE WHEN`。这个值还会参与下一步运算，条件里可能套进新的条件。需要继续执行的状态少了，**复杂度却转移到了表达式里**。

数学化简的威力在于递归。一条定律只处理眼前一小块；小块变了，上一层才看得见原先不明显的关系：

```text
((a + 0) - (a × 1)) + b
  → (a - (a × 1)) + b       加零
  → (a - a) + b             乘一
  → 0 + b                   同值相减
  → b                       再用一次加零定律
```

第一步和最后一步用的是同一条定律，发生在不同层。没有哪条定律认识原来的整个式子。它们各自算一小步，合在一起，却把一串计算变成了一个输入。

## 哪些定律可以用？

**数学定律解释为什么能改；化简规则决定何时改、往哪改、改完少了什么。** 交换律保证 `b + a → a + b` 等值，却没说为什么一定要交换；「不等式两边同减」也允许减任何数，却没有告诉执行器减哪个数。把这些定律直接交给执行器，它既可能毫无进展，也可能来回改。真正登记为化简规则的，是有明确目标的用法。

例如，看到 `z + 2 < 5`，我们要的是 **把比较变成「原来的值，与一个常量边界相比」**。执行器匹配 `t + k < c`：`k` 和 `c` 都必须是已知整数常量，而 `t` 是要保留的表达式。匹配到的偏移 `k` 决定了两边减多少，算出 `c - k` 后直接得到 `t < (c-k)`，不把减法留在式子里。于是 `z + 2 < 5 → z < 3`；和另一条 `z >= 3` 放到一起时，马上就能做区间相交。找不到这样的偏移和边界，就不试减别的数。

下面每条规则都给出**可识别的触发形状、确定的改写和可检查的目标**。数值按精确整数理解，布尔值只有真和假；式中的值均已取得，不能为了让式子变小而跳过可能失败的求值、挪动写入或混用两条路径的事实。

### 普通代数：让常量集中，让多余运算消失

| 规则与触发形状 | 🟠 原式 | 🟢 改写后 | 化简目标与边界 |
| --- | --- | --- | --- |
| 加法链里有多项常量 | `2 + (x + 3)` | `x + 5` | 用交换律和结合律把同一加法链的常量收成一个；交换本身不是目标，不跨减法或其他运算 |
| 一个运算的操作数全是常量 | `2 + 3` | `5` | 直接算掉这一层；只折叠有定义的运算 |
| 加法的一项是零 | `x + 0` | `x` | 去掉一层加法 |
| 乘法的一项是一 | `x × 1` | `x` | 去掉一层乘法 |
| 加进去的项紧接着被减掉 | `(base + x) - x` | `base` | 消掉一对加减；两处必须是同一个值 |
| 减法两边是同一个值 | `x - x` | `0` | 消掉对该值的依赖；不能只凭两边源码长得一样 |
| 两个常量系数乘同一项 | `2 × x + 3 × x` | `5 × x` | 叠加系数，让 `x` 只出现一次 |
| 两项都含同一个因子 | `a × b + a × c` | `a × (b + c)` | 把两次乘法减为一次；不再把结果倒着展开 |

### 等式、方程与不等式：把条件改成能直接用的事实

| 规则与触发形状 | 🟠 原式 | 🟢 改写后 | 化简目标与边界 |
| --- | --- | --- | --- |
| 等式一侧是值加常量，另一侧也是常量 | `x + 2 == 5` | `x == 3` | 去掉偏移，右侧只剩求完的常量 |
| 已知一个变量等于常量，比较式用到了它 | 在 `y == 4` 的路径内，`y > 4` | `false` | 用已知值把比较折成真假；不做任意的变量互换 |
| 两条线性等式里某个变量系数恰好相反 | `x + y == 10 AND x - y == 2` | `x == 6 AND y == 4` | 选相加就能消掉的 `y`；保留另一条方程用于回代。解出的值必须能反推出原约束 |
| 整数乘固定系数等于常量 | `2 × x == 12`；`2 × x == 3` | `x == 6`；`false` | 消掉非零系数；除不尽就证明没有整数解 |
| 把常量偏移折入比较边界 | `z + 2 < 5`；`z - 2 <= 5` | `z < 3`；`z <= 7` | 去掉值一侧的常量偏移，把常量运算算完。原比较是严格还是非严格，保持不变 |
| 负的常量系数乘值，与可整除的常量比较 | `-2 × z < 4` | `z > -2` | 消掉系数并反转方向；符号未知不套这条，不能整除则另证整数边界 |
| 同一值的上下界卡在同一包含端点 | `u <= 10 AND u >= 10` | `u == 10` | 两次比较收成一个确定值 |
| 同一值的两个区间不相交 | `z < 3 AND z >= 3` | `false` | 证明整组条件不可能成立 |
| 并列比较中一项已经保证另一项 | `x == 6 AND x >= 6` | `x == 6` | 去掉冗余比较；如改成 `x > 6`，应判矛盾而不是当作冗余 |

### 布尔代数：去掉重复条件和无关输入

| 规则与触发形状 | 🟠 原式 | 🟢 改写后 | 化简目标与边界 |
| --- | --- | --- | --- |
| 两个择一条件共享同一项 | `(g AND p) OR (g AND NOT p)` | `g AND (p OR NOT p)` | `g` 只留一份，并露出下一步可用的互补项；不反向分配 |
| 同一布尔值和它的否定二选一 | `p OR NOT p` | `true` | 直接折成真；`p` 必须是已取得的二值布尔值 |
| 同一布尔值和它的否定须同时成立 | `p AND NOT p` | `false` | 直接折成假；不能把两次独立观察当同一个 `p` |
| 连接符旁有不改变结果的常量 | `g AND true`；`g OR false` | `g`；`g` | 去掉一层连接符 |
| 同一个条件重复出现 | `p AND p` | `p` | 去掉重复检查；两处必须引用同一个值 |
| 一个选项比另一个多加了限制 | `p OR (p AND q)` | `p` | 去掉已经被 `p` 覆盖的选项 |
| 否定「落在区间外」 | `NOT (x < 3 OR x > 7)` | `x >= 3 AND x <= 7` | 用德摩根律和比较取反，得到能直接求交的上下界；不无条件把所有否定往里推 |
| 同一个值被连续取反两次 | `NOT (NOT p)` | `p` | 去掉两层否定 |

### CASE：让选择只保留真正有差别的结果

| 规则与触发形状 | 🟠 原式 | 🟢 改写后 | 化简目标与边界 |
| --- | --- | --- | --- |
| 某个守卫已证明为假 | `CASE WHEN false THEN a ELSE b END` | `b` | 删掉不可达臂，不提前求值 `a` |
| 第一臂守卫已证明为真 | `CASE WHEN true THEN a WHEN q THEN b ELSE c END` | `a` | 首臂已决定结果，后续臂不再处理 |
| 完整的两臂返回同一个值 | `CASE WHEN p THEN a ELSE a END` | `a` | 去掉整层选择；守卫已取得，`a` 在两臂都确实可用 |
| 相邻两臂返回同一个值 | `CASE WHEN p THEN a WHEN q THEN a ELSE b END` | `CASE WHEN p OR q THEN a ELSE b END` | 少一条臂；必须保持先看 `p`、没命中才看 `q`，不能越过夹在中间的其他臂 |
| 外层事实已经决定内层守卫 | 在 `y == 4` 的臂里，`CASE WHEN y > 4 THEN a ELSE b END` | `b` | 去掉只在这条路径上无用的内层选择；不能把这个改写搬到外层 |

## 从递归到停止：一轮具体怎么走？

**先确认条件，再动表达式。** 看见 `x/x` 时，匹配只完成了一半。必须从字面量、类型或当前路径条件证明 `x != 0`，才能化成 1。证据不足就保留原式。一个分支里的事实不能拿到另一个分支用。

**先处理子式，再重试父节点。** 对普通运算，先走入操作数；某个子式一变，就重新检查它的父节点。对 `CASE`，先按顺序化简守卫：能证明为假的，直接丢掉该臂，不去算它的结果；仍可能命中的，带上「此前各臂都没命中、当前守卫成立」进入该臂。算完各臂，再回来问整条 `CASE` 是否还有必要存在。

**同一处有多个选择时，先用便宜且能减少工作量的定律。** 先折叠常量、去单位元、删已知不可达的分支；再尝试抵消、把常量偏移折入边界、提取公共条件等局部改写；只有确实需要联合条件才能继续时，才做区间交集或方程消元。这不是固定地先跑完一整类定律：消元产出的等式如果立刻让一个守卫变假，就先用这个新事实裁掉分支，再继续算。互不影响的两块可以按固定顺序处理，不必反复比较哪块先做更好。

**可以反复用同一条，不允许原地打转。** 能直接缩小结构的局部改写可以一直做，但不能把提取公因子和反向展开都无条件打开。消元这类可能暂时多写几项的工作，在一个确定范围的约束组内做，按更少的未解变量推进，不把解出的变量又展开回原方程。只有子式变化或新事实出现，才值得重新检查受它影响的位置。如果当前规则和事实都不能再推进，就停在这个结果；遇到计算预算上限也要停，但此时不能说已经化简到位。**这里的「最简」指这组定律在当前事实下已无可用的改写，不是保证在所有等价公式里找到全世界最短的一条。**

把这套顺序落到执行器里，重访的单位就是「**这个节点，在这组已知条件下**」。同一个 `y > 4` 在外面可能无法判断，到了已知 `y == 4` 的臂里就能化成假，不能共用前一次判断。节点改写后，只重新检查被改写的部分和受影响的上层；如果守卫变了，再检查受它约束的分支。同一处、同一前提下有多条同级定律可用，就按预先定好的顺序选第一条有进展的，避免演算随遍历碰巧改变。

## 一次完整演算

假设一次符号执行后，要计算下面这条规则。为便于逐步看清变化，用 `G`、`H` 等名字给子式做记号；它们只用于演算，最后的结果不会依赖这些名字。所有参数都是已知类型的值，`p`、`q` 为普通布尔值。

```text
G = (x + y <= 10 AND x + y >= 10) AND x - y == 2
H = (x >= 6 AND p) OR (x >= 6 AND NOT p)
J = z + 2 < 5 AND z >= 3

CASE
  WHEN G AND H THEN
    CASE
      WHEN y > 4 THEN base + 100
      ELSE ((base + (x + 0)) - x) + 0
    END
  WHEN J THEN base + 200
  ELSE
    CASE WHEN q THEN 0 + (base - base) ELSE 0 END
END
```

下表每次只动一个位置。没写到的部分保持上一行的状态。注意一条定律算完之后，表格下一步为什么有了原先没有的条件。

| 步 | 用在哪、哪条定律 | 🟠 原式 | 🟢 改写后 |
| --- | --- | --- | --- |
| 1 | 进入 `G`，先收紧和的上下界 | `(x + y <= 10 AND x + y >= 10) AND x - y == 2` | `G = (x+y == 10) AND (x-y == 2)` |
| 2 | 联立上一行的两个等式。相加得 `2x=12`；解出 `x=6` 后回代得 `y=4`，反向代入也成立 | `(x+y == 10) AND (x-y == 2)` | `G = (x == 6) AND (y == 4)` |
| 3 | 进入 `H`，用布尔分配律提出公共条件 | `(x >= 6 AND p) OR (x >= 6 AND NOT p)` | `H = (x >= 6) AND (p OR NOT p)` |
| 4 | 子式里的 `p` 和 `NOT p` 互补 | `(x >= 6) AND (p OR NOT p)` | `H = (x >= 6) AND true` |
| 5 | 返回 `H` 的外层，去掉 `AND true` | `(x >= 6) AND true` | `H = x >= 6` |
| 6 | 回到第一条 `WHEN`，`x == 6` 已经蕴含 `x >= 6` | `(x == 6 AND y == 4) AND x >= 6` | 第一条守卫是 `x == 6 AND y == 4` |
| 7 | 进入第一臂时已知 `y == 4`；用它判断内层比较 | `CASE WHEN y > 4 THEN base+100 ELSE ((base+(x+0))-x)+0 END` | 内层变成 `CASE WHEN false THEN base+100 ELSE ((base+(x+0))-x)+0 END` |
| 8 | 用 CASE 的不可达臂规则 | `CASE WHEN false THEN base+100 ELSE ((base+(x+0))-x)+0 END` | 第一臂只剩 `((base + (x + 0)) - x) + 0`，不用算 `base+100` |
| 9 | 进入最里面，用加零定律 | `((base + (x + 0)) - x) + 0` | `((base + x) - x) + 0` |
| 10 | 回到减法，用加减抵消 | `((base + x) - x) + 0` | `base + 0` |
| 11 | 回到最外层加法，再用加零定律 | `base + 0` | 第一臂的结果变成 `base` |
| 12 | 进入第二个守卫 `J`，匹配「值 + 常量 < 常量」，把偏移 2 折进边界 5，直接算出 3 | `z + 2 < 5 AND z >= 3` | `J = (z < 3) AND (z >= 3)` |
| 13 | 两个区间没有交集 | `(z < 3) AND (z >= 3)` | `J = false` |
| 14 | 回到外层 CASE，删不可达臂 | `WHEN false THEN base+200` | 整条 `WHEN J THEN base+200` 消失 |
| 15 | 进入默认臂里最深的减法，同一个值减自己 | `CASE WHEN q THEN 0 + (base - base) ELSE 0 END` | `CASE WHEN q THEN 0 + 0 ELSE 0 END` |
| 16 | 回到加法，折叠两个常量 | `CASE WHEN q THEN 0 + 0 ELSE 0 END` | `CASE WHEN q THEN 0 ELSE 0 END` |
| 17 | 回到默认臂的 CASE，两臂相同且 `q` 已取得 | `CASE WHEN q THEN 0 ELSE 0 END` | 外层的 `ELSE` 只剩 `0` |

最后再看外层，两个结果并不总一样，第一条守卫也不是恒真或恒假。这个判断是真正留下来的业务区别：

```text
CASE
  WHEN x == 6 AND y == 4 THEN base
  ELSE 0
END
```

当 `base = 9`、`x = 6`、`y = 4` 时，结果是 9；只满足和、不满足差，例如 `x = 7`、`y = 3`，结果是 0。如果之后还有一条语句给出新事实 `base = 0`，这条式子还能接着算：先替换第一臂的值，发现两臂都是 0，再消去最后一个 CASE。没有这个新事实时，就保留它。

**数学化简就发生在执行中。** 下一步拿到的是已经按当前事实算过的值。程序绕了多少弯、曾经分过多少支，不决定最终规则需要多长。只要那些步骤反复在算同一件事，局部定律递归应用，就能一层一层把它们消掉。
