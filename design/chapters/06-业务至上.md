# 业务至上

**先问 Normalizer 吃不吃得下，再问值不值得为它建模。** 性能优化、容量预留、埋点和线程调度都可能不是业务规则，但这并不等于 AI 可以先删一遍。凡是已经符合[纯净工程规范](04-AI救赎.md#交给-normalizer-的是什么)的代码，分析时一律按程序逻辑原样交给内核。即使它看着冗余，或写它本来只是为了提速，也由内核执行、化简。AI 不负责提前折叠分支、消去运算或算出答案。

只有两件事同时成立，本章才讨论省略：**这部分不符合纯净工程规范，而且它只服务于实现，不决定业务行为。** 比如未获准的库类型、缺少规定语义的宿主调用，或依赖运行时调度的机制，确实会挡住交付。此时才值得问：去掉这层以后，业务值、可见状态、对外动作、失败或先后关系会不会变？能确认不变，就把实现负担去掉，把余下的计算交给内核；会变，就等价表达那部分行为；说不清，就报告缺口，不靠删代码把工程变「纯」。

这里的「按业务逻辑对待」说的是**谁来执行**，不是说每一行最终都必须出现在结果里。下面两个分支都符合输入规范，就原样交付。两边是不是一样、能不能合并，由内核决定。普通 Java 写出来的缓存判断、局部拷贝或清理也一样，不能仅凭它的用途就绕开这条规则。

```java
class Sum {
    static int run(boolean reverse, int a, int b) {
        if (reverse) return b + a;
        return a + b;
    }
}
```

## 埋点和日志：省掉内核不需要接管的宿主观测

原工程直接调用宿主的 `System.nanoTime()` 和 JDK 日志类。两者都不能直接作为规范操作交付。本例确认两次时间读取只用于打调试日志，日志也不是审计记录，业务不依赖日志是否写出或写出失败。**删的是计时和日志，原来的业务判断一行没动。**

```diff
diff --git a/Check.java b/Check.java
--- a/Check.java
+++ b/Check.java
@@ -1,14 +1,10 @@
-import java.util.logging.Logger;
-
 class Check {
     static boolean run(int value, int minimum) {
-        long started = System.nanoTime();
         boolean accepted = accepts(value, minimum);
-        Logger.getLogger("perf").fine("elapsed=" + (System.nanoTime() - started));
         return accepted;
     }

     static boolean accepts(int value, int minimum) {
         return value >= minimum;
     }
 }
```

读时钟若决定是否超期，就不能删，必须保留那次实际读取和后面的判断；调试实参若会更新状态，也要留下那次更新。反过来，如果耗时已经通过规范的环境操作读取，记录逻辑也已能由内核执行，AI 不再额外做一次「清埋点」。

## 线程调度：保留两个计算，不接管线程池

原代码依赖 `CompletableFuture` 的库类型和执行调度，不能直接作为纯净工程交付。这里两个函数独立、没有对外动作，分析合同也不观察提交失败、调度或等待故障。改写只去掉并行安排，两项计算和比较仍旧由内核执行。

```diff
diff --git a/Compare.java b/Compare.java
--- a/Compare.java
+++ b/Compare.java
@@ -1,12 +1,10 @@
-import java.util.concurrent.CompletableFuture;
-
 class Compare {
     static boolean run(int input, int limit) {
-        var value = CompletableFuture.supplyAsync(() -> adjusted(input));
-        var threshold = CompletableFuture.supplyAsync(() -> threshold(limit));
-        return value.join() >= threshold.join();
+        long value = adjusted(input);
+        long threshold = threshold(limit);
+        return value >= threshold;
     }

     static long adjusted(int x) { return (long) x * 2; }
     static long threshold(int y) { return (long) y + 3; }
 }
```

如果先完成的一方决定答案，或等满 50 毫秒就回退，等待就参与了业务。可以不模拟工作线程，却必须保留超时和选择规则。共享状态若要求原子更新，也不能拆成任意交错的读写。

## 容量和性能：别把实现上限认成业务上限

这里不直接交付 JDK 的 `StringBuilder` 实现；文本本身可以用规范的拼接表达。这份改写有两件事：**把两次追加及分隔符按原顺序写成文本拼接**，让内核执行；**不带入 `ensureCapacity(128)`**，因为它只预留内存，不决定输出。长过 128 仍继续拼，且本例不把内存分配失败纳入业务合同。

```diff
diff --git a/Ticket.java b/Ticket.java
--- a/Ticket.java
+++ b/Ticket.java
@@ -1,8 +1,5 @@
 class Ticket {
     static String run(String series, String id) {
-        StringBuilder s = new StringBuilder();
-        s.ensureCapacity(128);
-        s.append(series).append(':').append(id);
-        return s.toString();
+        return series + ":" + id;
     }
 }
```

「超过 128 就拒绝」不是预分配；队列满了会丢消息也不是扩容细节，都要保留实际后果。缓存同样不能见到就拔掉：能执行的命中分支原样交付；若缓存库本身不合规，先查命中是否改变取值、时点或请求次数。不能只凭「它是用来提速的」就替内核把两条路径合成一条。

## 运行维护：主动请求 GC 不参与业务判断

`System.gc()` 是对宿主运行时的请求，不属于纯净工程里的规范操作。这里原程序不会观察弱引用何时清除、清理回调是否运行，或内存耗尽；也没有业务依赖这次请求。去掉它，及格与否仍由原来的比较决定，不需要 AI 归约任何条件。

```diff
diff --git a/Grade.java b/Grade.java
--- a/Grade.java
+++ b/Grade.java
@@ -1,7 +1,6 @@
 class Grade {
     static boolean run(int score, int passMark) {
         boolean passed = score >= passMark;
-        System.gc();
         return passed;
     }
 }
```

如果程序依赖弱引用被清除后的分支，或者清理会释放影响后续执行的资源，就不能因为操作看起来像「运维」而删掉。先确认影响，才有资格省略。

## 取数性能：建议每批取 256 行，不是只读 256 行

[`setFetchSize(256)` 是给 JDBC 驱动的批量取数提示](https://docs.oracle.com/en/java/javase/21/docs/api/java.sql/java/sql/Statement.html#setFetchSize(int))，不是结果的行数上限。本例已确认：规范源码的 `work_item` 绑定到原连接所读的数据源和快照。表中 `units` 是非空整数，成功路径读取全部匹配行；分析范围不观察分批时点、游标和关闭动作，也不覆盖 JDBC 失败。纯净工程保留在原位置查询和对取得的行累加这两步。查询与循环如何交付见[《关系代数》](05-关系代数.md)；这里省掉的只有批次提示，不把它改成关系条件，也不提前计算总数。

```diff
diff --git a/Total.java b/Total.java
--- a/Total.java
+++ b/Total.java
@@ -1,19 +1,17 @@
-import java.sql.Connection;
-import java.sql.SQLException;
-
 class Total {
-    static long run(Connection db, int accountId) throws SQLException {
-        try (var query = db.prepareStatement(
-                "SELECT units FROM work_item WHERE account_id = ?")) {
-            query.setInt(1, accountId);
-            query.setFetchSize(256);
-            try (var rows = query.executeQuery()) {
-                long total = 0;
-                while (rows.next()) {
-                    total += rows.getInt("units");
-                }
-                return total;
-            }
-        }
+    static long run(int accountId) {
+        WorkUnits[] rows;
+        /* @normalizer-ir
+           rows = from work_item as w where w.account_id == accountId yield { units: w.units }
+        */
+        long total;
+        /* @normalizer-ir
+           total = sum from rows as r yield r.units
+        */
+        return total;
     }
 }
+
+class WorkUnits {
+    int units;
+}
```

如果该账户有 300 行且每行都是 1，总数仍是 300，不是 256。真的限制最多查 256 行时，必须保留限制；若分批读取会改变快照或错误处理，那个变化也不能省。

## Normalizer 内核的实现取舍

前面讲的是 **AI 什么时候可以拿掉不合规的实现机制**。这里讲的是另一层：**合规源码原样进来以后，内核用什么样的值和运算表达业务。** 原生类型和数值规则由 Normalizer 统一定义，不能由 AI 每遇到一个例子临时决定。

### 数学上的数，不是某台机器的寄存器

Java 的普通 `x + 1` 合规，AI 原样交付。要不要让这条加法默认继承 32 位回卷，是 **Normalizer 定义业务数值语义**时做的取舍，不是 AI 预处理哪一行的取舍。按普通业务数值合同，这行就是加一；不能因宿主字宽凭空给业务添一条回卷分支。例如协议规定序列号到上限就回卷，那条回卷规则就必须保留。业务合同下的归一化不等于承诺在所有宿主极值上逐位等价。

**IR 的 `number` 没有固定字宽、数值范围上限或精度上限。** 任意给定的有限整数和有限十进制都要能精确表示；`1/3` 可以保留为精确比例，不必展开为无限小数。没有固定上限不等于把「无穷」当一个普通数，也不保证每次分析都能用有限资源算完。资源不足应明示，而不是悄悄截断或舍入。

**默认不继承二进制浮点的尾差。** 同一条精确十进制业务规则，`0.1 + 0.2 = 0.3` 不该因 Java 或 TypeScript 的宿主数值容器变成另一个分支。外部已经交来的近似数，不凭空猜成某个精确原值。舍入只发生在业务合同规定的位置；例如两笔 0.005 元按两位 HALF_UP 各自舍入再加是 0.02 元，先加再舍入是 0.01 元。截断、除零、回卷和业务观察到的 IEEE 浮点行为（如 NaN、正负零或指定舍入）同样要保留；例如 Java 整数除法用于分组时，`5 / 2` 仍取 2。

### IR 原生类型的定义

不是宿主有多少种类型，IR 就要有多少种。反过来，也不能为了统一就把所有东西都塞进 `number` 或 `text`。**当两种值允许的运算不同，且这个区别能改变业务结果，IR 才需要区分。**

| IR 原生类型 | 保留的业务区别 |
| --- | --- |
| `boolean` | 真与假。不能把 0、空字符串或空值当成同一个假。 |
| `number` | 精确数量、比例、小数。没有宿主式的默认字宽和舍入；有业务意义的边界另行表达。 |
| `text` | 文本。匹配与比较按明确规则，不按机器存字符的布局来算。 |
| `date` | 日历上的一天。账期按哪一天划分，不是给时间戳加固定 24 小时。 |
| `instant` | 时间线上的一个时刻。时刻相同，在不同地区可能属于不同日期；转日期需要明确时区。 |
| `money` | 金额和币种。10 元和 10 美元不能直接相加，换算规则得明写。 |
| `bytes` | 有顺序的字节。对端若检查精确长度或签名，文本相同不代表字节相同。 |

空值由对应类型是否允许来描述，不等于 0、空串或没有这个键。记录、序列、Map 和关系是组合结构，不再为每种宿主容器增加一个原生类型。

归根结底，**不合规才需要 AI 动手，业务上的影响决定它能动到哪里。** 合规但可以化简的代码，始终留给内核。不能等价表达又不能安全省略的操作，报告 `Panic: not-support`，不交出猜测的结果。

扩展语义见[设计首页的二级设计目录](../README.md#二级设计)。
