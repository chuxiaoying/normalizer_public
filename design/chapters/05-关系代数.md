# 关系代数

算一个账户的应付总额：SQL 先取出未结账单，Java 再从这些账单里挑正金额、逐笔累加。如果把查询和循环当成两个不透明的调用，归一化只能说「先取一批数据，再跑一段程序」。但这两段做的是同一件事的两半：**先挑哪些账单，再算这些账单的金额。**

关系代数让这两半用同一套数学表达。筛选就是留下符合条件的行，投影就是挑出字段或为每行计算一个值，连接就是按条件配对，聚合就是把多行算成一个结果。写在 SQL 里，还是写成 Java 的循环或集合调用，不决定它能不能参与化简。是否要改源码，先看[这一步能否原样执行](04-AI救赎.md#ai-05-预处理停在哪儿)。本章讲需要关系表达时，怎样保住原程序的来源、次序和业务效果。

## 一、把扩展语义注入源码，不另造一份程序

给 SQL 和循环用同一种关系表达，不意味着要给 Java 或 TypeScript 新加关键字。**宿主语言照常写，扩展语义走它们已有的注解和注释。** 这份分析源码既能保留类、函数、声明和控制流，又能让 Normalizer 在原位读到宿主语法没表达出来的业务操作。

| 写在哪里 | 交付什么 |
| --- | --- |
| 声明上的注解 | 标明对象的身份。例如 Java 的 `@N.EntryState` / TypeScript 的 `@N entryState` 标的是已有状态；Java 的 `@N.External` / TypeScript 的 `@N external` 标的是真实外部端口。TypeScript 的 `@N componentProp` 标明提取的函数对应哪个组件属性。不因为加了标记就执行一次读写或调用。 |
| 原语句位置的 `/* @normalizer-ir … */` | 注入一条可执行的扩展指令。块里写的是受约束的伪代码：比如 `total += sum from rows as row yield row.amount`。块外仍是 Java 或 TypeScript；块内不是给人看的随笔，是 Normalizer 要解析的语法。 |

**「无伤」是指不破坏宿主源码的语法、结构和原业务的观察行为，不是说改写后的分析源码还能当生产源码替换上线。** 比如用指令给局部变量赋值，普通 JVM 或 JS 运行时并不会执行注释；运行时真的要执行的是未改写的生产源码。在分析副本里，删去被替代的那段原语句，不能原语句和注入指令两头都执行，也不能补一个默认值让宿主编译器看起来满意。

这样，原程序走到哪一步，关系操作就跟到哪一步。语句绑定和不合规交付的具体处理见[扩展句和宿主执行](#ra-02-扩展句和宿主执行)。

## 二、把 SQL 和循环放进同一个算式

以下例子只读一次账单表。金额是非空的精确整数，逐行读取没有副作用，数据库故障不在这个例子的观察范围。原程序按账户和 `OPEN` 状态取账单，再按正金额筛选；每笔金额还先加上 `extra`，又减掉同一个 `extra`。

### 先从循环里找出四个动作

这个循环没有写出 `filter` 或 `sum`。要读的是变量怎样流动，而不是关键字长什么样：

| 循环里看到什么 | 转成什么 | 为什么 |
| --- | --- | --- |
| `for (BillRow row : …)` | `from rows as row` | 每轮处理原查询取到的一行，不重复查询。 |
| `if (row.amount > 0)` | `where row.amount > 0` | 不满足条件时什么也不做，累加器保持原值。 |
| `(row.amount + extra) - extra` | `yield (row.amount + extra) - extra` | 这是当行的贡献，只看当前行和固定输入，不读前几轮的结果。 |
| `int total = 0` 和 `total += …` | 从 0 开始求和 | `total` 只用于累加，既不决定下一项选不选，也不决定什么时候停。 |

拿一批实际数据走一遍：SQL 返回四笔未结账单，金额依次是 `[5, -2, 5, 0]`；`extra = 3`。前后两笔 5 是不同账单。

| 当前金额 | Java 循环结束这一轮后的 `total` | 关系式对这行做什么 |
| --- | ---: | --- |
| 第一笔 5 | 5 | 保留，产出 `(5 + 3) - 3 = 5` |
| -2 | 5 | 筛掉，没有贡献 |
| 第二笔 5 | 10 | 保留，再产出一个 5 |
| 0 | 10 | 筛掉，没有贡献 |

循环把「筛选、算一项、累加」揉在每一轮里；关系式把它们分开写，计算的还是同一批数据。若条件改成 `total < 6 && row.amount > 0`，对 `[5, 5, 5]` 原程序累加前两笔得 10，逐行独立筛选却会得 15。能用已定义的等价数学运算才交付；不能用逐轮更新伪装成聚合。

### 同一段集合运算，Java 和前端怎么交付

还是这批已经取到的 `rows`。把循环换成 Java Stream，或者把同样的逻辑写成 JavaScript 数组链：

**Java Stream → 局部关系式。** 这里列表只被遍历，元素与次序都由数组保留。

```diff
--- a/Preview.java
+++ b/Preview.java
@@ -1,6 +1,9 @@

+int total(BillRow[] rows, int extra) {
-    return rows.stream()
-        .filter(row -> row.amount > 0)
-        .mapToInt(row -> (row.amount + extra) - extra)
-        .sum();

+    /* @normalizer-ir
+       result = sum from rows as row
+           where row.amount > 0
+           yield (row.amount + extra) - extra
+    */
+    return result;
 }
```

JavaScript 数组链在同一批已取得的密集值上做相同的纯筛选、投影和求和，可以交成同一关系式。Java Stream 可逐项贯穿各阶段，数组链会先完成整批 filter。回调若会发消息，两种顺序可能产生不同动作。各 CLI 入口的接入范围见[工具手册](../../usage/cli.md)。

把同一批数据代到两条链里，可以直接看见每一步的中间结果：

| 阶段 | 这组账单的结果 |
| --- | --- |
| 输入 `rows` | `[5, -2, 5, 0]`（这里只列金额） |
| `filter` | 两笔金额为 5 的账单，还是两行 |
| `mapToInt` / `map` | `[(5 + 3) - 3, (5 + 3) - 3] = [5, 5]` |
| `sum` / 从 0 开始 `reduce` | `0 + 5 + 5 = 10` |

已实现这类交接的入口可以写成循环示例里的 `sum from rows as row where … yield …`。其中 `extra` 还在，`rows` 也还是原来的来源；等到工程化简时才消掉 `extra`、把筛选和 SQL 的条件合并。如果同样的函数接收的是前端已经拿到的数组，而不是数据库查询结果，集合操作照样能化简，但不能凭空补上一张表。

两个语言可以使用相同的关系表示，因为这个例子的两条路径只对同一批业务值做纯计算。对照有副作用的回调，见[逐项运算与等价交付](#ra-07-逐项运算与等价交付)。

## 三、逐层化简：先算行内，再合并行集

下面用接近 SQL 的记法展示演算，不是在重写应用要发给数据库的 SQL。记 `rows` 为已取得的查询结果；原循环从 0 开始，所以没有命中行时也必须得到 0。

| 步骤 | 改写前 | 改写后 | 为什么可以改 |
| --- | --- | --- | --- |
| 1. 化简行内表达式 | `(row.amount + extra) - extra` | `row.amount` | 是同一个不可变入参，两处都只读；在本例的精确整数上加减抵消。 |
| 2. 穿过字段投影 | `row.amount > 0` | `b.amount > 0` | `row.amount` 就是这批行的 `b.amount`，取字段没有副作用。 |
| 3. 合并两层筛选 | 先留本账户的未结账单，再留正金额 | 留下同时满足三项条件的账单 | 两层筛的是同一次查询的行，没有分页、去重或另一次读表隔在中间。 |
| 4. 保留空集结果 | 从 Java 初值 0 开始累加 | `COALESCE(SUM(...), 0)` | 没有匹配行时 SQL 式求和为空，不能丢掉原程序的 0。 |

得到的业务结果是：

```sql
SELECT COALESCE(SUM(b.amount), 0)
FROM bill AS b
WHERE b.account_id = :accountId
  AND b.status = 'OPEN'
  AND b.amount > 0
```

现在可以直接从结果看出：**金额取决于账户和账单，跟 `extra` 无关。** 这不是删掉入口参数，而是证明它不影响这个结果。如果数据库里同一账户有两笔正好都是 5 元的未结账单，两笔都参与，结果是 10，不是 5；再加一笔已结账单或一笔负金额账单，仍是 10。一个符合条件的账单都没有，结果是 0。

如果另一份实现一开始就把正金额筛选写进 SQL，或者先把列表 `filter` 再 `sum`，在同样的来源、空集和重复行约定下，归一化可以把它们化到同一个结果。关系代数不只是把流程换个写法，它让**不同实现里的同一个业务规则能被算成同一个表达式**。

#### 第零项何时就是首项

同一批有序数据的第零项和首项可以表达同一个正常值。取得时点和缺省或失败仍要单独核对，见[第零项与首项](#ra-01-第零项与首项)。

### 区间求和：直接说清哪些数参与

```diff
 class RangeSum {
     static int total(int hi) {
         int total = 0;
-        for (int i = 0; i < hi; i++) {
-            if (i < 1) continue;
-            if (i > 300) break;
-            total += i;
-        }
+        /* @normalizer-ir
+           total = sum from [1, min(hi, 301))
+        */

```

下界 1 来自跳过条件；上界不含 301，且不能超过原来的 `hi`。`hi = 1` 得 0，`hi = 4` 得 6，`hi >= 301` 得 45150。AI 确定参与项，内核决定如何化简求和。普通数值序列上的 `acc += contribution` 同样交成初值加求和，不交 `acc` 的逐轮更新。只有要改每项贡献时才写别名和投影，如 `sum from [1, hi) as i yield i * i`。

## 五、可以化简计算，不能搬动真实操作

SQL 写入也能交付目标表、命中条件和新字段值。以下例子约定单条更新原子提交，失败抛出 `DatabaseWriteError`；mapper 只用于装配这个已知数据库操作，不是独立的业务输入。

把筛选条件化简，不等于能删掉这次写入。比如有两笔未结账单，结果是**修改两笔**并返回 2，而不只是算出 2；发生写入失败时也不能照常返回 2。

读取也是一样：能合并的是同一批账单上的计算。归一化消掉的是写法的差别，不是程序实际做过的事，见[取得后的化简不搬动读写](#ra-08-取得后的化简不搬动读写)。

## 六、扩展语义语法表

从一行实际输入读语法：

```java
/* @normalizer-ir total += sum from rows as r where r.amount > 0 yield r.amount */
```

`total +=` 在原位置读取已初始化的累计值；`from rows` 遍历已取得的行；`as r` 引入本条指令的行别名；`where` 选择参与项；`yield` 给出每项贡献。若把 rows 换成物理表，取数来源和时点也跟着变。

| 要表达的事 | 语法入口 | 详细合同 |
| --- | --- | --- |
| 标出状态、端口、可空性、外部失败或组件属性 | Java 注解、TypeScript 声明注释 | [声明标记与赋值](#声明标记与语句边界) |
| 对表或已取得的序列计算 | 投影、求和、计数、首项、分组、连接、并集去重、任选 | [关系、集合与循环](#关系集合与循环) |
| 在有限整数域上求值 | 区间计数、区间求和、按位置选择首个匹配 | [区间与位置](#区间与位置) |
| 对局部值计算 | 文本键映射、精确小数复制与舍入 | [其他局部扩展](#其他局部扩展) |

每条可执行指令写在它取代的语句位置，一块 `/* @normalizer-ir … */` 只放一条。各表里的小写示例是分析副本的输入；最终值如何定形见[第八章](08-统一定形.md)。

## 规则区

### RA-01 第零项与首项

**规则：**

先核对双方选的是**同一批已经取得的有序值**，包括过滤、投影、元素身份和存在性。位置从零开始，且位置确定为零时，第零项与首项观察采用同一种结构。不按来源语言、集合内部表示或原来的写法另设形状。不能确定顺序、位置或值来源时，不作这个归并。

再分别核对三种结果：**空集合、首项存在但为 null、首项存在且非 null**。有首项时，保留原值，不能擅自跳过 null；无首项时，是否采用缺省、返回空值还是抛出异常，取决于原合同。只有完整合同一致，才能说整个观察等价。若只在正常完成域等价，也只统一该域中的取值结构；不同的异常、缺省及其发生条件仍分别保留。

还要核对取得时点。先遍历完整集合再取零位，和找到第一项就停止，可能有不同的读取、调用或失败。即使最终值相同，也不能用首项结构掩盖这些差别。判断等价的条件在本节，统一后如何验收见[统一定形的代表选择](08-统一定形.md#选代表不替代等价证明)。

**示例：**

同一已取得序列 `[7, 2]` 的下标 0 和首项都取 7；若源序列为空，越界异常和返回缺省值仍是不同完成。

空集合没有首项；`[null]` 有一项且值为 null，不能拿缺省值覆盖它。若另一个版本先扫全表，后续某行可能失败，即使两种写法成功时都返回 7，也不能合并完整 PERS。

例如一条完整扫描先取得全部工单，后面的空工单可能使投影失败；结果公式中的 FIRST 不把失败挪到取第零项以后。若同一行绑定的过滤已证明必命中投影 CASE 的一臂，可在 FIRST 内改用该臂，但保留过滤、投影身份和空集处理。

### RA-02 扩展句和宿主执行

**规则：**

扩展指令跟随原语句位置、分支与绑定；语法识别不等于所有入口、所有操作数组合都可执行。表中名称均是同一作用域内实际绑定的占位。

解析要保留原生绑定及指令位置；类型、列、行别名或完成合同对不上时拒绝分析，不把正式指令静默当注释。

**示例：**

若指令只在真支为 `rows` 赋值，假支直接读取 `rows` 的工程在校验时被拒绝，不生成 PERS。贴一条普通注释不能赋值；补默认值即使能过类型检查，也不是合法改写，因为它给假支增加了原来没有的结果。

### 声明标记与语句边界

**规则：**

声明标记只建立身份与类型合同；扩展语句与原语句共享作用域和求值边界。

| 写法 | 语义和限制 |
| --- | --- |
| Java `@N.EntryState`、`@N.External`、`@N.Nullable` | 分别标明状态根、真实端口和可空性。Java 标记不带参数；端口的参数、返回和异常由方法签名声明。 |
| TypeScript `/** @N entryState */`、`/** @N componentProp Component#instance.prop */`、`/** @N external */` | 分别绑定状态、原模板属性入口和真实端口。声明只建立身份，不替代实际调用或读写。属性入口仍须[同步、无参](04-AI救赎.md#ai-10-组件属性投影必须同步无参)。 |
| TypeScript 外部接口方法上的 `/** @N rejects ErrorType */` | 声明外部失败类型；参数和成功返回仍用原生 TypeScript 类型。没标记不建立外部失败路径，见[外部异常声明](04-AI救赎.md#ai-09-外部异常须显式声明)。 |
| `/* @normalizer-ir target = operation */` | 一块一条指令，放在语句之间。普通目标在同一作用域声明，并在首次读取前由指令初始化。 |
| `/* @normalizer-ir target += operation */` | 在原位置读已经初始化的目标，再加入本次结果。可累加的形式见下表。例如 `total += sum from rows as r yield r.amount`、`n += count from [lo, hi)`；`first` 取得的是选中值，只能用 `=`。 |

**示例：**

`@N.EntryState` 标出现有余额，不会读取或重写余额；`total += sum from rows as r yield r.amount` 先读已初始化的 total。

### 关系、集合与循环

**规则：**

以当前表的各指令合同说明投影、筛选、聚合、首项、连接与任选。该表是关系指令的准入清单；未列出的运算或输入组合不从相似语法类推。指令没有跨项可变绑定、任意回调或退出命令。

表中 `source`、`row` 等代表实际绑定的名字。`子句` 代指该操作允许的行内筛选、绑定或排序，没有时直接接后面的投影。`[可选项]` 表示该段可省略；整数区间 `[lo, hi)` 和切片 `values[k:]` 的方括号是输入字符。

**行来源、筛选与投影。** 物理表和已取得的行都能作为来源，只有前者在执行到该处时取得表快照。行别名在本条指令内生效。例如先按账户筛选，再 `let net = r.amount - r.waived`，后面的 `where net > 0` 才能读到 net。这里的 let 绑定当前行，第八章的 LET 绑定一个输出值内可共享的子式。

| 指令主体 | 读法与边界 |
| --- | --- |
| `dst = from source as row 子句 yield { field: expr, … }` | 读表或已取得的行关系，按指定字段构成结果行。 |
| `dst = from records as r yield r.member.field` | 按原序完整读取记录数组，结果为整数数组。中间字段是记录，末字段是整数；此形式没有筛选、绑定或排序子句。 |
| `n = sum from source as row 子句 yield expr`；也可 `+=` | 求和，空集贡献 0。二维整数数组可再嵌一层求和，例如 `sum from groups as group yield sum from group as value yield value`。内层遍历外层当前项，各自绑定别名。 |
| `out = first from rows as row 子句 yield expr else fallback` | 有序首项；记录可 `yield row else null`，标量缺省须满足类型合同。 |
| `out = first from values[k:] else fallback`；可省略 `[k:]` | 在业务整数数组上按位置选；`k` 是非负整数字面量，省略时为 0，没有该项才用缺省。 |
| `n = count [distinct] from source as row 子句 [yield expr]` | 行关系省略投影时数行；写出 `yield` 时数非 NULL 的标量值（整数、文本或布尔），加 `distinct` 后按该值去重。在整数序列上省略投影即取元素自身；记录行不能省略投影再加 `distinct`。 |

两个容易混淆的例子：

- `ids = from rows as r yield r.ticket.id` 会读完整批记录。第二张票是 null，即使下一行只取 `ids[0]`，也会先在投影中失败。把投影改成 `yield r.ticket.id + 1` 就超出了这条整批取字段指令。[完整取号种子](../examples/topics/collections/java-eager-first.md)
- 三行的备注依次是 `null, "A", "A"`。数行得 3，投影备注后计数得 2，再加 `distinct` 得 1。若原程序要求把 null 也当作一种备注，直接写 `count distinct from rows as r yield r.memo` 会漏算。[可空列计数种子](../examples/compositions/relational-data-and-collections/composition-relation-distinct-aggregate.md)

**行内子句和标量怎么读。** 下列记号用于读表。引号里的内容按字面写；问号表示可省，星号表示可重复，竖线表示选择。标量是对当前项求出的值；用于筛选时须为谓词，用作排序键时须能按该键的合同排序。

```text
子句     ::= (筛选 | 绑定 | 排序)*
筛选     ::= "where" 谓词 ("and" 谓词)*
绑定     ::= "let" 名字 "=" 标量
排序     ::= "order by" 键 ("," 键)*
记录投影 ::= "{" 字段 ":" 标量 ("," 字段 ":" 标量)* "}"
标量     ::= 加减式 | 加减式 比较符 加减式 | 列路径 "is" "not"? "null"
加减式   ::= 乘积 (("+" | "-") 乘积)*
乘积     ::= 原子 ("*" 原子)*
比较符   ::= "==" | "!=" | "<" | "<=" | ">" | ">="
```

普通行内原子包括已绑定的名字或字段路径、整数字面量、双引号文本、`true`、`false` 或括号内的标量。`is [not] null` 也可写大写关键字；文本转义只认双引号和反斜杠。区间界限及索引另有[专用形式](#区间与位置)。`where A and B` 要逐项保留 SQL 真值；通用 `OR`、任意函数调用和排序方向子句均未开放。例：`where r.memo IS NULL` 检查已绑定列，`order by r.priority, r.id` 以第二个键打破第一个键的平局。

**跨组、跨来源与任选。** 两张表配出四对，连接计数交付数字 4。要返回配对数组的程序还会观察成员与顺序，不能交成一次计数。

| 指令主体 | 读法与边界 |
| --- | --- |
| `n = count groups from source as row by key [, key …]` | 数分组键元组形成的组。当前要求未筛选的已声明表及明确列。 |
| `n = count from left as a join right as b on predicate [where predicate [and …]]` | 已绑定表关系的内连接计数，不是任意 JOIN 或配对列表投影。 |
| `n = count distinct union left.field, right.field [, …]` | 至少两支；先投影各支的列，再按并集去重计数，不是通用并集语法。 |
| `out = choose from members else fallback` | 允许从候选任选，空集用缺省；每个源码位置的选择独立。不能用它代替 `first`。 |

#### 区间与位置

| 指令主体 | 读法与边界 |
| --- | --- |
| `n = count from [lo, hi)`；也可 `+=` | 数区间内的整数；兼容省略投影的 `as i`，未引用的别名不进入 IR。 |
| `n = sum from [lo, hi)`；也可 `+=` | 直接加区间内的整数；空区间得 0。 |
| `n = sum from [lo, hi) as i [where predicate [and …]] yield expr` | 对命中整数求投影之和；若没有过滤且投影是绑定的 `i` 本身，与直接求和共用同一 IR。 |
| `n = count from [lo, hi) as i where predicate [and …]` | 数命中的位置；不因同值去重。 |
| `out = first from [lo, hi) as i [where predicate [and …]] yield expr else fallback` | 按整数升序取第一个命中项的投影；没有命中才使用缺省值。 |

**界限与索引。** `[lo, hi)` 的两端是进入关系作用域之前已经闭合的整数式，可用已绑定整数、整数常量、`+`、`-`、`*`、`min(a, b)`、`max(a, b)`、`length(sequence)` 与括号。上下界各取一次；`hi <= lo` 时为空；不截成机器位宽，也不按运行预算缩小区间。索引投影写 `sequence[index]`；对密集整数序列取整数，对密集记录序列可用 `sequence[index].field` 取已声明的非空整数或布尔字段。区间 `first` 的投影和缺省都是整数。序列必须已取得且位置稳定；在当前路径和整个索引域内，必须能证明 `0 <= index < length(sequence)`，解引用字段还要证明对象可访问。密集序列的索引域与 SQL 无序行集不是同一种来源。只有绑定后才能读别名，外层界限和缺省不捕获它；同名局部变量不得冒充序列位置。比较和投影不得引入未建模的求值或失败。

**区间结果的定形。** 区间来源的两个有序子槽是下界、上界；索引取值的子槽是序列来源、索引。区间别名按词法槽位识别，不使用源码拼写作身份。空计数及空求和统一为 0；直接求和与恒等投影共用规范节点。如果符号结果保留区间来源，使用 `indices(hi)` 表示下界为 0 的索引区间，否则使用 `range(lo, hi)`；两者都不承诺实际枚举。对无过滤的整系数二次及以下多项式投影，可以按区间项数、一次和、二次和的恒等式化简；其他已准入的投影保留精确聚合，不用循环展开上限改变结论。关系表达继续使用同一套 `SUM`、`COUNT`、`FIRST` 及[统一定形](08-统一定形.md#cf-02-共享结构与顺序)，不得保留循环关键字、未用的别名或源码阶段的指令拼写。

**示例。** 对序列 `[7, 2, 0, 9]`，先找停止位置 2，再只在 `[0, 2)` 找大于 7 的值，结果是缺省。把上界改成 4 就会选到 9。[完整代码](#有序选择停止信号限定搜索范围)

### 其他局部扩展

**规则：**

查键与舍入使用各自明确的操作与参数，不共享任意兜底规则。

| 指令主体 | 读法与边界 |
| --- | --- |
| `m = value.map_empty(text, text?)`；`m = value.map_put(m, "key", value)`；`x = value.map_get_or(m, "key", fallback)` | 当前是局部映射、文本字面量键、可空文本值。写入保持同一绑定；缺省取决于键是否存在。 |
| `out = input`；`out = round(value, scale, HALF_UP)` 或 `HALF_EVEN` | 精确小数载体内的复制与舍入。值可为已绑定精确值、小数字面量或精确乘积；位数用非负整数字面量，舍入模式不得靠猜。 |

**示例：**

同一个 `value.map_get_or(m, "main", fallback)`，当 m 含有 `"main": null` 时返回 null；m 是空映射时才返回 fallback。

若调用前已经求出了 fallback，则有 `main` 的路径虽然不返回它，也不能取消那次求值。

### 数据库写入

**规则：**

在原位置保留实际写入，记录受影响的行数、原子性和已有根据的失败合同。

| 指令主体 | 读法 |
| --- | --- |
| `n = insert into table values { col: value, … } returning affected_rows atomic throws ErrorType` | 插入指定列和值。 |
| `n = update table [as t] set { col: value, … } [where t.col == value [and …]] returning affected_rows atomic throws ErrorType` | 在原位置更新命中行。 |
| `n = delete from table [as t] where t.col == value [and …] returning affected_rows atomic throws ErrorType` | 按显式条件删除，省略条件不表示全表删除。 |

写入值来自闭合变量、整数或文本，写入条件当前是已绑定列的相等合取。表中 `{ col: value, … }` 逐项列出写入的列和值。三种指令都要声明实际影响行数、原子性和有依据的失败类型。这里的 `throws ErrorType` 是表中这些数据库写入指令的语法，不是要求每个 Java 或 TypeScript 外部端口都声明失败。`where` 用 `==` 和双引号是**源码扩展语法**；最终写入 SQL 才使用 SQL 自己的 `=` 与文本引号。注入指令、工程执行和输出表达是三层，不能互相冒充。

**示例。** 同一次删除命中两行时返回 2，正常完成但没有命中时返回 0。若数据库抛出声明的异常，这次写入仍在 S 里，调用方取不到影响行数。

### RA-07 逐项运算与等价交付

**规则：** 关系式用已取得的输入、值条件、顺序和投影描述结果。别名只代表当前候选值，不能读取「上一项留下的可变状态」。原代码用了循环、回调或递推，不是接收或拒绝的依据；能证明与清单中某个值操作等价才交付。原生可直接执行的部分仍由内核执行。没有等价表达时按[预处理停在哪儿](04-AI救赎.md#ai-05-预处理停在哪儿)拒绝。

**示例：** 从非零初值逐项独立累加，可交初值加求和。按 `acc = 2 * acc + item` 更新属于有序递推；不能按同样的方式求和，也不提供通用 `reduce` 兜底。即使可以推导为带权求和，没有已定义的精确权重运算和数值合同，也不交付。如果算式引用进入关系前取得的一次汇率，保留那次获取和原守卫，不能让关系式逐项读取环境。

### RA-08 取得后的化简不搬动读写

**规则：**

读取也是一样：上面的演算只合并**同一批账单上的筛选**。如果原程序先更新再查询，后一次读取可能看见更新后的数据，不能拿入口时的表来替它。归一化要消掉的是计算写法的差别，不是业务行为本身。

**示例：**

先更新欠费状态再实际查表，后一次查询可能看到更新结果；不能用更新前已取得的行顶替。

如果代码只对更新前已取得的同一批行再算一次，则不增加一次读表观察。两者不能只因为表名相同而统一。

同账户原有一行，删除成功后再次物理读取且期间无其他修改，前后行数差为 1；如果只对旧行绑定再计数，则差为 0。删除失败并向外传播时，没有第二次读取。真实读取发生一次就只记一次，保留它对实际完成的依赖。只有证明影响行数等于同一查询的行数差才可消去差式；例如更新两行备注不改变全表行数，不能把差写成 2。记录新快照的方式见[PERS登场](07-PERS登场.md#pers-08-观察身份先于显示编号)。

### RA-09 值表达式中的任选

**规则：** 每次合同允许的任选只绑定一个成员。同一成员的多个字段不能拆成多次选择。缺省可以引用已经取得的闭合整数值，包括在当前路径已取得的聚合结果；仅在能证明其输入与较早的选择都可用时接受，并保留这些依赖。

**示例：** `CHOOSE(offers DEFAULT backup AS member YIELD {code: member.code, price: member.price})` 从非空候选任选一条记录，空时取 `backup`，再用同一条记录计算整个 `YIELD`。两个独立选择写成两个 `CHOOSE`；若它们共同决定一个返回结果，内层写进外层的 `YIELD`，依次绑定。绑定名只在 `YIELD` 内可见。任选从外到内显示为 `member0`、`member1`，按绑定槽位生成，不沿用源码变量名，不借 LET 合并独立选择。

`choose` 是关系运算节点，计一次运算，再计其子式；依次为来源、缺省、`YIELD` 体。前两槽在外层求值，只有 `YIELD` 引入词法槽位。两个节点结构相同，不意味着它们执行时是同一次选择。

### RA-10 等价关系谓词共用定形比较器

**规则：** WHERE 与 ON 中的谓词只用[统一定形的结构键](08-统一定形.md#cf-02-共享结构与顺序)排序。先绑定来源，再证明改写保留 SQL 真值、观测和读取范围。物理表行中的已绑定列直接引用关系列槽，限定写法不是额外字段读取；对普通记录求字段值则仍是取值节点。列槽保留查询作用域、表行绑定、物理列和快照。SQL 的等值和关系比较复用相应运算符标识并保留 SQL 合同；渲染写入 SQL 时才使用 SQL 的拼写。不得移动谓词所属的槽位，也不得重排结果顺序。

**示例：** 已取得的布尔参数 `enabled` 不含运算，比一项列比较简单。对同一快照的无副作用内连接，`WHERE 列比较 AND enabled` 和 `WHERE enabled AND 列比较` 都把 `enabled` 放在 WHERE 的第一个合取项。若列为 NULL 且该比较结果为 UNKNOWN，`enabled` 为真时整体仍为 UNKNOWN、为假时整体为 FALSE；换位不能抹掉这一区别，也不能把 WHERE 的过滤移到 ON。结果上的 `ORDER BY priority, id` 仍先比 priority 再比 id。

### RA-11 有序内容与自然数基数

**规则：** 序列的确定长度是自然数，但长度不是取项许可。保留元素次序、重复项、空值和访问边界。

**示例：** Java 的 `new int[2]` 得 `[0, 0]`，不能定成 `[2]`；负长度与越界仍按源码失败。已取得的不可变 Vector 可用 `LENGTH(values) == 0` 表达其非正长度，但不能因此假定第零项存在。两份已取得、有序的快照只能在 `indices(LEAST(LENGTH(x), LENGTH(y)))` 内逐位配对，仍分别从 x、y 取值；有序位置不动，也不去重。宿主稀疏数组的 length 不能证明实有等量元素，业务可观察的窄化亦不从一般基数推得。

### RA-12 去重以实际投影值为准

**规则：** 无序投影并集按投影值去重；来源次序和重复来源不影响结果。依赖顺序或首次位置的运算不套用此规则。

**示例：** 两张表的记录内容不同却都投影到账户 7，跨表去重计数得到 1；不能按整行计成 2。若换成账单号投影，结果可能改为 2，不能沿用此前按账户的结果。
