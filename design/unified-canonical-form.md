# 统一正则规范

**等价的写法，在已发布规则的适用范围内，只能归到一种结构。** 例如精确整数的 `a + b` 与 `b + a` 不只是结果相等；它们经过内核后必须得到同一个 PERS 结构。排序是核心，但只有先证明可交换，才有资格排序。统一正则不是正则表达式，也不是通用程序等价判定。

| 输入 | 唯一代表或必须保留的区别 |
|---|---|
| 精确整数 `b + a`、`a + b` | 用同一结构键排序；若 `a < b`（指结构键），两式都写成 `a + b` |
| 精确整数 `c + (b + a)`、`(a + b) + c` | 先展开同族节点，再排序，最后固定左折叠为 `(a + b) + c` |
| `a > b`、`b < a` | 交换两端的同时反转比较符号，再依据已发布的结构规则选唯一方向 |
| 完整二分 CASE 的 `(p,y,n)`、`(NOT(p),n,y)` | 证明语义和取得域等价后，比较两个完整候选，只保留同一个代表 |
| `"a" + "b"`、`"b" + "a"` | 结果不同；文本次序不得交换。真实调用、短路、异常和 CASE 首命中次序同理 |

设计区是这套规范的权威来源。先定义适用域、唯一方向和反例，再写[专题种子与验收矩阵](examples/topics/unified-canonical-form/README.md)；[正式测试](../tests/README.md)从源码独立推导预期并通过唯一的测试 CLI 比较完整 PERS。实现现状与规范不一致时，保留正确预期，修内核；仍未通过的规则不声称已交付。源码求值与产物结构排序是两件事：排序不制造新的读取、调用、异常或分配。

本文件规定归一化内核必须遵守的规则与验收职责，不增加架构模块，也不是任意公式等价判定能力的声明。AI 预处理准备保留计算的合法输入，多语言解析器给出有类型和边界的 IR，内核执行、归约并产出完整 PERS。不能让测试侧替内核完成最后一次归约。

## 先判断失败属于什么问题

严格完整比较失败时，必须分别判断：

1. **业务语义错误**：输入范围、正常结果、异常、别名、调用、状态或取得条件发生改变。修输入准备、解析或内核中的错误；不能改预期迎合错误行为。
2. **缺少有效数学归约**：输出虽等价，但已明确的数学规则没有执行。给出规则前提、统一方向及反例，修内核。
3. **纯规范形式差异**：结构不同，但还没有定义它们应采用哪一个规范代表。先明确支持范围和统一选择，不能让某份偶然的 expected 直接成为全局规范。
4. **预期错误**：源码推导错误、观察合同错误或没有遵循已明确的规范。重新审查并修正预期；保留独立推导依据。

通过多少测试，不是规则正确的证明。既有测试也可能固化了错误的前提或偶然的括号结构。

## 运算域决定可用的法则

| 语义域 | 可以使用的法则及前提 | 必须保留的区别 |
|---|---|---|
| 纯、总 Boolean | AND／OR 的交换、结合、幂等及布尔恒等式 | 部分值的取得条件必须由宿主保护；不能把部分 CASE 或 nullable Boolean 当作总 Boolean |
| 普通整数 Add／Sub／Mul | 精确数学整数，不由宿主存储位宽定义上限 | 源语言的回绕、窄化或饱和须显式表达，不能混入普通整数运算 |
| word_add32／word_add64 等 | 按声明位宽执行回绕；规则须保留窄化、符号和模数 | 不能把回绕减法后的符号比较改成原数比较；不同位宽不能混用 |
| IEEE 浮点扩展 | 使用对应浮点扩展合同及其证明规则 | NaN、无穷、舍入和有符号零；不能直接套普通整数或实数恒等式 |
| 文本、序列及参数列表 | 使用对应的有序合同 | 不能因纯值而交换拼接、元素或参数的次序 |
| 引用 | 使用身份、别名及可观察字段合同 | 相同字段内容不意味着相同对象；内部重命名不能合并不同分配 |

在两个操作数都已经按源顺序求值后，入口快照取得的引用与本次执行中新分配的对象一定不相等，可直接折叠为常量。依据是来源与分配证明，不是私有堆编号的大小；两个入口引用仍可能别名。 已经取得一个完整条件引用和一个明确来源的引用后，可按原先的分支条件逐臂比较身份，不重跑原分支，也不比较对象字段。若替换分支取得另一个入口引用，仍保留两入口引用可能相同的判断。 替换为 null 的分支依据另一端已声明的可空性比较：非空入口不等于 null，可空入口必须保留其真实 null 判断。 若两端都是已取得的完整身份分区，等于和不等于可以利用交换律，按两组分支的条件结构键选择外层比较顺序。分区内部仍保持各自首命中，原源码的取值、状态和调用顺序不移动。

普通整数中 `(MAX_i64 + 1) - 1 = MAX_i64`，中间结果不会被宿主 i64 的上限钳位。`x+1 > x` 是精确整数定律；显式 `word_add64(x,1) > x` 则不能使用这条规则。普通 Sub 的零比较可以比较两端，word_sub 的回绕差值则不适用。

当 `x` 有总的精确整数证明时，`(x - c) + d` 与 `d + (x - c)` 只合并两个整数字面量偏移，不交换减法。差 `d - c` 为零时保留 `x`，为正时写 `x + (d - c)`，为负时写 `x - (c - d)`。不从这条规则推广到符号减法、部分观察、文本或回绕算术。

序列基数是精确自然数，push 令基数加一，不隐含 64 位回绕。源语言 size／length 结果的位宽转换由解析或预处理后的显式操作保留。原来的 i64 饱和求值是实现缺陷，不是既定产品合同；实现验收必须覆盖超过 i64、i128 的中间值。

## 结构排序与改写方向

`math::canonical_order_compare`／`canonical_order_key` 是现有结构排序核心。只有已经证明位置可交换后，才能调用它；排序本身不证明可交换。

纯总 Boolean 的 AND／OR 统一展开同类节点、按该排序核心排列叶子，再重建固定的左折叠树。不动点检查必须比较重建后的完整结构，不能只比较叶子是否已经有序。业务值表达式用 `AND`、`OR` 打印，不把源语言的 `&&`、`||` 带进 R；进入边界记录时，沿用该字段自己的条件语法。

关系来源的空值、非空与存在保护必须依据同一个已证明来源及取得域；相同的公开名字或名称前缀不证明两项观察来自同一批行，也不能据此删保护条件。

同一已取得的整数上的小型比较并集，和 CASE 的整数分区使用同一套区间划分。只有每个整数区间都命中，才把条件归为真或证明没有遗漏返回；例如 `x > 0 OR x < 0 OR x == 0`。漏掉零、混入另一个变量或依赖未取得值时，不用此规则证明完备。

当 `p`、`q` 都已取得且是无副作用的总 Boolean 时，`(p AND q) OR (p AND NOT(q))` 与 `(p OR q) AND (p OR NOT(q))` 都归约到 `p`。这是对同一 `q` 的完整互补，不可把不同输入换成互补；不同输入可以抽取公共项，但应保留剩余条件。外部调用和受保护的部分观察不适用这条规则。

`Lt／Le／Gt／Ge` 在参与结构排序与 CASE 取向前先统一操作数方向：共享 subject strength 较高者在左；相同 strength 时按当前 SortContext 的操作数共享键升序选边；键相等则保持。换边同时执行 `Lt↔Gt、Le↔Ge`，Expr、完整结构键和 formatter 共用这条规则。例如 `keep > index` 与 `index < keep` 必须先成为同一个比较结构，再选择 CASE 的条件及两臂方向，不能只在打印阶段换边。Heap 显示名和 T 公开别名均使用当前上下文，不借用默认上下文缓存的方向。该改写不移动源程序求值、端口观察或取得域；它只重述原纯比较，既不补部分 CASE，也不新增 NOT 互补定律（IEEE 含 NaN 时尤其不能据换边推 `NOT(x<y)=x>=y`）。Eq／Ne 仍遵循各自既有规则。

```text
(a AND b) AND c
c AND (b AND a)
```

在同一变量合同下，这类允许交换、结合的写法必须汇合，而不能各自幂等后就宣称规范完成。

完整二分 CASE 可以同时取反条件并交换两个结果；不得只取反条件。部分 CASE 不补 ELSE。多分支 CASE 保留首个命中语义，不能直接按条件字符串排序。

二分的两个结果均不是嵌套 CASE 时，先建立两个完整候选：`(p, yes, no)` 与 `(NOT(p), no, yes)`；只有在条件已经证明互补、两臂可交换且不会改变取得域、异常域、调用次数或惰性时，才允许比较这两个候选。候选方向由下文的 `case_orientation` 规则及其语义域专用策略决定，不能再由某个局部调用按 null、表达式大小或源码分支顺序自行决定。嵌套 CASE 不由这条局部规则交换。宿主保护 CASE 只能同时交换两臂来取向，不能因此把依赖取得域的 Boolean 结果展开为无保护的 AND／OR，也不能重新 normalize 整个保护 CASE 来消掉惰性边界。例如 nullable source 的空集判断采用 `CASE WHEN source == null THEN false ELSE empty(source) END`，而非在 null 域观察 source。

对于业务 `number` 的二元取小值或取大值，两个返回臂必须恰好是参与比较的两个值，且已知它们可全序比较。相等时两者可互换，因此统一用严格比较。字面量默认值保留在 ELSE；其余优先将较短的表达式放在 THEN，同等大小时按共享结构排序选边。业务 PERS 将选中的值写在比较左侧，例如 `WHEN quota < total THEN quota ELSE total`。这条规则只整理已经取得的业务值，调用次数、顺序和条件均保持原有语义。

相邻同值分支可按原顺序合并 guard：

```text
CASE WHEN C1 THEN V WHEN C2 THEN V ELSE W END
→ CASE WHEN C1 OR C2 THEN V ELSE W END
```

OR 左侧先求值；只有 `C1` 为 false 才求值 `C2`，与 CASE 只有在第一支未命中时才检查第二支相同。该规则只合并相邻同值分支，不跨中间不同结果分支直接合并原始 guard；有序 Boolean 规则统一 guard 内 OR 项的结构形式。已合并的 OR 必须作为一个 guard 保留，不能在二值 CASE 规范化时拆回重复结果分支。改写必须减少分支数，且再次归一保持同一结构。

非相邻同值分支仍使用首命中有效域 `D_i = C_i AND NOT(C_0) … AND NOT(C_{i-1})`，不能直接合并原始条件。显式 ELSE 且至少三种可达结果时，可合并同值有效域，非默认结果组保持首次出现顺序，原默认值仍在最后；只有分支数严格减少才应用。二值分区继续使用唯一二分规范，部分 CASE 不增加 ELSE。该方向不承诺任意等价多值分区已经具有全局唯一表示。

对于展开、提取公因子、默认值选择等更大的结构，需要先定义可比较的候选范围、规则前提、统一方向及停止条件。局部代码不能各自用表达式大小、渲染字符串或某个样例的分支先后决定同一类问题的规范形式。现有局部策略不能据此被推断为完整统一规范。

### 等价候选、复杂度不变与唯一代表

规范化不是“找到一个能通过当前 expected 的写法”，而是对同一语义候选集合选择唯一代表。对允许改写的结构，归一化器必须同时满足：

```text
semantic_equal(input, candidate)
preserves_observation_and_lazy_domains(input, candidate)
complexity_equivalent(input, candidate)
```

其中 `complexity_equivalent` 至少要求节点数、分支数、真实调用次数、观察次数、分配次数和递归展开边界不因取向改写而增加；同一复杂度的候选才进入规范排序。允许交换的 Add／Mul 只收集叶子、排序并固定左折叠，不默认做分配律展开或因式分解。完整二分 CASE 只交换已经存在的条件和两臂，不复制 RPC／E、观察或异常路径。顶层的一次 NOT 只反转分支选择，不增加谓词求值或观察，允许和未取反的候选比较。

完整二分 CASE 的候选排序必须使用稳定的结构键，而不是渲染文本或表达式长度：

```text
case_key = (domain_policy, guard_key, then_value_key, else_value_key)
```

`guard_key` 先使用当前 `SortContext` 统一比较两端，再使用语义域公布的关系顺序；`then_value_key` 与 `else_value_key` 只在 guard 平局时打破平局。语义域策略可以不同，但每个策略必须显式发布、可证明、幂等，并对所有语言入口相同。现有 typed Vector 长度合同的“空长度代表先行”策略继续有效；它不能被普通整数计数合同的策略悄悄覆盖。

完整二分值 CASE 的语义域优先级依次是已认证的数值指示器／正域计数、`ELSE null`、普通结构键。某一结果为 null 时，只能通过取反并同时交换两臂将 null 放在 ELSE，不能把存在的 null 当作缺失或空域。

实现收口在 `math::case_orientation`。普通完整二分 CASE 通过共享候选入口取向；宿主为 nullable 观察建立的 `CASE WHEN subject != null THEN value ELSE false END` 保护形态，通过同一模块的 nullable false-default 入口改成 `CASE WHEN subject == null THEN false ELSE value END`。pipeline、fold 和观察域只能调用这些共享入口，不能各自按 expected、入口名称或局部表达式形状重写 CASE。该 nullable 入口允许非 null 臂保留嵌套 normal-return CASE，并把外层 CASE 作为惰性保护边界。

同一完整 CASE 的输入顺序不应影响候选集合，因此必须满足：

```text
normalize(CASE WHEN p THEN y ELSE n END)
== normalize(CASE WHEN NOT(p) THEN n ELSE y END)
normalize(normalize(x)) == normalize(x)
```

如果候选无法证明语义等价、惰性边界相同或复杂度约束成立，保留原结构并报告规范缺口；不能把两个候选都作为可接受 expected，也不能以放宽 equals 代替唯一代表。

### 数值指示器

只有取值恰为 0 和 1、条件可安全取反且两臂可互换的完整 CASE，才按“条件为真时得到 1，否则得到 0”规范化。比如存在性指示器用 `WHEN label != null THEN 1 ELSE 0`。若非空分支改为 2，已不是二值指示器，回到普通 CASE 的取向规则。此规范只改写值表达式，不移动字段读取。

### 普通整数计数的非正／正二分策略

在已经证明为精确整数、同一宿主取得域、无副作用且有完整 ELSE 的计数 CASE 中，`count <= 0` 与 `count > 0` 是互补的整数区间。对于“正计数返回原计数、非正计数返回零”的同一语义，发布唯一代表：

```text
CASE
  WHEN count > 0 THEN count
  ELSE 0
END
```

因此以下两种输入必须汇聚到同一个 PERS：

```text
CASE WHEN count <= 0 THEN 0 ELSE count END
CASE WHEN count > 0 THEN count ELSE 0 END
```

该策略只适用于上述已认证的普通整数计数域。它不把 `count` 的自然下界、typed Vector 的长度策略、word 回绕或 IEEE 浮点关系混入同一规则；不同域继续使用各自已发布的 `domain_policy`。两种候选都只有一次比较、一个 CASE 和两次分支选择，故取向不改变求值复杂度、观察次数或异常边界。该合同的独立回归必须以两种输入分别运行，并严格比较完整 PERS；不能把 actual 写回 expected。

返回 CASE 的 guard 可在已证明的正常完成域及首匹配分支域内删除冗余 AND 项。先认证全部叶子为该域内的纯总 Boolean，再展开、去重并按实际宿主 SortContext 的共享键排序；从大键到小键逐项证明“当前域 AND 当前其余项蕴含该项”，成立立即删除，最后按共享顺序左折叠。不能依据原始全体项批量删除，否则互相蕴含的两项可能同时丢失。首批认证限直接原生 Boolean 与已知入口原始值／引用的 null 比较，未知调用、字段、E／T 和部分 CASE 不参与。该规则只统一给定叶集合的删除方向，不宣称任意等价公式的全局最小形；也不规定异常域内 R 必须为 bottom。保护后的惰性 CASE 不再整体 normalize。

对响应字段的扩展认证，必须沿已取得响应的真实端口 record 声明逐层查到字段类型，确认投影使用 composite 工厂登记的精确 intrinsic，且返回类型与声明一致。只有这样的 Boolean 字段及已认证 nullable 原始字段比较可以参与上述 guard 归约；普通 pure Boolean 返型、同名函数、未取得响应、未知字段和任意 heap getter 都不构成证明。

### 输出局部绑定 LET 的许可边界

候选是被绑定的表达式，而非其外层使用位置。只有候选本身含 CASE WHEN，且会在同一输出表达式的合法作用域中出现至少两次，才允许提取 PERS LET。仅重复普通算术或无 CASE 的聚合，即便引用都在同一个外层 CASE，也必须内联；候选只出现一次同样不得绑定。

提取不得扩大取得域，不得移动受保护或惰性求值，也不得改变调用、观察、异常或写入的次数及顺序；绑定不跨 R 或单个 S 值表达式的边界。满足许可条件不意味着必须提取，前序合法化简消掉重复结构后，不为保留 LET 重新引入重复。 首批在同一算术值的无条件操作数中共享闭合的 CASE 聚合；需要跨外层 CASE、行绑定或 E/T 取得域的用法，不提取。

## 条件取得的外部回执

若 E 只在守卫 G 成立时取得，R、S 的参数、值、条件及 throws 在读取位置都必须保留显式 CASE，只在 G 选中的分支引用回执。布尔保护域之外用 false，不能把仅在部分输入域存在的回执当成全域可读的 AND／OR 操作数。若所有相关值已在同一域取得，才能使用普通逻辑化简。真实调用和写入仍按源码顺序保留。

## 当前取得域内的精确整数下界

宿主先证明普通 `Count` 的关系来源、谓词、投影及环境依赖在当前观察域内已定义，数学层才能采用 `Count >= 0`。计数没有人为的有限上界。下界证明只接纳精确整数字面量、已认证的无投影／无默认值 Count 和精确整数 Add；使用任意精度整数相加，不从数字返型推断未知调用、行值、部分 CASE、浮点或 word 运算的下界。

统一方向是把下界已足以判定的字面量比较归约为 Boolean 常量，再由原宿主消去死分支。只有下界时，`Count == 0` 仍未知；`1 + Count == 0` 在合法取得域内为 false。原取得条件和独立异常必须保留，例如 source 为 null 时的 NPE 不能一并删除。证据不足时不改写，也不能把当前域的证明写进无上下文的 normalize 缓存。

## 有序 Java 常量数组

对于已执行的封闭 Java `int[]`，初始化值按源顺序占据对应位置，不能应用标量 Add／Mul 的交换律移动元素。声明简写与显式初始化共享唯一语义；`new int[n]` 则先求长度、再得到长度为 `n` 的零填充数组，不能与 `new int[]{n}` 同形。读取可确定的长度和位置直接归约；在当前取得域越界或负长度时保留各自的真实异常及 guard，而不是正常返回 null、补零或把异常推到无关路径。该例的 [正式验收种子](examples/topics/unified-canonical-form/java-constant-array.md) 不把可变数组归为不可变 Vector，也不认证对象身份、写入、逃逸和符号长度。

## 已取得 typed Vector 长度的自然域（目标合同）

宿主可认证原生 `ValueLength` 的精确自然数域，但证据必须同时包含：接收值在当前宿主域已经取得；完整声明类型确为不可变 Vector；若来自响应或 record 字段，完整字段路径逐层有声明类型，且该取得条件已成立。字段中的 Java null 标志不使完整 record 的其他载荷变成未定义；相应源异常仍由独立 throws 保留。不能仅凭 `Ty::I64`、普通 Number 返型、函数名包含 length、相似打印或尚未取得的 E/T 推断这些前提。

通过认证的长度 subject 取值域为无有限上界的自然数，不按 i64 标签截断。单一 subject 的总比较沿整数区间规范在该自然域内计算真集与补集：长度 `> 0` 的真域是 `[1,+∞)`，补域是单点 `{0}`；单点统一用 `== 0`。对于“正长度返回 A、空长度返回 B”的完整二分值 CASE，若 A/B 均非 null、非嵌套 CASE，两个方向尺寸相同，再由共享排序的 Eq 早于 Ge，唯一代表是 `CASE WHEN length == 0 THEN B ELSE A END`。不能将当前局部取向的 `<= 0`、原源码 `> 0` 或正域 `>= 1` 同时作为可接受黄金。

首批通过正式 JavaScript 模块验收：入口声明非空 `ReadonlyArray<number>`，适配层交付有类型 Vector 后，内核才能使用已认证的长度观察。左右换位、空分支反写、阈值变化、可空 Vector 和普通业务数字都有全量断言。这里只解释声明中的长度，不把宿主稀疏数组的长度当作已存在索引的计数；响应或深层记录路径仍需独立验收。

这个规则只使用当前取得域内的 typed Vector 自然域证据，不扩展未知调用、未声明字段、nullable／部分接收值或任意 E 路径；它也不授权把 Source 的零项规则跨类型套给 Vector。源语言显式 word 转换与回绕仍独立保留，原标准 Java List 的有限可达上界不替代一般数学 Vector 的域定义。生产认证与区间归约须通过独立完整断言验证；目标合同已明确不代表当前内核已经实现，未满足时必须真实报红。

## 不可变总运算的 CASE 外提规范

对具有明确纯性、总性和结构类型证据的不可变构造运算，直接参数中的完整 CASE 统一向运算外提升。仅有 `pure=true` 或普通 `Number` 返型不足以证明这些前提；未知调用不自动适用。选中的 CASE 必须有显式 ELSE，所有分支满足该参数的同一声明类型；其他参数和 CASE 条件必须在同一宿主取得域内为总值，结果的结构类型也必须保持一致。

```text
f(a, CASE WHEN C THEN x ELSE y END, b)
→ CASE WHEN C THEN f(a, x, b) ELSE f(a, y, b) END
```

首批通过正式 JavaScript 模块验收不可变数值 Vector 构造：出口声明 `ReadonlyArray<number>`，前端拒绝空洞、未知元素及非数值元素。按元素位置从左到右外提，不改 Vector 内的位置；重复相同的 guard 不能留下不可达构造，超出展开预算明确拒绝。不将这些证据套给可变对象分配、未取得的 E/T 或任意 map。

该改写只复制已经取得的纯值引用，不得复制或重新取得 RPC／E，不得复制可观察身份分配、改变调用次数／顺序，也不跨 T 定义、迭代绑定或宿主取得域边界。部分 CASE 不补 ELSE，不将其隐含的未定义／null 域扩展成合法参数域；惰性参数运算亦不能套用此规则。

规范方向先从左到右递归处理子表达式，再按从左到右的参数位置选择直接参数中的合格总 CASE。保留所选 CASE 的首匹配分支顺序，逐分支将该参数替换成对应分支值；分支中的其他合格 CASE 继续按相同规则外提。结果中的直接 CASE 使用既有结果 CASE 展平规则，再执行既有首匹配有效域、冗余 guard 剥除与结构排序规则。禁止反向把这些分支因式提取回运算参数，不能按 fixture 或打印长度选择另一方向。

例如同一取得域内三个按顺序处理的 nullable 字段 `a,b,c`，每次仅在非 null 时向不可变 map 插入不同常量键：最终按外层 `c == null`、中层 `b == null`、内层 `a == null` 的源首匹配顺序枚举八个结果域，每个结果保留 `a,b,c` 的插入顺序。CASE 条件内可交换的 AND 项仍采用共享结构排序，不能将分支列表按字符串排序。 [JavaScript 有序只读文本 Map](examples/topics/language-entries/javascript-module.md#有序只读-map可空输入只在非空时插入)验收八个完整结果域、插入顺序的反例、空 Map、错误保护与预算。首匹配能证明的条件不重复；不扩展到重复键覆盖、可变或任意外部 Map。

终止条件是所有合格运算的直接参数均无待提升总 CASE，结果 CASE 和条件已达既有规则不动点。对每个待分发运算，递归分支把选中的 CASE 替换成严格子项，该分支中待处理的参数 CASE 数严格减少；有限输入生成有限笛卡尔积，且没有反向改写。实现若因资源或分支预算无法完成，必须报告未归一化，不能以保留嵌套式作为另一个可接受规范代表。本节定义目标规范方向；不能仅凭合同发布声称生产内核已经实现，实际支持范围仍须由独立完整断言验收。

## 单一整数 subject 的谓词区间规范

当一个 Boolean／CASE 子树具有独立的总性与整数类型证据，且所有原子谓词只比较同一个稳定 subject 与精确整数字面量时，以最大互不相交整数区间的并集作为该子树的统一代表。证据须来自入口／绑定的声明类型及宿主取得域；通用 `Number` 返型或未定型行值不能单独证明整数总性。例如 `vector<i32>` 的纯 fold item 具有 i32 整数域证据，不能擅自缩为 UTF-16 的 `0..65535`。

允许的组合为总 Boolean 常量、AND／OR／NOT，以及分支值均为总 Boolean 的完整 CASE；CASE 先按首个命中语义解释。原子比较限同一 subject 与整数常量的 `==`、`!=`、`<`、`<=`、`>`、`>=`。在精确整数域内以区间并、交、补计算真值集合，再合并相邻真区间。若类型具有固定上下界，所有求补、全域与空域判断都使用该类型域；端点计算使用精确整数，不能在宿主整数溢出后决定区间。

空集与全域分别表示为 `false`、`true`。单点使用 `subject == k`；其他区间使用包含端点的 `subject >= lower` 与 `subject <= upper`，仅当某一端到达已证明的类型域边界时省略该端比较。每个区间内部的 AND、所有区间之间的 OR 均按既有共享结构键排序并重建固定左折叠，不按源码分支顺序、区间插入顺序或打印文本排序。

多值 CASE 的结果不是总 Boolean，不能把其 payload 直接套入上述 Boolean 真值化简。对于同一已认证整数 subject、具有显式 ELSE 的多值 CASE，可先按有限整数单元计算首匹配的有效域，再将同一 payload 的所有区间汇聚为一个 guard；各 guard 使用上述单点／包含端点区间规范和共享 Boolean 排序。非默认 payload 按原分支中首次出现顺序排列，保留原显式默认 payload 为最后的 ELSE，不按区间出现次数选择新默认，也不按数轴顺序重新排列 payload。与默认相同的其他分支归入默认域，不输出重复 payload；不可达 payload 不输出。部分 CASE 不补 ELSE。这一衔接使区间计算与既有同值汇聚具有同一方向：区间规则不能再把一个已汇聚的 payload 拆为多个 CASE 分支，其他规则也不能反向展开其 guard，或按前支失败域删掉下一轮区间分区必须恢复的边界。已认证的完整多值整数分区在这一层是终态；后续一般 CASE 规则不再改写它的有效域表示。此处只统一给定默认和 payload 顺序下的分区表示，不承诺不同显式默认或不同多值决策结构具有全局唯一代表。

该方向只作用于同一宿主取得域内的合格子树。有限比较端点把整数域分成有限个真值恒定单元；完成并／交／补与相邻区间合并后，再次执行得到同一代表，因而停止。其他 Boolean 规则不能反向展开或因式分解成另一代表；实现须在该子树范围内保持这一规范方向。

该规则不覆盖 IEEE 浮点、nullable／部分 Boolean、缺少 ELSE 的部分 CASE、多变量比较、word 算术改写、未知调用或尚未取得的 E／T；也不授权跨宿主域移动观察。类型与总性证据不能因端点有限而省略。只有生产内核实际执行该汇聚且通过独立断言后，才能称相关子集已实现；固定规范预期暴露的差异仍须真实报红。

## 保序序列第零项的统一规范

对顺序、元素类型和宿主取得域均有明确证据的纯序列关系，`NthValue(index=0, default=null)` 统一为同一关系的 `FIRST(identity projection, default=null)`。索引零必须是精确整数字面量；Base、Project、Select 等输入结构不构成保留另一种索引／SQL 表达风格的理由。带投影的关系须通过既有投影组合规则保留其实际元素值，不能改成底层未投影对象。

此规则保留顺序、重复元素和首项 null：`FIRST` 读取第一个元素，不附加非 null 过滤。可空投影具有非空缺省时，只有无记录才使用缺省。规范用存在性 CASE 保护首项；不能把选中记录的 null 当成空集。源语义如果已过滤 null，保留同一关系中的该过滤；不能把未过滤的第零项换成第一个非 null 元素。Java 的 null 接收者和空集合越界仍由独立 throws 域表达；`default=null` 只是纯选择值表达式的默认值，不授权删除源异常。

固定方向只从合格的第零项观察改为 FIRST，再执行既有关系／投影归约；不反向生成 Base 索引打印，不以原 IR 结构、入口或语言决定风格。不覆盖非零／未知索引、非 null fallback、缺少顺序证明的关系，也不移动 E、调用或迭代绑定。前提不满足时保留原观察。合同规定目标代表，生产归约及 renderer 仍须通过独立完整断言证明已统一，不能将等价索引打印作为第二份可接受预期。 对直接取得的有序标量数组，R 写成 `FIRST(value FROM values)`，只替换值观察，不改 S 中的索引写入目标，也不改越界的 throws。

[先完整投影后取首项](examples/topics/collections/java-eager-first.md)的 FIRST 只表达正常完成时的值。先扫描整个非空记录数组，后行的空工单仍能使投影失败；取索引的越界条件在投影成功之后。仅当确证同一输入为空时，才移除对过滤子集再次判空的守卫，不从同名别名猜测相同关系。

[跨表投影去重](examples/topics/relational-data/sql-projected-distinct.md)先用已声明的非空标量列构造每条投影，再对同类无序集合做并集。交换或重复分支不改变可能值；同一分支重复时仍按投影值而非整行去重。改变投影列则是另一种业务结果。

[显式空值覆盖缺省](examples/topics/collections/java-map-present-null.md)将键的存在性和可空载荷作为不同事实归一化：只有缺键才取 fallback；已存在的 null 不是缺键。不能用 COALESCE 或普通非空测试替换此规则。

FIRST 的选中值若为 CASE，且同一行绑定的过滤域已蕴含某个显式分支的首匹配有效域，可用该分支的原行值或纯字面量替换选中 CASE。首批证明限 Base 与连续 Select、行值的 null 比较和总 Boolean 组合；未知调用、其他行绑定、技术观察根及未取得 E 不参与。原关系和空集默认值保留，后续既有规则可继续归约；部分 CASE 不补 ELSE，不跨投影绑定取用外层同名行，也不增加求值或改变身份。

## 两个保序快照的共同位置范围

当两个非空入口引用提供长度已取得的不可变记录序列时，`indices(LEAST(LENGTH(x), LENGTH(y)))` 枚举两序列都存在的位置，不包含上界。只在长度这两个纯、总、已经取得的自然数上使用 `LEAST` 的交换律，按共享结构键排序；同一快照的两个长度去重为单个长度。两个序列在实际位置表达式里的职责不交换：对关闭序列取 `i`，对打开序列取 `LENGTH(opened) - 1 - i`。任何一个输入可能为空，也不得访问界外位置或去掉重复编号。见[打开与关闭的反向位置对照](examples/topics/state-and-aliasing/java-lifo-release.md)。

## 顶层异常结果的稳定排列

顶层 `throws` 列表表示互斥的终态异常结果，不是按列表位置执行的抛出或 catch 优先级。源码真正先发生的异常必须由各记录的首匹配有效域保留。typed 归约完成、宿主取得 guard 闭合、E／T 编号确定后，以 `(exception class, payload presence + typed Expr structural key, guarded condition structural key)` 排列记录：类名采用稳定字典序，载荷缺省与已观察到的 null 区分，表达式键使用既有共享结构排序核心，不使用 JSON／SQL 文本、函数注册号或 fixture 名称。

只有终态记录域已证明互斥时才允许交换。未能证明互斥不能靠排序补齐源优先级；实现须保留原顺序并明确报告规范缺口，或拒绝交付尚未归一化结果。相同 class 与相同载荷的已有归约可在保留取得域的前提下汇聚 guard；本排序规则不新增合并策略，不合并不同载荷，也不移动或重新取得 E、改变 S 调用顺序。payload 的类型与取得域须继续遵守原异常观察合同。

`task_completion.throws` 的类型声明、异常 tag 及完成记录布局属于另一层合同，不是顶层异常数组，不能独立重排声明而不一致改写相关 tag。此规则只适用于已闭合的 typed 终态，不适用于 SQL 文本中的无载荷异常展示。

本节规定所有有类型出口的目标方向。仅有异常类型、没有载荷的终态，在完成域已证明互斥后先按类汇聚，再按类名排列；有载荷的出口必须再比较载荷与条件结构键。不具备互斥证明的出口保留原顺序并报告规范缺口，不能将一个出口的局部实现扩大为全局完成。具体支持范围以专题种子和独立完整断言为准。当前[直接 Java 异常验收](examples/topics/unified-canonical-form/java-exception-payload.md)闭合 RuntimeException 的字面量消息和显式 null；不将其扩大为 cause 或可观察异常对象；[外部端口型载荷](examples/topics/unified-canonical-form/java-exception-payload.md#外部异常载荷必须来自它自己的回执)独立证明同类不同回执、声明类型与取得路径。

## 规范代表的统一选择

规范形式先确定语义域，再确定结构，最后才打印文本。测试作者不能自行在 `a+b` 与 `b+a`、不同括号树、不同 CASE 方向之间任选一个。所有语言入口必须遵守同一套已发布的规范规则；不能按 Java／JavaScript、fixture 或入口名称选择不同风格。

规范输出的目标顺序如下：

1. 校验值类型、正常／异常域及观察获取域。未取得的 E、未执行的 T 不得被当作总值参与代数排序。
2. 归约已定义的常量、投影、恒等式、集合运算及可消除递推；规则只依赖语义运算及其前提。
3. 对允许结合、交换的同一运算族收集叶子，执行规定的合并，使用结构排序核心排序，再固定左折叠重建。
4. 对不能交换的结构使用各自规则：文本连接只统一结合结构，列表保留元素次序，CASE 保留首匹配有效域，边界记录保留真实调用顺序。
5. 对可重命名的内部绑定按依赖关系统一编号，替换所有引用；再用同一结构排序和格式器打印。不得按打印后的字符串反推排序。
6. 验证输出闭合、编号一致及规则不动点；比较完整 PERS，而不是比较去掉某些字段的投影。

业务 `number` 的精确字面量只有一种内部结构。去掉不影响数值的系数尾零；小数位归零时用整数节点表示，零也只有一个节点。源写法 `0.10` / `.1` 与 `1.0` / `1` 在进入 CASE 和相等判断之前就得到相同的结构，不等到显示时再处理。`x - x` 在两边已各自完成业务求值、取得同一个精确数值表达式之后可归约为零，前面发生的外部效果和异常不因此消失。此规则不表示接纳 IEEE 近似，也不宣称所有符号小数的 AC 汇聚已接入。

精确整数的 Add／Mul 分别属于两个不同的 AC 运算族。目标规范收集同类节点、按结构键排序后左折叠；加法零、乘法一及相邻可合并常量依据精确整数合同处理。文本 Add 必须由类型证据排除，浮点运算不得混入。该规范不自动授权分配律展开、因式分解或把 Sub 改写为 Add：每种更大范围改写必须规定一种统一方向，避免两个相反规则反复切换。

```text
normalize(add(b,a)) = normalize(add(a,b))
normalize(add(c,add(b,a))) = normalize(add(add(a,b),c))
normalize(mul(b,a)) = normalize(mul(a,b))
normalize(concat(b,a)) != normalize(concat(a,b))
```

右侧的 `a,b,c` 表示按统一结构键排列的同域符号，而不是由某个测试选择的字母顺序。排序键必须包含运算族、类型和稳定的语义名称；不能依赖函数注册先后、内存地址、HashMap 遍历顺序或输出中偶然分配的数字编号。

精确整数 Add／Mul 的 AC 汇聚接收具有总性证据的直接入口整数参数、整数字面量，以及由这些值构成的 Add／Sub／Mul／Neg 树；聚合常量使用任意精度整数。语言适配器把已证明的源类型交付为逻辑整数或显式固定字宽载体，math 不从 Java 类名推断业务值域。源语言算术的回绕仍须由 word 算子独立表达。技术观察根、字段／索引路径、E／T、未定型行值、调用、CASE、除法、浮点与 word 节点不能仅凭数字返型进入该规则。拒绝认证只保留原结构，不改变值域。

该子集具有独立的排列、括号、常量、幂等及负向验收；Java 源码主线另验证 Boolean 合取写法的汇聚，不将 Java 回绕算术当成精确整数 AC 的证明。扩大到其他有域整数值需要补齐总性或观察域证据。**跨全图 E／T 的稳定重编号仍需单独实现与验收。** 不能让测试端替内核归约，也不能将局部支持扩大为“任意等价公式唯一”。

## E／T 和内部名字

计算是否合法依赖 IR 中已确认的符号来源，而不依赖显示名。数学层的已绑定整型输入不会因为名字的前缀像 E、T 或 heap 就变成部分值；真正的回执和递推结果仍需自己的取得域证据。

已取得的两个直接对象参数（例如 `left` 和 `right`）仍按引用身份判断，无论源码与入口参数的声明先后如何，`left == right` 与 `right == left` 都以公开参数路径比较并汇到 `left == right`。路径排序不改 P 的 position，不改变两次取得的先后，也不把相同内容或同名对象视为同一实例。这个起步合同不声称所有 heap 路径或 T 编号已经接通。

E／T 的内部标识与所有 R／E／S／T／throws 引用必须一致重命名。观察的依赖、取得条件、调用身份和次数都属于语义，不能为排序改变。

在已证明可交换的表达式位置，匿名观察按其编号的数值排序，例如 `$e_2` 排在 `$e_10` 前。该比较不改变 S 的调用顺序。编号较小不等于在所有分支都更早发生。同一个入口快照可在一个分支中于调用前读取，在另一个分支中于调用成功后读取。应核对实际依赖和环，而不是仅比较编号。

稳定排列只可移动已证明相互独立且可交换的项目；真实调用顺序、集合顺序、CASE 首个命中以及部分值取得域必须保留。不得仅以“没有显式写入”为理由移动可能受环境、时间或调用身份影响的观察。

内核的一致重命名与依赖感知的稳定排列需要单独验收。测试不能忽略编号、排序整个 S、删除取得条件或对名字做任意对应，来替代这项内核职责。

已经取得且有公开名字的入口状态字段，以公开的 E 根路径和字段路径参与结构排序。例如 `zebra.units + amber.units` 和反向源码均归到 `amber.units + zebra.units`；两个记录仍各自指向原状态字段，`zebra.units - amber.units` 不交换。这里只规范数学表达式，不排序真实调用，也不承诺未命名观察已可跨图重编号。

### 独立入口快照的规范编号

规范对以下受限子集要求稳定 E 命名：文档没有调用、索引调用族、内部选择或 T 定义；所有实际使用的入口字段观察具有同一直接入口对象身份和完全相同的获取条件。对象身份须是 Heap 中的入口引用，其显示名必须对应合同中 Object 类型的参数；字段类型须来自合同的 heap_fields。获取条件只能依赖已声明入口参数及闭合值，不含行绑定、E 或 T 依赖。

满足这些前提时，字段按 `(field,type)` 的稳定结构键排列，依次命名为 `$e_0,$e_1,…`，E 列表使用相同的数字编号顺序；R、获取条件、S 和 throws 中的引用统一替换。字段、观察符号及原身份编号必须唯一；重复字段不以排序为由合并。这个计划只改变数学入口快照的名字与呈现次序，不移动运行时读取，不改变获取条件，不授权交换 getter、volatile 读取或外部环境访问。

前提不满足时保留既有编号和观察次序，继续执行因果、定义域与作用域检查。带调用或不同获取域的 E、多个对象根、T 的跨全图依赖重编号尚未纳入该计划；不能把此局部规则宣称为所有等价程序的唯一命名，也不能在测试端忽略名字来补齐缺口。

### 边界记录的规范排列

结构化 S 的发生条件统一显式写入 `cond`，无条件事件使用表达式字符串 `"true"`。不能因纯式快路径、有状态路径或端口类别不同而在最终输出中省略该字段。最终规范只允许一种结构。

E 的“相同”需要同时满足观察对象身份、字段／端口、获取时点、获取条件及调用实例合同。名字相同不能合并两次 RPC；同一对象字段的入口快照可以复用，但必须保留它实际需要获取的域。

稳定编号的目标是：先构造状态观察、调用响应和纯定义之间的依赖图；对无环图按稳定拓扑顺序分配编号。同一时刻有多个可选节点时，用不依赖临时编号的结构键确定顺序。依赖键递归引用已规范的依赖节点，不能先按 `$e_1` 的字面顺序排序再声称结果稳定。 对纯定义还要同时验证：两条互不依赖定义的源码声明先后不同、局部名字不同或定义内部只交换可交换项时，公开 T 与全部引用不变；后一条依赖前一条时不能反向发布。此要求不授权把多个 `member_choice` 或真实调用合并。有序精确整数的纯递推采用 `T.fold`，记录取得后的输入序列、初值、两个固定词法绑定和已规范化的闭合更新表达式。先按依赖拓扑排序，再以公开输入、规范初值和更新体结构选取当前可发布项；别名用于后续结构排序以及所有公开引用。无条件且无副作用的等价定义可共享。目前验收单入口、纯标量返回、无外部效果或异常的递推，初值可引用已经取得且类型已声明的整数 E 字段；其他 E/T 混合图及定义仍须独立证明。 [直接整数成员选择](examples/topics/unified-canonical-form/java-member-choice.md)已经验证两个实际发生位置保持各自的 T 身份；不会用纯递推的结构去重合并相同候选，对依赖已取得入口标量的条件选择，以真实 `T.when` 和 CASE 使用路径一起验收；编号不证明全域取得。其他条件仍须独立证明。 [混合 T 图](examples/topics/unified-canonical-form/java-member-choice.md)验证选择与递推的双向依赖、独立结构排序、守卫内重复取得，以及真实整数回执作初值；不推广到未证明的状态写入或部分回执。 [整条报价](examples/topics/collections/java-independent-choice.md)验证同一次选择的编号和价格使用同一个 T，第二次选择仍独立；字段内容不等于对象身份。

真实调用的先后、循环迭代路径及不同动态实例构成不可交换约束，即使参数相同仍须保留。只在证明相互独立、观察可交换的节点之间使用稳定键打破平局；一旦依赖成环或者所需可交换性未证明，明确报告合同缺口。S 的有序边界调用不得全表排序；最终字段记录的排列也不能抹掉 checkpoint、异常域或别名关系。

YAML／JSON 对象键的存储顺序可不参与结构比较；数组顺序和表达式的运算结构参与。编号、CASE 分支、E 获取条件不是“格式噪声”，不能在断言前删除或任意重排。

## 规则与测试的分工

每条新增规则必须说明：输入语义域、数学法则、成立前提、统一方向、前提不满足时的行为，以及对定义域和边界记录的影响。不得按入口名、fixture 名或具体业务返回值特判。

规则验证至少包括不同符号、不同树形或排列的同类正例，以及破坏前提的反例。按适用范围增加：

- 合法交换、结合后的同一规范结果；
- 内部绑定的一致重命名；
- 不同进程、函数注册或分析遍历顺序的稳定结果；
- `normalize(normalize(x)) = normalize(x)`；
- 完整二分 CASE 的两种互补输入得到同一代表，并验证候选交换不增加节点、分支、调用或观察次数；
- 普通整数计数的 `count <= 0 / count > 0` 两种方向都得到发布的正计数代表；typed Vector 长度则按其单独发布的空长度优先策略验收；
- 调用重排、部分 CASE、浮点及显式机器运算等负向反例。

这些跨写法检查是补充证据，不能替代业务回归中的独立完整预期。业务回归仍须对所有 R／E／S／T／throws 字段严格 equals；不能在比较前把 actual 和 expected 同交完整化简器再补判通过，也不能接受多个等价 expected。

预期可以使用结构构造和格式化便利工具，但如果调用生产化简器生成关键预期，必须明确它未独立验证该化简器，另用独立常量预期、语义证明或原源码对照覆盖相应规则。

每个 feature 的预期审核须记录源码依据、观察范围、适用的规范规则，以及未知输入下的手工关系。输出不一致时，先按本合同区分语义错误、未充分归约、规范缺口和预期错误，再修改对应层。禁止将 actual 写回 expected、以多个候选完整文档接纳 actual、在比较前把条件替换成真值表，或以等价证明替代完整规范式 equals。辅助差分和证明可以保留，但必须与最终产物严格比较分别验收。

只读源码审计不能证明所有手写预期独立正确。新增比较辅助函数与预期变更仍须接受代码审核。PERS 结构守卫、完整唯一预期比较、规范律测试、独立行为证据四者职责不同，不互相替代。

## 能力边界与完成标准

不承诺任意等价程序或公式都可判成同一个结构。只能对已建立规则及其明确支持的范围声明规范化能力。

以下三项要分别验收：运算合同和规范规则是否明确且实现正确；预期是否按源码与规范独立推导；实际业务及完整回归是否通过。任何一项通过都不能替另外两项作结论。

搜索预算或迭代上限耗尽，不构成“已获得唯一规范形式”的证据；也不能伪装成数学上的不成立。不得用上限截断未知业务输入，或用保留下来的未完成表达式宣称规范归约完成。
