# 标准操作与声明标记

Normalizer 的跨语言标准不是两套各自相似的 API。Java 和 TypeScript 可以有不同的声明写法，但同一个标准操作必须有同一个类型合同、空值规则和返回含义。识别依据是官方 `N` 的实际绑定和签名。应用文件里碰巧叫 `N` 的对象或遮蔽导入的局部变量都不能获得标准语义。

| 用途 | Java | TypeScript | 语义 |
| --- | --- | --- | --- |
| 标准操作入口 | `import normalizer.intrinsics.N;` | `import * as N from "@normalizer/stdlib";` | 同一业务操作以同一个 `N` 方法名和参数合同表达。 |
| 纯值操作 | `N.trim(x)`、`N.round(x, 2, N.HALF_UP)`、`N.plusDays(day, days)` | 同名操作 | 按业务合同判断能否替换为同一操作；宿主裁剪差异按[业务至上](../chapters/06-业务至上.md#bf-05-文本清理按业务合同统一)处理。显式舍入位置和模式不能丢。 |
| 环境读取 | `N.currentTimeMillis()` | 同名操作 | 每次执行到这里才取得一个 Unix 纪元毫秒的符号环境值，记录为 E，不因此产生 S。两次读取不能合并，但它们可以碰巧读到相同的值。 |
| 可空值 | `@N.Nullable String value` | `value: string \| null` | 只说明有效值域，不做转换或补默认值。 |
| 入口已有状态 | 字段上的 `@N.EntryState` | 声明前的 `/** @N entryState */` | 声明的是这次执行开始前就存在的状态，不是入参，也不会替代码写状态。 |
| 外部端口 | 接收者字段上的 `@N.External` | 声明前的 `/** @N external */` | 标明调用边界。标记本身不发调用，不替签名补未知异常。 |
| 异步端口失败类型 | 方法的 `throws` 声明 | 外部接口方法上的 `/** @N rejects ErrorType */` | `Promise<T>` 给成功类型；异常类型须解析到工程内声明的异常类，或 Normalizer 内置的通用类型 `ExternalFailure`。没有失败声明就不建外部失败路径；何时标记见[外部异常须显式声明](../chapters/04-AI救赎.md#ai-09-外部异常须显式声明)。这些声明不能把普通对象变成端口。 |
| 组件属性入口 | 不适用 | `/** @N componentProp Component#instance.prop */` | 把已导出的函数与原组件属性关联，不触发渲染，不取代导出入口定位。 |

已经合规的原语言操作原样执行。比如 `a + b` 不必包一层 `N.add`，显式舍入到整数也不等于普通加法。第三方库若只有名字像标准操作，需保留的空值或舍入行为却说不清，不能硬换成 `N`。已经取得的纯值交给内核化简；注解、注释和标准库入口不承接 AI 推算出的结果。
