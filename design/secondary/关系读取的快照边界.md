# 关系读取的快照边界

本专题细化《关系代数》的关系取得和《PERS登场》的 PERS。表声明说明物理来源和列合同，不保证每次查询取得相同的行。

- 对已取得的行绑定重新计数，不是重读。一次可能成功的同表写入之后再次物理读表时，新的行属于独立的环境观察；不能用旧行、表名或相同 SQL 替代。
- 保留实际读取条件和它与已发生且成功的同表写入之间的依赖。每条依赖指向真实写入完成，只在该完成可达时成立。分支汇合后实际读取一次，就只记录一次观察；不能为没发生的写入捏造回执。已交付为关系读取的观察进入 E，不新增 S 写动作；若源码调用仍作为外部端口交付，则按[PERS登场的外部调用合同](../chapters/07-PERS登场.md#pers-01-参数环境和回执的来源)记录调用和回执，不能仅因它只读而删掉调用。
- 只有确认两次查询的取数合同，并证明写入影响行数恰好等于该查询的行数差，才可化简差值。隔离和无并发不等于这个证明：把两行的备注更新后仍查询全部行，影响两行，行数差却是 0。即便能化简差值，两次真实取得也不能合并。

判别例：同账户原有一行，删除成功且期间没有其他修改。重读时，前后行数之差为 1；复用删除前已取得的行时，差为 0。若删除失败且未被捕获，仍保留写入尝试及失败回执，但没有第二次读取。机器字段见 [PERS 接口](../../implementation/contracts/business-pers.md)。
