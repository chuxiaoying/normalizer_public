# 精确数值与区间怎样化简

本专题细化第三章、第六章和第八章的精确业务值规则。先有类型和取得域，再选择法则。

## 运算域决定可用的法则

| 语义域 | 可以使用的法则及前提 | 必须保留的区别 |
|---|---|---|
| 纯、总 Boolean | AND／OR 的交换、结合、幂等及布尔恒等式 | 部分值的取得条件必须由宿主保护；不能把部分 CASE 或 nullable Boolean 当作总 Boolean |
| 普通整数 Add／Sub／Mul | 精确数学整数，不由宿主存储位宽定义上限 | 源语言的回绕、窄化或饱和须显式表达，不能混入普通整数运算 |
| word_add32／word_add64 等 | 按声明位宽执行回绕；规则须保留窄化、符号和模数 | 不能把回绕减法后的符号比较改成原数比较；不同位宽不能混用 |
| IEEE 浮点扩展 | 使用对应浮点扩展合同及其证明规则 | NaN、无穷、舍入和有符号零；不能直接套普通整数或实数恒等式 |
| 文本、序列及参数列表 | 使用对应的有序合同 | 不能因纯值而交换拼接、元素或参数的次序 |
| 引用 | 使用身份、别名及可观察字段合同 | 相同字段内容不意味着相同对象；内部重命名不能合并不同分配 |

普通整数中 `(MAX_i64 + 1) - 1 = MAX_i64`，中间结果不会被宿主 i64 的上限钳位。`x+1 > x` 是精确整数定律；显式 `word_add64(x,1) > x` 则不能使用这条规则。普通 Sub 的零比较可以比较两端，word_sub 的回绕差值则不适用。

当 `x` 有总的精确整数证明时，`(x - c) + d` 与 `d + (x - c)` 只合并两个整数字面量偏移，不交换减法。差 `d - c` 为零时保留 `x`，为正时写 `x + (d - c)`，为负时写 `x - (c - d)`。不从这条规则推广到符号减法、部分观察、文本或回绕算术。

序列基数是精确自然数，push 令基数加一，不隐含 64 位回绕。源语言 size／length 结果的位宽转换由解析或预处理后的显式操作保留。实现验收必须覆盖超过 i64、i128 的中间值。


## 当前取得域内的精确整数下界

宿主先证明普通 `Count` 的关系来源、谓词、投影及环境依赖在当前观察域内已定义，数学层才能采用 `Count >= 0`。计数没有人为的有限上界。下界证明只接纳精确整数字面量、已认证的无投影／无默认值 Count 和精确整数 Add；使用任意精度整数相加，不从数字返型推断未知调用、行值、部分 CASE、浮点或 word 运算的下界。

统一方向是把下界已足以判定的字面量比较归约为 Boolean 常量，再由原宿主消去死分支。只有下界时，`Count == 0` 仍未知；`1 + Count == 0` 在合法取得域内为 false。原取得条件和独立异常必须保留，例如 source 为 null 时的 NPE 不能一并删除。证据不足时不改写，也不能把当前域的证明写进无上下文的 normalize 缓存。

## 单一整数 subject 的谓词区间规范

当一个 Boolean／CASE 子树具有独立的总性与整数类型证据，且所有原子谓词只比较同一个稳定 subject 与精确整数字面量时，以最大互不相交整数区间的并集作为求证用的真集，不把完整区间边界强制打印成守卫。证据须来自入口／绑定的声明类型及宿主取得域；通用 `Number` 返型或未定型行值不能单独证明整数总性。例如 `vector<i32>` 的纯 fold item 具有 i32 整数域证据，不能擅自缩为 UTF-16 的 `0..65535`。

允许的组合为总 Boolean 常量、AND／OR／NOT，以及分支值均为总 Boolean 的完整 CASE；CASE 先按首个命中语义解释。原子比较限同一 subject 与整数常量的 `==`、`!=`、`<`、`<=`、`>`、`>=`。在精确整数域内以区间并、交、补计算真值集合，再合并相邻真区间。若类型具有固定上下界，所有求补、全域与空域判断都使用该类型域；端点计算使用精确整数，不能在宿主整数溢出后决定区间。

空集与全域分别表示为 `false`、`true`。单点使用 `subject == k`；其他区间使用包含端点的 `subject >= lower` 与 `subject <= upper`，若某一端到达类型域边界，或在当前位置已由前序失败的首匹配条件蕴含，删除该端的冗余比较。每个区间内部的 AND、所有区间之间的 OR 均按既有共享结构键排序并重建固定左折叠，不按源码分支顺序、区间插入顺序或打印文本排序。

多值 CASE 的结果不是总 Boolean，不能把其 payload 直接套入上述 Boolean 真值化简。对于同一已认证整数 subject、具有显式 ELSE 的多值 CASE，可先按有限整数单元计算首匹配的有效域，再将同一 payload 的所有区间汇聚为一个 guard；各 guard 使用上述单点／包含端点区间规范和共享 Boolean 排序。非默认 payload 按原分支中首次出现顺序排列，保留原显式默认 payload 为最后的 ELSE，不按区间出现次数选择新默认，也不按数轴顺序重新排列 payload。与默认相同的其他分支归入默认域，不输出重复 payload；不可达 payload 不输出。部分 CASE 不补 ELSE。求证有效域与选择公开守卫是两步。一个端点若在首匹配位置已由前序失败蕴含，可不在守卫中重写。只有保留全部源值、首匹配、正常／异常和取得域且降低整值复杂度时，才用更简单代表；不能宣布内部区间形式覆盖后一阶段的化简。

该方向只作用于同一宿主取得域内的合格子树。有限比较端点把整数域分成有限个真值恒定单元；完成并／交／补与相邻区间合并后，再次执行得到同一代表，因而停止。生成候选后还须按第八章比较复杂度与结构；真集的计算不要求展开最终表达式。

该规则不覆盖 IEEE 浮点、nullable／部分 Boolean、缺少 ELSE 的部分 CASE、多变量比较、word 算术改写、未知调用或尚未取得的 E／T；也不授权跨宿主域移动观察。类型与总性证据不能因端点有限而省略。只有生产内核实际执行该汇聚且通过独立断言后，才能称相关子集已实现；固定规范预期暴露的差异仍须真实报红。


## 精确字面量与同族运算

业务 `number` 的精确字面量只有一种内部结构。去掉不影响数值的系数尾零；小数位归零时用整数节点表示，零也只有一个节点。源写法 `0.10` / `.1` 与 `1.0` / `1` 在进入 CASE 和相等判断之前就得到相同的结构，不等到显示时再处理。`x - x` 在两边已各自完成业务求值、取得同一个精确数值表达式之后可归约为零，前面发生的外部效果和异常不因此消失。此规则不表示接纳 IEEE 近似，也不宣称所有符号小数的 AC 汇聚已接入。

精确整数的 Add／Mul 分别属于两个不同的 AC 运算族。目标规范收集同类节点、按结构键排序后左折叠；加法零、乘法一及相邻可合并常量依据精确整数合同处理。文本 Add 必须由类型证据排除，浮点运算不得混入。该规范不自动授权分配律展开、因式分解或把 Sub 改写为 Add：每种更大范围改写必须规定一种统一方向，避免两个相反规则反复切换。

```text
normalize(add(b,a)) = normalize(add(a,b))
normalize(add(c,add(b,a))) = normalize(add(add(a,b),c))
normalize(mul(b,a)) = normalize(mul(a,b))
normalize(concat(b,a)) != normalize(concat(a,b))
```

右侧的 `a,b,c` 表示按统一结构键排列的同域符号，而不是由某个测试选择的字母顺序。排序键必须包含运算族、类型和稳定的语义名称；不能依赖函数注册先后、内存地址、HashMap 遍历顺序或输出中偶然分配的数字编号。

精确整数 Add／Mul 的 AC 汇聚接收具有总性证据的直接入口整数参数、整数字面量，以及由这些值构成的 Add／Sub／Mul／Neg 树；聚合常量使用任意精度整数。语言适配器把已证明的源类型交付为逻辑整数或显式固定字宽载体，math 不从 Java 类名推断业务值域。源语言算术的回绕仍须由 word 算子独立表达。技术观察根、字段／索引路径、E／T、未定型行值、调用、CASE、除法、浮点与 word 节点不能仅凭数字返型进入该规则。拒绝认证只保留原结构，不改变值域。

该子集具有独立的排列、括号、常量、幂等及负向验收；Java 源码主线另验证 Boolean 合取写法的汇聚，不将 Java 回绕算术当成精确整数 AC 的证明。扩大到其他有域整数值需要补齐总性或观察域证据。不能让测试端替内核归约，也不能将局部支持扩大为“任意等价公式唯一”。
