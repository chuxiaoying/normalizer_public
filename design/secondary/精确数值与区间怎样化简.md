# 精确数值与区间怎样化简

本专题细化《数学化简》、《业务至上》和《统一定形》的精确业务值规则。先有类型和取得域，再选择法则。

## 运算域决定可用的法则

| 语义域 | 可以使用的法则及前提 | 必须保留的区别 |
|---|---|---|
| 纯、总 Boolean | AND／OR 的交换、结合、幂等及布尔恒等式 | 部分值的取得条件必须由宿主保护；不能把部分 CASE 或 nullable Boolean 当作总 Boolean |
| 普通整数 Add／Sub／Mul | 精确数学整数，不由宿主存储位宽定义上限 | 业务可观察的回绕、窄化或饱和须按其合同表达，不能混入普通整数运算 |
| 有业务意义的显式回绕或近似数值行为 | 依据[业务至上的数值合同](../chapters/06-业务至上.md#bf-02-业务数值的精确合同)保留行为 | 不把显式位宽、有效舍入或可观察的 NaN 等混进普通精确运算 |
| 文本、序列及参数列表 | 使用对应的有序合同 | 不能因纯值而交换拼接、元素或参数的次序 |
| 引用 | 使用身份、别名及可观察字段合同 | 相同字段内容不意味着相同对象；内部重命名不能合并不同分配 |

普通整数中 `(MAX_i64 + 1) - 1 = MAX_i64`，中间结果不会被宿主 i64 的上限钳位。`x + 1 > x` 是精确整数定律；若协议规定序列号到上限后回卷到 0，这个比较在上限处为假，不能化成恒真。普通精确减法的差值与 0 比较可以改成比较两端；有回绕时则不能照套。

当 `x` 有总的精确整数证明时，`(x - c) + d` 与 `d + (x - c)` 只合并两个整数字面量偏移，不交换减法。差 `d - c` 为零时保留 `x`，为正时写 `x + (d - c)`，为负时写 `x - (c - d)`。不从这条规则推广到符号减法、部分观察、文本或回绕算术。

序列基数是精确自然数，push 令基数加一，不隐含固定字宽回绕。源语言 size／length 中实际可观察的位宽转换仍须保留。


逐行筛选中的标量项若在当前行的取得域内已证明为精确整数，也可与已取得的入口整数做字面量移项。精确整数数组的元素和类型已证的记录字段都可以提供证据。例如 `value + 2 == target` 归为 `value == target - 2`；附带的总布尔开关仍须成立。只变换同一行的谓词，不改变行身份，不跨行合并，不把未知表列、可空值或两种行绑定当成这个标量项。


## 当前取得域内的精确整数下界

只有当关系来源、谓词、投影及环境依赖在当前取得域都已定义时，才可采用普通计数非负的下界。用精确整数计算下界；不能仅凭数字返型推断未知调用、部分 CASE 或浮点运算的下界。

统一方向是把下界已足以判定的字面量比较归约为 Boolean 常量，再由原宿主消去死分支。只有下界时，`Count == 0` 仍未知；`1 + Count == 0` 在合法取得域内为 false。原取得条件和独立异常必须保留，例如 source 为 null 时的 NPE 不能一并删除。证据不足时不改写，也不能把当前域的证明写进无上下文的 normalize 缓存。

## 单一整数 subject 的谓词区间规范

当一个 Boolean／CASE 子树具有独立的总性与整数类型证据，且所有原子谓词只比较同一个稳定 subject 与精确整数字面量时，以最大互不相交整数区间的并集作为求证用的真集，不把完整区间边界强制打印成守卫。证据须来自入口／绑定的声明类型及宿主取得域；通用 `Number` 返型或未定型行值不能单独证明整数总性。例如 `vector<i32>` 的纯 fold item 具有 i32 整数域证据，不能擅自缩为 UTF-16 的 `0..65535`。

允许的组合为总 Boolean 常量、AND／OR／NOT，以及分支值均为总 Boolean 的完整 CASE；CASE 先按首个命中语义解释。原子比较限同一 subject 与整数常量的 `==`、`!=`、`<`、`<=`、`>`、`>=`。在精确整数域内以区间并、交、补计算真值集合，再合并相邻真区间。若有业务合同或当前取得域证明了固定上下界，求补、全域与空域判断都限于该域；不能仅因宿主存储类型有字宽就划定业务数值域；端点计算使用精确整数，不能在宿主整数溢出后决定区间。

代表选择见[统一定形](../chapters/08-统一定形.md#cf-07-整数守卫的代表)。例如整数 x 的真集若只排除 0，`x != 0` 比拆成两个区间更简单；若型域已知非负，`x <= 0` 的真集则只剩零。先把当前域算对，再选表示。例如精确整数 `x` 的 `x >= 1` 与 `x > 0` 都只需一次比较，按章规则选 `x > 0`；若 `x` 可以是小数，二者不是同一真集，不参加这个比较。

多值 CASE 的结果不是总 Boolean，不能把结果值直接套入上述 Boolean 真值化简。对于同一已认证整数 subject，可先用有限整数单元计算各臂的首命中有效域，再考虑合并同一结果的区间。保留原有的空域、取得域和正常或异常完成；部分 CASE 不补 ELSE。真集计算与选规范结构是两步：按《统一定形》比较候选的复杂度和结构，不能按源码中哪一组先出现裁决。

该方向只作用于同一宿主取得域内的合格子树。有限比较端点把整数域分成有限个真值恒定单元；完成并／交／补与相邻区间合并后，再次执行得到同一代表，因而停止。生成候选后还须按《统一定形》比较复杂度与结构；真集的计算不要求展开最终表达式。

不能把整数区间真集的证明套到 IEEE 浮点、可空或部分 Boolean、缺少 ELSE 的部分 CASE、多变量比较、固定字宽回绕或未取得的值。有限端点不能代替类型、总性或观察域的证据。


## 精确字面量与同族运算

精确的有限十进制以数值定形；不影响数值的尾零不产生另一种数学表示。若业务另有有效位数或格式观察，应保留那项观察。两个操作数已完成求值且为同一个精确数值表达式时，`x - x` 可归约为零；此前的外部效果和异常不因此消失。

精确整数的 Add／Mul 分别属于两个不同的 AC 运算族。目标规范收集同类节点、按结构键排序后左折叠；加法零、乘法一及相邻可合并常量依据精确整数合同处理。文本 Add 必须由类型证据排除，浮点运算不得混入。该规范不自动授权分配律展开、因式分解或把 Sub 改写为 Add：每种更大范围改写必须规定一种统一方向，避免两个相反规则反复切换。

```text
normalize(add(b,a)) = normalize(add(a,b))
normalize(add(c,add(b,a))) = normalize(add(add(a,b),c))
normalize(mul(b,a)) = normalize(mul(a,b))
normalize(concat(b,a)) != normalize(concat(a,b))
```

右侧的 `a,b,c` 表示按统一结构键排列的同域符号，而不是由某个测试选择的字母顺序。排序沿用[统一定形的共享结构键](../chapters/08-统一定形.md#cf-02-共享结构与顺序)：运算合同、类型和结构先比较，公开名字只用于最后的平局。不要求匿名值额外取名，也不用偶然的内部编号代替稳定身份。

加法和乘法的汇聚只处理已证明同域、已取得、纯且总的精确整数运算树。普通数值返型不能替代类型和取得域证明；证明不足时保留原结构。不能让测试侧替内核做归约，也不能把这个局部规则扩大成任意等价公式都有唯一表示。
