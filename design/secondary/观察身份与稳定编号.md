# 观察身份与稳定编号

先确立「这是哪一次观察」，再为它分配显示名。两个端口调用即使端口和参数相同，也可能成功、失败或分别取得不同回执，所以不能仅凭结构相同合并。反过来，给同一回执换两个局部变量名，也不会生成第二个回执。

- **P 和入口 E。** 公开参数名与位置来自入口合同；已有状态、表和字段由公开路径及快照身份定位。同名不等于同一来源，同路径在两个时刻取得的值也不能只凭路径合并。P/E 的公开名字只在结构和语义优先级打平以后裁决。
- **调用完成。** 按已确定的可观察动作顺序为调用分配回执编号，`$e_2` 先于 `$e_10`。编号来自已经绑定的动作，不按守卫、编号、源码文字或探索次序事后重排 S。互斥路径没有共同执行顺序；若需要稳定地展示已经证明互斥的记录，只给序列原本无法比较的记录确定展示次序，不制造执行先后，不覆盖既有依赖。现有合同不能区分两个动作身份时，报告缺口，不能临时拿不稳定的编号代替。
- **派生绑定。** 保留来源、守卫和取值之间的真实依赖。等价输入在保留依赖的前提下交付一致的定义、编号与引用；用[统一定形的共享结构键](../chapters/08-统一定形.md#cf-02-共享结构与顺序)识别稳定来源，不让显示名参与分配自身。
- **平局要能解释。** 真正相同且可以共享的纯定义可以共用；仍是两次独立观察的绑定，要依靠调用位置、快照身份或有效条件区分。不能靠线程探索顺序打破平局，也不能省掉某次动作来消除平局。

小例子：先 `check(x)` 再 `check(x)`，如果两次都执行，必须有两个调用记录和两个不同回执。改动局部接收变量名，编号不该变；交换两个可观察调用、或把第二次改成只在第一次成功后才发生，则必须保留相应的顺序和条件区别。

## 内部名字与入口快照

计算是否合法依赖 IR 中已确认的符号来源，而不依赖显示名。数学层的已绑定整型输入不会因为名字的前缀像 E、T 或 heap 就变成部分值；真正的回执和递推结果仍需自己的取得域证据。

已取得的两个直接对象参数仍按引用身份判断。交换等值比较的两端不改 P 的参数位置，不改变两次取得的先后，也不把相同内容或同名对象视为同一实例。结构比较须使用声明的参数来源。

E／T 的内部标识与所有 R／E／S／T／throws 引用必须一致重命名。观察的依赖、取得条件、调用身份和次数都属于语义，不能为排序改变。

在已证明可交换的表达式位置，匿名观察按其编号的数值排序，例如 `$e_2` 排在 `$e_10` 前。该比较不改变 S 的调用顺序。编号较小不等于在所有分支都更早发生。同一个入口快照可在一个分支中于调用前读取，在另一个分支中于调用成功后读取。应核对实际依赖和环，而不是仅比较编号。

稳定排列只可移动已证明相互独立且可交换的项目；真实调用顺序、集合顺序、CASE 首个命中以及部分值取得域必须保留。不得仅以“没有显式写入”为理由移动可能受环境、时间或调用身份影响的观察。

内核的一致重命名与依赖感知的稳定排列需要单独验收。测试不能忽略编号、排序整个 S、删除取得条件或对名字做任意对应，来替代这项内核职责。

已经取得且有公开名字的入口状态字段，以公开的 E 根路径和字段路径参与结构比较。比如 `zebra.units + amber.units` 与反向源码可归到同一加法结构；`zebra.units - amber.units` 不交换。这里只规范数学表达式，不排序真实调用。

### 随执行取得的环境值

按真实取得确定动态环境值的身份，不和端口完成回执混用。每次执行到时钟操作都产生一次独立观察，即使所得值相同，也不能共用身份。只有在观察实际发生的条件成立后，才可取用该值。已发生的环境读取即使从 R 公式消去，也不因此消失。

时钟与外部写入之间的相对次序也是观察。不同路径的动作只在各自发生条件下保留，不能靠一个共同的显示顺序制造额外动作。写后重读取到的新表快照参见[关系读取的快照边界](关系读取的快照边界.md)。

## 派生绑定的边界

有序纯递推先建立 T 的定义依赖。已闭合定义以输入来源、规范初值和更新体作结构比较；只有取得条件一致、且能在原取得域内安全共享的等价纯定义才复用。不能为了共享把只在某个守卫生效的定义提到守卫外。同一规则下的独立选择、回执或身份不同的读取不因候选相同而合并；同一次选择的多个字段必须用同一个绑定。警惕依赖环与条件取得域。实例见[有序折叠](../examples/topics/unified-canonical-form/java-pure-fold-definitions.md)、[选择与递推](../examples/topics/unified-canonical-form/java-member-choice.md)及[整条报价](../examples/topics/collections/java-independent-choice.md)。


有序递推可引用进入递推前已经取得的局部值。引用不得跨取得域，不能把动态读取或外部回执搬进更新体，也不能把公开来源和递推局部绑定混为一谈。R 重复引用同一个 T 仍只引用同一份定义；不能把定义中的 CASE 当成 R 中重复出现的 CASE。

## 条件引用的身份比较

在两个操作数都已经按源顺序求值后，入口快照取得的引用与本次执行中新分配的对象一定不相等，可直接折叠为常量。依据是来源与分配证明，不是私有堆编号的大小；两个入口引用仍可能别名。 已经取得一个完整条件引用和一个明确来源的引用后，可按原先的分支条件逐臂比较身份，不重跑原分支，也不比较对象字段。若替换分支取得另一个入口引用，仍保留两入口引用可能相同的判断。 替换为 null 的分支依据另一端已声明的可空性比较：非空入口不等于 null，可空入口必须保留其真实 null 判断。 若两端都是已取得的完整身份分区，等于和不等于可以利用交换律。外层比较仍使用《统一定形》的共享结构键，比较完整操作数，不能只看两端的守卫而忽略各臂引用的身份。分区内部仍保持各自首命中，原源码的取值、状态和调用顺序不移动。
