# 观察身份与稳定编号

先确立「这是哪一次观察」，再为它分配显示名。两个端口调用即使端口和参数相同，也可能成功、失败或分别取得不同回执，所以不能仅凭结构相同合并。反过来，给同一回执换两个局部变量名，也不会生成第二个回执。

- **P 和入口 E。** 公开参数名与位置来自入口合同；已有状态、表和字段由公开路径及快照身份定位。同名不等于同一来源，同路径在两个时刻取得的值也不能只凭路径合并。P/E 的公开名字只在结构和语义优先级打平以后裁决。
- **调用完成。** 按已确定的可观察动作顺序为调用分配回执编号，`$e_2` 先于 `$e_10`。编号来自已经绑定的动作，不按守卫、编号、源码文字或探索次序事后重排 S。互斥路径没有共同执行顺序；若需要稳定地展示已经证明互斥的记录，只给序列原本无法比较的记录确定展示次序，不制造执行先后，不覆盖既有依赖。现有合同不能区分两个动作身份时，报告缺口，不能临时拿不稳定的编号代替。
- **派生绑定。** 先建立来源、守卫与取值之间的依赖图，再做稳定拓扑排列。同一批可发布的绑定用规范类型、运算、依赖来源和结构键比较，不用临时编号或内存地址。依赖来自此前已绑定的公开来源或其结构键，不通过显示名自我定义。
- **平局要能解释。** 真正相同且可以共享的纯定义可以共用；仍是两次独立观察的绑定，要依靠调用位置、快照身份或有效条件区分。不能靠线程探索顺序打破平局，也不能省掉某次动作来消除平局。

小例子：先 `check(x)` 再 `check(x)`，如果两次都执行，必须有两个调用记录和两个不同回执。改动局部接收变量名，编号不该变；交换两个可观察调用、或把第二次改成只在第一次成功后才发生，则必须保留相应的顺序和条件区别。

## 内部名字与入口快照

计算是否合法依赖 IR 中已确认的符号来源，而不依赖显示名。数学层的已绑定整型输入不会因为名字的前缀像 E、T 或 heap 就变成部分值；真正的回执和递推结果仍需自己的取得域证据。

已取得的两个直接对象参数（例如 `left` 和 `right`）仍按引用身份判断，无论源码与入口参数的声明先后如何，`left == right` 与 `right == left` 都以公开参数路径比较并汇到 `left == right`。路径排序不改 P 的 position，不改变两次取得的先后，也不把相同内容或同名对象视为同一实例。这个起步合同不声称所有 heap 路径或 T 编号已经接通。

E／T 的内部标识与所有 R／E／S／T／throws 引用必须一致重命名。观察的依赖、取得条件、调用身份和次数都属于语义，不能为排序改变。

在已证明可交换的表达式位置，匿名观察按其编号的数值排序，例如 `$e_2` 排在 `$e_10` 前。该比较不改变 S 的调用顺序。编号较小不等于在所有分支都更早发生。同一个入口快照可在一个分支中于调用前读取，在另一个分支中于调用成功后读取。应核对实际依赖和环，而不是仅比较编号。

稳定排列只可移动已证明相互独立且可交换的项目；真实调用顺序、集合顺序、CASE 首个命中以及部分值取得域必须保留。不得仅以“没有显式写入”为理由移动可能受环境、时间或调用身份影响的观察。

内核的一致重命名与依赖感知的稳定排列需要单独验收。测试不能忽略编号、排序整个 S、删除取得条件或对名字做任意对应，来替代这项内核职责。

已经取得且有公开名字的入口状态字段，以公开的 E 根路径和字段路径参与结构排序。例如 `zebra.units + amber.units` 和反向源码均归到 `amber.units + zebra.units`；两个记录仍各自指向原状态字段，`zebra.units - amber.units` 不交换。这里只规范数学表达式，不排序真实调用，也不承诺未命名观察已可跨图重编号。

### 独立入口快照的规范编号

规范对以下受限子集要求稳定 E 命名：文档没有调用、索引调用族、内部选择或 T 定义；所有实际使用的入口字段观察具有同一直接入口对象身份和完全相同的获取条件。对象身份须是 Heap 中的入口引用，其显示名必须对应合同中 Object 类型的参数；字段类型须来自合同的 heap_fields。获取条件只能依赖已声明入口参数及闭合值，不含行绑定、E 或 T 依赖。

满足这些前提时，字段按 `(field,type)` 的稳定结构键排列，依次命名为 `$e_0,$e_1,…`，E 列表使用相同的数字编号顺序；R、获取条件、S 和 throws 中的引用统一替换。字段、观察符号及原身份编号必须唯一；重复字段不以排序为由合并。这个计划只改变数学入口快照的名字与呈现次序，不移动运行时读取，不改变获取条件，不授权交换 getter、volatile 读取或外部环境访问。

前提不满足时保留既有编号和观察次序，继续执行因果、定义域与作用域检查。带调用或不同获取域的 E、多个对象根、T 的跨全图依赖重编号尚未纳入该计划；不能把此局部规则宣称为所有等价程序的唯一命名，也不能在测试端忽略名字来补齐缺口。


## 派生绑定的边界

有序纯递推先建立 T 的定义依赖。已闭合定义以输入来源、规范初值和更新体作结构比较；只有无条件、无副作用且可安全共享的等价纯定义才复用。同一规则下的独立选择、回执或身份不同的读取不因候选相同而合并；同一次选择的多个字段必须用同一个绑定。警惕依赖环与条件取得域。实例见[有序折叠](../examples/topics/unified-canonical-form/java-pure-fold-definitions.md)、[选择与递推](../examples/topics/unified-canonical-form/java-member-choice.md)及[整条报价](../examples/topics/collections/java-independent-choice.md)。

## 条件引用的身份比较

在两个操作数都已经按源顺序求值后，入口快照取得的引用与本次执行中新分配的对象一定不相等，可直接折叠为常量。依据是来源与分配证明，不是私有堆编号的大小；两个入口引用仍可能别名。 已经取得一个完整条件引用和一个明确来源的引用后，可按原先的分支条件逐臂比较身份，不重跑原分支，也不比较对象字段。若替换分支取得另一个入口引用，仍保留两入口引用可能相同的判断。 替换为 null 的分支依据另一端已声明的可空性比较：非空入口不等于 null，可空入口必须保留其真实 null 判断。 若两端都是已取得的完整身份分区，等于和不等于可以利用交换律，按两组分支的条件结构键选择外层比较顺序。分区内部仍保持各自首命中，原源码的取值、状态和调用顺序不移动。
