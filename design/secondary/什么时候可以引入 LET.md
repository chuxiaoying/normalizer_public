# 什么时候可以引入 LET

`LET` 给单个 PERS 输出表达式里的重复结构取名，不新增一次执行、读取或外部观察。它是定形规则，不是输出时的排版开关。

## 候选条件与整值比较

从同一个已经完成数学化简的值收集候选，不随该值先前写成内联还是局部绑定而变。确认既有绑定合法后，按其表示的表达式统计出现次数，不能按内存里是否共享节点计数；不合法的绑定不靠文本内联隐藏。在单个输出值内，按下列条件找候选并比较整值，不逐个强制提取：

1. 被绑定的子式本身含 CASE，且规范化后仍出现至少两次。仅仅处在外层 CASE 里，或重复普通算术／无 CASE 的聚合，都不满足。
2. 所有被共享的引用处于同一安全域。不能跨 R、不同 S 动作、外层守卫、行绑定或回执的取得边界。候选按安全域核对：受不同守卫保护的引用不得纳入同一个替换；本身满足条件的同域引用仍单独比较复杂度。
3. 定义及其依赖都已取得。绑定不引起额外求值，不改变调用、读取、异常、写入的顺序和次数。
比较的是包含绑定和引用的最终整值。计数口径见[统一定形](../chapters/08-统一定形.md#cf-09-let-的整值比较)：严格小于内联基准才提取，持平时保持内联。不能为保留一个 LET 重新引入已化掉的重复。

同一输出值中有多个合格候选时，按一级规则比较最终整值。例如把同一大子式提为定义后，其中的小 CASE 可能只剩一次，不能再按内联时的出现次数计算降幅。同一个值的内联与安全绑定变体必须得到同一规范形，固定挑选顺序本身不能替代这条验收。定义按依赖顺序发布；互不依赖的定义按共享结构键排序，最后在该输出值内依次命名为 `$l_0`、`$l_1` 等。源码的临时变量名和遍历顺序都不参与命名。


## 普通标量也适用

例如 `C = CASE WHEN enabled THEN a ELSE b END`，三个值都来自本次入口。对于 `(C + shift) * (C - shift)`，单独外提任一操作中的 CASE 不减少条件臂，反而把该操作复制到两臂。保留这两处在同一安全域中的 CASE；提取一个 `LET` 可以少写一份条件臂，因此必须提取。相比之下，若整个表达式只是 `C * C`，先按同一守卫同步取臂就只剩一个 CASE，没有重复值需要再提取。若还有一处受外层守卫保护，不把它纳入这组共享；其余引用仍按同域、已取得和降复杂度条件独立判断。

## 一正三反

下例是已取得数组的同一个纯聚合，在一个 R 中乘以自身。只展示 R：

```yaml
R: |-
  LET $l_0 = COALESCE(SUM(SELECT value + CASE WHEN enabled THEN extra ELSE 0 END FROM values), 0)
  IN $l_0 * $l_0
```

| 变化 | 预期 |
| --- | --- |
| 改变源码局部变量名，或用两段等价写法得到同一个聚合 | 仍提取一次，同一输出里仍叫 `$l_0`。 |
| 只返回一次聚合，或者先经数学化简只剩一次引用 | 不输出 LET。 |
| 两次引用的是没有 CASE 的聚合 | 即使有重复，也按本规则内联。 |
| 多出一次只在外层守卫成立时才取得的引用 | 不做跨守卫的整值替换，也不提早取得该值。 |

测试仍比较完整 PERS。不能由测试侧临时内联或提取，也不能为两种写法各接受一份 `expected`。
