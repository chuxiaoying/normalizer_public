# 完整二分 CASE 怎么选方向

两个等价的写法：

```text
CASE WHEN p THEN left ELSE right END
CASE WHEN NOT(p) THEN right ELSE left END
```

这里的 `p` 是已经取得的总布尔值。只翻转条件并同时交换两臂，就能保留每个结果的有效条件。若变形会挪动求值、扩大回执读取范围或改变异常条件，就没有第二个合格候选。部分 CASE 不补 ELSE；多臂 CASE 不按守卫排列，因为它按首个命中取值。

**先化简，再选向。** 能删不可达臂、能合并两臂同值时优先化简。不存在更简单候选且两种方向复杂度相同时，把守卫表示成「基准谓词 + 取反标志」，由同一候选生成器得到这一对，再选不取反的方向。直接布尔值以自身为基准；已证互补的精确比较，先固定操作数方向，再确定基准比较：`>`／`<=` 取 `>`，`<`／`>=` 取 `<`，`==`／`!=` 取 `==`。互补关系不能证明时，不用这条换向规则。两种输入以及已经选定的结果，都必须回到同一对候选。

对普通二分值，**不因为某一臂是 `null` 就另改方向**。例如 `CASE WHEN p THEN null ELSE value END` 和 `CASE WHEN NOT(p) THEN value ELSE null END` 都收成前者；`p` 为真时得到 `null`。只取反却不换两臂的写法改变业务结果，必须通过负例排除。

对有保护的读取，要核对有效域而非空值位置。例如 `hasReply` 为真才允许读取 `reply.ok`。不论用哪个方向表达，都须保留这个限制；不能把它改写成允许任意重排的布尔项。精确计数的 `count > 0` 与 `count <= 0` 可以互补；可能出现 NaN 的浮点比较不能凭拼写套用同一推论。
