# 仓库整理与验收原则

## 先按实际覆盖判断存废

- 以仓库登记的正式测试实际执行结果为准。没有执行到的仓库自有代码，默认按死代码处理；它能编译、有静态调用方、写在文档里、预期将来有用，均不是保留理由。
- 判断保留的证据要落到入口、实现和可执行分支。仅导入模块、初始化声明或发现一个调用点，不等于完整功能已被测试。平台不符、插桩缺失或采集范围不明时标记为待确认，不能把未测量误写成覆盖或已证实可删。
- 确需保留的未覆盖工具或路径，先明确用途和最小路径范围，由仓库负责人签字；不要把设计阅览器、调试或性能工具的例子扩张成整个目录的自动豁免。如果一个可复现的反例证明删除会破坏已确认合同，按[种子覆盖模型](../../design/examples/README.md#覆盖模型)回到主题级设计与测试：系统补齐主题，再修复内核、验证并重采受影响范围的覆盖，之后继续清理；全量收口按下文执行。仅在合同边界不明确或需要工具豁免时提交负责人裁决；不要为保住单个分支编造临时预期。
- 代码之外的文档、配置、样例、发布材料和必要声明，以现行用途为准；旧版本可由 Git 历史追溯。只有明确的合规或发行追溯义务才单独保留必要材料，不为此保留一个已经退役的应用。
- 记录每项保留的测试入口，或签字的最小范围、用途和复审条件。一次性的原始覆盖数据、候选清单和迁移日志留在仓库外，不作为维护文档提交。

若反例暴露现有合同的缺口，先划定主题，独立列出输入域、边界、能改变结果的组合和反例，区分已验收、不支持和待裁决部分。不要仅凭单点反例给代码补票：设计和预期定好后修复内核，跑完整基线，再从同一提交重采受影响的覆盖。其余主题可独立清理，不等待补齐所有潜在主题。

## 已签字的覆盖例外

| 保留范围 | 用途 | 复审条件 |
|---|---|---|
| [设计区阅览器](../apps/design-reader/README.md)的启动、浏览和离线导出 | 人工评审设计、查看相关测试，不参与 PERS 计算 | 更换评审入口或停止使用时复审 |
| 现有 CLI 的[调试日志](normalizer-debugger.md)、执行计数和[性能采样](performance-risk-response.md) | 定位归一化阶段、分支与耗时；默认关闭 | 改变输出接口、新增诊断入口或旧工具不再使用时复审 |
| 拒绝非法或超出已发布合同的输入所必需的唯一入口检查 | 在进入模拟执行前明确拒绝、不给出 PERS；不要求用业务用例逐条触发 | 输入合同改变，或已有一个仍执行的检查提供同等准入保证时复审 |

只有表中作用明确的路径例外，不扩张到旧脚本、未实现的性能计划或其他不在正式测试里的功能。

唯一入口检查应逐项记明拒绝的输入、检查所属入口，以及没有其他检查可替代的依据。不要为了让覆盖率命中而新增业务种子。若入口已经保证某个静态条件，内核不再保留重复兜底；合法输入仍可能产生的运行时异常不属于这个覆盖例外。

## 运行时覆盖与待补回归的 100% 收口目标

- 固定当前正式回归作为基准。覆盖由这套用例实际执行得到；不为凑覆盖补用例、不放宽预期、不注入专为覆盖而执行的代码。
- Rust 同时报分支结果计数与源码区域计数，JavaScript 报 V8 执行区间。用语法边界核对计数坐标；同一行有多个分支时，以分支体或结果的可核验计数为准。插桩未覆盖到的自有运行时代码单列待核验，不能按已覆盖或不适用处理。
- 单列原始覆盖、适用范围内实际命中、待补回归、已签字例外和未判定项。只有能对到具体位置并有明确签字依据的例外才从适用分母剔除；既有例外不扩张到相邻逻辑。不同计量口径不相加。编译器聚合计数无法与源码项目一一对应时，分别提供原始覆盖与源码对账，不用两者作混合算术。
- 现行设计要求、能给出可达输入和独立预期、但固定基准没跑到的行为，登记为待补回归；它仍是未覆盖，不等于豁免。先记录所属设计、入口、能区分正误的观察以及对应零命中项，不提交未裁决的新用例，不从遗留实现反造需求。无论主题分成几个用例，同一覆盖项只计一次。
- 请求签字时记录源码位置、触发条件、删除影响和复审条件；未获签字前计入分母。只有最终提交的测量范围已核清、正式回归通过，且适用范围内「实际命中 + 已登记待补」等于分母，才能宣告对账 100%。只有待补为零且适用项均实际执行，才称为实际覆盖率 100%。

### 已有正式对照

- **关系查询标量的 `!=`**：[`PositiveCount.count` 变体](../../tests/e2e/variants/java/collections/collection-filter/PositiveCount.count.yaml)使用 `where row.amount != 0`，断言排除零并保留原账户筛选、聚合及空结果默认值的完整 PERS。该场景不是待补用例；运行时命中仍以当前提交的实际覆盖报告为准。

- **关系谓词与可选子句**：正式对照已核验小写 `is null`／`is not null`、无 `where` 的连接计数、无 `as` 的 UPDATE 表名绑定，以及无 `where` 的全行 UPDATE。依[关系指令](../../design/secondary/关系指令的统一写法.md)分别保留输出、行数与写入效果。
- **计数的精确下界**：按[可空关系列种子](../../design/examples/topics/relational-data/java-null-semantics.md)，`count <= -1`、`1 + count == 0` 恒假，`count > -1`、`count >= 0` 恒真。正式对照保留表和筛选所依赖的 P/E，不把带未知偏移的表达式错判为常量。
- **已初始化 long 的有限循环**：正式[常量循环种子](../../design/examples/topics/loops-and-termination/java-constant-bound.md)有赋值式 `long` 局部计数器对照，结束后仍观察末次步进。
- **TypeScript 局部元组的空分支**：正式[回执元组种子](../../design/examples/topics/collections/typescript-tuple-slots.md)验证命中空分支后继续执行剩余语句，保留原返回观察。

- **合法 Java 词法边界**：正式[声明种子](../../design/examples/topics/basic-contracts/java-invalid-declaration.md)验证 `intValue`、`int_value`、`int$value` 在括号里是普通名称，并验证文件末尾没有换行的行注释。[业务数值种子](../../design/examples/topics/number-domain/java-business-number.md)独立验证最小负整数边界带浮点后缀时仍按精确业务数解释。

- **计数下界不足时保持比较**：正式用例验证 `count < 3`、`count > 3` 和 `count >= 3` 必须保留表、筛选和原参数；`3 > count` 与 `count < 3` 定形相同。加上符号未知的偏移不继承 COUNT 的下界。

- **数组首项的分支条件**：正式[首项种子](../../design/examples/topics/collections/java-empty-singleton.md#首项参与比较越界仍先发生)同时验收两种比较方向、正常完成的最大值以及空数组的越界。带异常的读取不是带默认值的纯取首项。

### 待补回归（不属于覆盖例外）

- **有序折叠的空提交前缀与隐式依赖**：沿[提前退出种子](../../design/examples/topics/loops-and-termination/java-break-continue.md)把首个可处理索引移到终止界之后，断言初值不变；沿[纯折叠定义](../../design/examples/topics/unified-canonical-form/java-pure-fold-definitions.md)让 R 只引用后一项，断言 T 仍按依赖顺序保留前项。
- **关系去重并集的来源错误**：依[投影并集种子](../../design/examples/topics/relational-data/sql-projected-distinct.md)，分别提供未绑定来源与并集合同不接受的过滤来源，两者必须明确区分且均不产生 PERS。
- **Java 名称、声明和分派**：在已支持的源码场景中覆盖 `$` 和关键字前缀标识符、受保护和 `strictfp` 的方法、`final` 类、`transient` 字段、普通 `Object` / `java.lang.Object` 和 `java.lang.String` 声明，以及多接口的已声明方法分派。另覆盖右操作数为文本的 `null + "s"`，R 为 `"nulls"`。不据此扩张可空引用类型或默认接口方法的合同。
- **独立 JavaScript 无源码调用与适配器启动失败**：按[无源码边界](../../design/chapters/第四章%20·%20AI%20救赎.md)，同步直接调用与 `await` 都不得把普通参数的方法变成 external，分别保留 `:call` 和 `:await` 的失败位置且不输出 PERS。适配器内核若无法启动，工程验收用隔离的可执行文件路径重现启动失败，断言退出非零且无 PERS，不伪造业务种子。
- **证明预算和缓存边界**：按[性能治理](performance-risk-response.md)，用同一份合法 Java 嵌套条件和异常源码，分别降低证明节点上限与缓存条目体积上限，覆盖拒绝证明及跳过过大缓存项。仍要得到相同 PERS；性能探针不能把近似答案变成成功，也不计作已经补齐的正式回归。
- **布尔 CASE、整数穷尽和相消**：按[统一正则规范](../../design/chapters/第八章%20·%20统一定形规范.md)，`(p ? q : !q) ? true : p` 归约为 `p OR NOT(q)`；`x<0`、`0<=x<=5`、`x>=6` 穷尽整数域，不残留不可达尾臂。把 `x>0?x:x+2` 的值减去 `x`，结果应为 `x<=0?2:0`，不能残留 `x-x`。最后一例已发现实现缺口，不把未化简结果当预期。
- **关系连接和 LET 输出**：在[内连接计数](../../design/examples/topics/relational-data/java-join.md)中给两表匹配追加独立布尔开关；为假时结果为零，为真时保留原连接和重复行计数。按[CASE LET 种子](../../design/examples/topics/expression-simplification/java-case-let-extraction.md)区分入参数组、E 状态数组、借用记录字段和 CASE 内取反；检查完整 PERS 中重复子式究竟提取为 LET 还是保持内联，不能把未确认的读取条件冒充已取得的值。
- **状态写入、独立字段与可空内容**：在[多次写后读](../../design/examples/topics/state-and-aliasing/java-multi-write-read-order.md)中分别验证同一对象的相邻字段、不同声明对象的同名字段。写入进 S，读取不得混到另一字段或对象；空值声明则沿[可选字段](../../design/examples/topics/objects-and-types/java-optional-field.md)断言完整 R 中保留 `null`，不省字段。
- **合法接收者与身份**：按[多态分派](../../design/examples/topics/objects-and-types/java-polymorphic-dispatch.md)验证显式 `this.field` 读实际分派到的对象；按[内容与身份](../../design/examples/topics/objects-and-types/java-structural-vs-identity.md)验证非空入参与已绑定为 null 的局部变量不相同。比较不创造外部身份或改变 P。
- **已取得值相消但不抹掉效果**：纯参数、不可变外部回执字段、第二次采集的完整回执分别计算同值减自身，R 都应归零。参数版不新增 S；两次采集均保留；[原子写入](../../design/examples/topics/relational-data/java-batch-write.md)后取时钟只发生于成功路径，仍保留 SQL、时钟及异常完成。当前参数和回执字段版本还有未化简结果，不能把它们当作预期。
- **多臂与部分 CASE、精确值取负**：六个标量分支进入同一运算时仍依首匹配顺序，部分 CASE 保留独立抛出完成而不补默认值。局部数组首项不能套用 COUNT 的规则，空数组仍抛出；已绑定的精确小数可以符号化取负，不新增舍入规则。
- **逆序关闭的规范排序**：沿[按相反顺序关闭嵌套任务](../../design/examples/topics/state-and-aliasing/java-lifo-release.md)只重命名两个等长的公开参数名，使共同长度的 LEAST 不需要交换操作数。比较方向必须同时换符号，反向索引仍以打开序列为基准；完整匹配返回真、部分匹配返回假、位置不符抛异常，S 始终为空。
- **只读 Vector 长度的适配边界**：[统一正则规范](../../design/secondary/有序序列的长度与首项.md#已取得-typed-vector-长度的自然域)定义自然数长度及正长度与零长度的唯一方向。合法的 `>= 0`、`!== -1` 和 `<= 0` 变体目前在独立 JS 入口被拒绝，尚未命中对应内核分支；记录为待修，不把拒绝变成规范答案。
- **外部结果和适配信封的拒绝**：分别验证闭合适配输入过大、来源路径含控制字符，以及 Java 外部结果声明为无闭合字段合同的接口或空类。拒绝应明确且不产生 PERS；用已有可投影记录做正向对照，保留原外部调用。对合法 JavaScript 文件扩展名和标识符的限制另行核对，不能根据当前拒绝直接写成预期。
- **关系输入和局部栈的变化轴**：依[关系代数合同](../../design/chapters/第五章%20·%20关系代数：让%20SQL%20和集合运算一起化简.md)，分别覆盖连接缺失／过滤右表、并集的来源形状、已声明列与投影、可空列的绑定、首项／聚合的数据来源及查询局部名冲突。未被观察的文字或已绑定标量投影不能成为虚构数据库列。沿[栈种子](../../design/examples/topics/state-and-aliasing/java-lifo-release.md)覆盖三个绑定、连续操作、不同记录载体以及不参与匹配的额外字段。拒绝应精确说明缺少哪项合同，正向场景保留独立完整 PERS。
- **未调用方法的合法混合表达式**：同一个已通过源码准入的类可以有未调用的 `Object` 方法，条件两臂分别为 Boolean 与 number；选定的独立普通数值入口仍应得到完整 PERS。不据此宣称能将该混合值直接从业务入口投影。
- **适配工程的状态与签名完整性**：经现有测试 CLI 的工程合同验收，分别覆盖状态目标缺字段、状态种类或来源声明错误、通过标量访问子字段、将整条记录当标量、外部类型声明循环及参数位置重复／缺失。拒绝不能产生 PERS；不将这些无效适配工程伪装为可编译业务种子。

## 好找、好改、好验证

- 遇到疑似 legacy 模块，按能力而不是整模块判断。已命中的能力先辨认当前消费者和语义合同，补齐独立验收，迁入承担同一职责的新架构；切换正式消费者并核对旧入口全量行为后，才一起删除旧实现、兼容旁路和过渡接线。命中不构成保留旧架构的理由，未命中也不构成误删仍有合同义务的能力的理由。
- 每项能力只有一条正式实现路径；转换、校验、聚合、兼容层必须各有独立职责。相同规则、默认值和格式有一个权威定义。测试预期依然从源码和合同独立推导。
- 设计、合同、生产实现、工具、验收和使用说明按长期职责归位。正式入口、内部工具、实验及历史有可辨认的边界。提交不包含本机配置、缓存、构建产物或一次性证据。
- 代码、命令帮助、示例、文档和实际支持范围同步改变；设计目标不写成已交付功能。核心术语和失败阶段一处定义，故障能追溯到阶段、入口和原因，诊断不混入正式 PERS。
- 优先削减改动波及面，用可执行检查而非人工记忆守住易错边界。干净检出在声明的工具链和依赖条件下可构建、可验证；性能敏感操作的约束和证据可复现。

## 如何验收变更

以验收基线中的具名案例核对完整 PERS 和明确的拒绝结果，拒绝时不产出 PERS；同时检查独立预期、预处理补丁、链接和正式命令。分开提交纯整理、缺陷修复和合同变更。发现现行合同可能变化，先裁决；清理不改 expected 来换绿，不降级或删除合法用例。新增覆盖应验证可说明的行为，不把通过数或覆盖百分比当作质量目标。

### 分批定向验收与全量收口

- 清理期间，用最近一次通过的全量正式回归与覆盖报告，在未受后续变更影响的范围内挑选候选。先核对采集提交、正式入口和具名用例，以及工具链、插桩和配置，再核对候选的实现、调用/准入路径、种子和测试未影响原覆盖判定。旧报告只用于筛选，不证明新提交通过，也不能替代尚未采集的覆盖。
- 每批先界定改动影响的入口、实现和具名案例。对可明确界定范围的批次，运行相应的正式 CLI 定向验收及受影响的工程检查；通过后可单独推送检查点，不必每次重跑全量。推送时记录验证提交、定向范围、结果、覆盖证据和待全量项，明确区分“定向已通过”“沿用旧覆盖筛选”“全量已通过”。拒绝诊断和完整 PERS 断言不能减弱。
- 新增或修改种子、改变内核路径可达性等，必须在该候选提交对受影响范围重新采集正式测试覆盖，再按新证据判定路径存废。只见入口命中、用混合区间中的一段命中替代整项，或改变用例集合后套用旧覆盖结论，都不算验收。若影响边界证明不了，或无法按正式入口完整覆盖受影响范围，须在该批推进前先跑全量。
- 当负责人确认现有正式回归已足以作为一轮清理依据，默认同批删除能精确对应当前实现的未命中代码，不为每一项额外证明用途或补业务用例。保留签字例外和实际命中的代码。旧坐标失配或混合区间先对齐当前边界，不把命中邻支一起删除。可按需要修正编译，再统一回归；若失败，只恢复或修正回归证实需要的行为，不改预期换绿。
- 所有计划清理项处理完毕后，对最终候选提交跑一次带覆盖的全量正式回归，核对完整基线、最终覆盖和签字例外。这一趟同时产出回归及覆盖结果，不再另跑一遍同内容的普通全量回归；工程检查和内核单测等职责不同的检查仍按验收要求执行。最终全量未通过，不宣布收口。

- 默认复用同一提交的结果。若验收期间合入的变化只涉及不被构建、回归和种子装载读取的文档，可在逐项证明确切的构建、用例、种子、预期、工具及配置快照未变后复用已有业务与覆盖结果。记清已测试的提交、最终提交和两者实际差异，只补跑受影响的文档及工程检查；不要把复用的业务验证写成在新提交重新执行过。凡改动测试读入的种子、配置或文档夹具，不适用本例外。
