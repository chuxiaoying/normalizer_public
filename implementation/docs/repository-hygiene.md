# 仓库整理与验收原则

## 先按实际覆盖判断存废

- 以仓库登记的正式测试实际执行结果为准。没有执行到的仓库自有代码，默认按死代码处理；它能编译、有静态调用方、写在文档里、预期将来有用，均不是保留理由。
- 判断保留的证据要落到入口、实现和可执行分支。仅导入模块、初始化声明或发现一个调用点，不等于完整功能已被测试。平台不符、插桩缺失或采集范围不明时标记为待确认，不能把未测量误写成覆盖或已证实可删。
- 确需保留的未覆盖工具或路径，先明确用途和最小路径范围，由仓库负责人签字；不要把设计阅览器、调试或性能工具的例子扩张成整个目录的自动豁免。如果一个可复现的反例证明删除会破坏已确认合同，按[种子覆盖审查](../../design/seed-coverage-audit.md)回到主题级设计与测试：系统补齐主题，再修复内核、验证并重采受影响范围的覆盖，之后继续清理；全量收口按下文执行。仅在合同边界不明确或需要工具豁免时提交负责人裁决；不要为保住单个分支编造临时预期。
- 代码之外的文档、配置、样例、发布材料和必要声明，以现行用途为准；旧版本可由 Git 历史追溯。只有明确的合规或发行追溯义务才单独保留必要材料，不为此保留一个已经退役的应用。
- 记录每项保留的测试入口，或签字的最小范围、用途和复审条件。一次性的原始覆盖数据、候选清单和迁移日志留在仓库外，不作为维护文档提交。

## 已签字的覆盖例外

| 保留范围 | 用途 | 复审条件 |
|---|---|---|
| [设计区阅览器](../apps/design-reader/README.md)的启动、浏览和离线导出 | 人工评审设计、查看相关测试，不参与 PERS 计算 | 更换评审入口或停止使用时复审 |
| 现有 CLI 的[调试日志](normalizer-debugger.md)、执行计数和[性能采样](performance-risk-response.md) | 定位归一化阶段、分支与耗时；默认关闭 | 改变输出接口、新增诊断入口或旧工具不再使用时复审 |
| 拒绝非法或超出已发布合同的输入所必需的唯一入口检查 | 在进入模拟执行前明确拒绝、不给出 PERS；不要求用业务用例逐条触发 | 输入合同改变，或已有一个仍执行的检查提供同等准入保证时复审 |

只有表中作用明确的路径例外，不扩张到旧脚本、未实现的性能计划或其他不在正式测试里的功能。

唯一入口检查应逐项记明拒绝的输入、检查所属入口，以及没有其他检查可替代的依据。不要为了让覆盖率命中而新增业务种子。若入口已经保证某个静态条件，内核不再保留重复兜底；合法输入仍可能产生的运行时异常不属于这个覆盖例外。

## 好找、好改、好验证

- 遇到疑似 legacy 模块，按能力而不是整模块判断。已命中的能力先辨认当前消费者和语义合同，补齐独立验收，迁入承担同一职责的新架构；切换正式消费者并核对旧入口全量行为后，才一起删除旧实现、兼容旁路和过渡接线。命中不构成保留旧架构的理由，未命中也不构成误删仍有合同义务的能力的理由。
- 每项能力只有一条正式实现路径；转换、校验、聚合、兼容层必须各有独立职责。相同规则、默认值和格式有一个权威定义。测试预期依然从源码和合同独立推导。
- 设计、合同、生产实现、工具、验收和使用说明按长期职责归位。正式入口、内部工具、实验及历史有可辨认的边界。提交不包含本机配置、缓存、构建产物或一次性证据。
- 代码、命令帮助、示例、文档和实际支持范围同步改变；设计目标不写成已交付功能。核心术语和失败阶段一处定义，故障能追溯到阶段、入口和原因，诊断不混入正式 PERS。
- 优先削减改动波及面，用可执行检查而非人工记忆守住易错边界。干净检出在声明的工具链和依赖条件下可构建、可验证；性能敏感操作的约束和证据可复现。

## 如何验收变更

以验收基线中的具名案例核对完整 PERS 和明确的拒绝结果，拒绝时不产出 PERS；同时检查独立预期、预处理补丁、链接和正式命令。分开提交纯整理、缺陷修复和合同变更。发现现行合同可能变化，先裁决；清理不改 expected 来换绿，不降级或删除合法用例。新增覆盖应验证可说明的行为，不把通过数或覆盖百分比当作质量目标。

### 分批定向验收与全量收口

- 清理期间，用最近一次通过的全量正式回归与覆盖报告，在未受后续变更影响的范围内挑选候选。先核对采集提交、正式入口和具名用例，以及工具链、插桩和配置，再核对候选的实现、调用/准入路径、种子和测试未影响原覆盖判定。旧报告只用于筛选，不证明新提交通过，也不能替代尚未采集的覆盖。
- 每批先界定改动影响的入口、实现和具名案例。对可明确界定范围的批次，运行相应的正式 CLI 定向验收及受影响的工程检查；通过后可单独推送检查点，不必每次重跑全量。推送时记录验证提交、定向范围、结果、覆盖证据和待全量项，明确区分“定向已通过”“沿用旧覆盖筛选”“全量已通过”。拒绝诊断和完整 PERS 断言不能减弱。
- 新增或修改种子、改变内核路径可达性等，必须在该候选提交对受影响范围重新采集正式测试覆盖，再按新证据判定路径存废。只见入口命中、用混合区间中的一段命中替代整项，或改变用例集合后套用旧覆盖结论，都不算验收。若影响边界证明不了，或无法按正式入口完整覆盖受影响范围，须在该批推进前先跑全量。
- 所有计划清理项处理完毕后，对最终候选提交跑一次带覆盖的全量正式回归，核对完整基线、最终覆盖和签字例外。这一趟同时产出回归及覆盖结果，不再另跑一遍同内容的普通全量回归；工程检查和内核单测等职责不同的检查仍按验收要求执行。最终全量未通过，不宣布收口。

- 默认复用同一提交的结果。若验收期间合入的变化只涉及不被构建、回归和种子装载读取的文档，可在逐项证明确切的构建、用例、种子、预期、工具及配置快照未变后复用已有业务与覆盖结果。记清已测试的提交、最终提交和两者实际差异，只补跑受影响的文档及工程检查；不要把复用的业务验证写成在新提交重新执行过。凡改动测试读入的种子、配置或文档夹具，不适用本例外。
