# Normalizer 性能排查

与[调试日志说明](normalizer-debugger.md)配合。从触发问题的最小合法源码、模块或场景开始，保持原业务语义和独立 PERS/拒绝预期。

## 复现和对比

1. 固定源码提交、入口、输入、工具链、构建模式和运行环境。先构建，再计时，避免把编译或依赖安装算进执行耗时。
2. 在正式 CLI 上选用调试类别，记录阶段耗时、节点与方法访问、分支拆分和最大深度。慢输入要提供相邻规模和资源上限，不用单次耗时推断趋势。
3. 比较前后完整输出；顺序、异常、投影或规范形式不能为性能让路。诊断存在时记录退出码和 stderr；失败不能输出半份 PERS。
4. 证据保存在工作区之外。仓库保留最小回归输入和稳定的约束，不保留单次压测表、已退役的压力脚本或历史结果。

## 当前工具

- `NORMALIZER_PROFILE_LOG` 写入流水线阶段和当前启用的执行计数。需要细粒度采样时使用 `NORMALIZER_DEBUG_CATEGORIES` 与 `NORMALIZER_DEBUG_MAX_EVENTS`。
- `NORMALIZER_MATH_PROFILE_LOG` 开启数学内核事件，`NORMALIZER_MATH_PROFILE_SLOW_MS` 调整慢事件阈值。默认不打开采样。
- 数学化简的资源预算与规范形式见[统一正则规范](../../design/chapters/第八章%20·%20统一定形规范.md)。临时提高预算只能辅助定位，不能当作修复。
- 数学记忆表有固定条目上限；达到上限时回收一部分键，最多导致下次重算，不改变归一化结果。工具可通过文档里的数学日志核对 `math.cache.evict`。
- 规范工程表达式的结构深度在加载时受限，过深时 CLI 不产生 PERS。执行期仍限制 Java 活跃调用栈与总工作量；性能日志记录真实表达式访问深度，不再另设不可达的语义函数递归上限。

### 已有 CLI 的证明预算验收

`normalizer test engineering` 的独立工程检查用合法 Java 嵌套 CASE 验收两种独立的资源限制。(x < 0) 时由 `p` 选择 10 或 20；否则 `y > 1` 返回 20，其余返回 30。分别将 `NORMALIZER_MATH_MAX_PROOF_NODES` 和 `NORMALIZER_MATH_MAX_CACHE_ENTRY_NODES` 设为 1，三次都与同一个独立完整 PERS 预期比较，不仅互相比。低证明预算可以拒绝推理捷径，文本日志应报告 `run_proof_budget`；低缓存上限只影响缓存准入。这一性能检查不计入种子回归覆盖率，也不依赖已经退役的机器可读采样。

没有另设产品 CLI 或自动压测发布门禁。发现性能回退时，先确认瓶颈属于输入准备、语义执行、数学化简还是出口输出，再选择对应的最小复现。

内核单测还区分工作步数与固定点迭代：内层步数失败后，外层即使手里已有值也不得发布正常结果；做了一步有效改写也不等于已证明固定点。测试直接用每线程的真实预算作用域，不改其他测试进程的环境变量。
