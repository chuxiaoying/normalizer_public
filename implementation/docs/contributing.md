# 贡献指南

业务含义、预处理边界、统一 IR 和最终 PERS 由[设计区](../../design/README.md)记录。修改实现时，先按[实现入口](../README.md)定位负责该转换的模块，再运行对应构建或 CLI 检查。公共用法变化时同步更新[使用区](../../usage/README.md)。

提交遵守[全仓约定](../../AGENTS.md)。设计裁决后，验收用例从其输入和观察范围独立推导，放在[测试区](../../tests/README.md)。

清理代码、目录和文档时遵守[仓库整理与验收原则](repository-hygiene.md)。

## 审查归约与定形

完整 PERS 不同，先区分业务含义错误、可证明但尚未执行的归约、尚未规定的等复杂度选向和独立预期错误，再修改责任层。归约规则须注明语义域、保留的观察、失败时的行为和停止条件。验证汇合需覆盖等价写法、前提失效的反例及幂等；结构守卫、完整等值断言和行为证据不能互相代替。生产化简器构造的预期不能独立验证该化简器。
