# 场景入口层、统一 IR 与归一化内核

本文展开[设计区](../../design/README.md)所述三个模块的工程职责和交接合同。对使用者而言，normalizer 不是一组需要手工串联的语言工具，而是由场景入口承接原始工程、由多语言处理内部消化语言差异、再由统一内核产出最终 PERS 的归一化系统。

## 架构结论

使用者只需要理解下面这条主链：

```text
原始工程
  ↓
多语言场景入口层
  ├─ 选择场景、入口和观察范围
  ├─ 按场景合同执行 AI 预处理
  └─ 将场景差异消化为统一 IR
  ↓
统一 IR
  ↓
归一化内核
  ↓
最终 PERS
```

多语言场景入口层是对外产品层；统一 IR 之后才进入所有场景共享的公共归一化内核。

Java 函数、Java Bean、前端 VO 生产、前端 VO 消费、组件监听、模板绑定等场景可以有不同的入口形式，但差异必须在进入统一 IR 前消失。内核不应该知道“这是 Java 方法、前端事件还是组件监听器”。

## 公共术语

长期文档只把以下概念作为公共主链：

| 术语 | 定义 |
|---|---|
| 原始工程 | Java、JavaScript、TypeScript、TSX、框架脚本、模板、依赖和配置，以及待分析入口和观察范围 |
| 场景入口 | 面向一种归一化任务的入口合同、AI 预处理要求、边界定义、CLI 和验收方式 |
| 规范工程 | AI 预处理后的完整源码／扩展语义工程，保留可达业务逻辑、类型、状态、异常、对象身份、顺序和来源证据 |
| 多语言处理 | 场景入口内部完成的语言解析、绑定、框架入口识别、跨文件闭包和语义下沉 |
| 统一 IR | 语言无关、入口和边界已经明确、可以交给内核的语义表示 |
| 归一化内核 | 对统一 IR 做符号化求值、状态归约、对象和异常归约、边界归约并生成最终 PERS |
| 最终 PERS | 内核生成的正式生产归一化结果或消费归一化结果，使用 `P/E/R/S/T/throws` 表达 |
| 独立 expected PERS | 根据原始源码、观察范围和规范合同独立推导的最终结果预期，用于断言内核实际输出 |

语言 AST、typed IR、前端边界摘要和内核调试表示是实现材料，不是额外的公共主链概念，也不能被称为统一 IR 或最终 PERS。

## 多语言场景入口层

场景入口层负责把一个完整原始工程变成统一 IR。它不是一个只做文件扫描的工具集合，而是一个由场景合同约束的产品入口。

每个场景都必须提供一份 README，作为交给 AI agent 的工作合同。README 至少说明：

1. 场景的目标和归一化结果类型。
2. 接收的原始工程、入口、观察范围和依赖材料。
3. AI 预处理必须补齐的类型、状态、VO、端口、异常、对象身份和顺序。
4. 哪些调用属于业务内部逻辑，哪些是真实外部边界。
5. 源码入口如何映射为统一 IR 入口。
6. 场景 CLI 的命令、输入文件、输出文件和失败阶段。
7. 统一 IR 的交付条件。
8. 最终 PERS expected 的独立推导方式。

场景入口层不得预先计算业务答案，也不得把最终 PERS 作为 AI 输入。它只负责理解场景差异，并把差异消化为统一 IR。

### 第一批场景

| 场景 | 原始入口 | 统一 IR 中的入口含义 | 最终结果 |
|---|---|---|---|
| `frontend-vo-production` | 页面事件、生命周期、action | 事件参数、VO 读取、边界调用和 VO 有序写入 | 前端 VO 生产 PERS |
| `frontend-vo-consumption` | 组件监听、模板绑定、双向绑定提交 | VO 快照读取、组件属性和显示出口 | 前端 VO 消费 PERS |
| Java `source` | 已符合规范合同的静态或实例业务方法 | 普通函数入口、表达式、状态和边界 | Java 函数 PERS |
| JavaScript `module` | 闭合的独立 JS 模块和导出函数 | 标量函数入口，保留错误边界 | JavaScript 函数 PERS |

场景可以共享内核能力，但不应把场景特有的入口识别、框架调度或 VO 绑定塞进内核。

## 前端 VO 入口的统一方式

前端 VO 生产和消费是两个场景，不是一个模糊的“前端 PERS”旁路。

```text
事件／生命周期／action
  → frontend-vo-production 场景入口
  → 统一 IR 的生产入口
```

```text
组件监听／模板绑定／双向绑定提交
  → frontend-vo-consumption 场景入口
  → 统一 IR 的消费入口
```

消费入口在源码里可能不是普通函数，但场景入口必须在进入统一 IR 前把它适配成内核可理解的入口，并明确：

- 观察的 VO 快照和观察时点；
- 组件或模板读取的 VO 字段；
- 显示条件、属性和文本出口；
- 状态提交和重新渲染的顺序；
- 组件之间通过 VO 字段建立的连接。

这是入口适配，不是制造一个虚假的业务函数。统一 IR 之后，内核只处理入口、环境、结果和有序副作用，不再区分前端事件和组件监听器的语言形态。

## 三个模块与场景层的关系

场景入口层位于三模块公共内核之前：

```text
┌──────────────────────────────────────────────────────────┐
│ 多语言场景入口层                                         │
│ 场景选择 · AI 预处理合同 · 入口适配 · CLI · 统一 IR 交付 │
└──────────────────────────────┬───────────────────────────┘
                               │ 统一 IR
                               ▼
┌──────────────────────────────────────────────────────────┐
│ 归一化内核公共部分                                       │
│ 符号化求值 · 状态归约 · 对象身份 · 异常 · 边界顺序       │
└──────────────────────────────┬───────────────────────────┘
                               │
                               ▼
                         最终 PERS
```

### 场景入口层

输入是完整原始工程、场景、入口和观察范围；输出是闭合统一 IR。它负责：

- 读取或指导读取完整工程和依赖；
- 按场景合同确定入口和观察范围；
- 让 AI 预处理闭合类型、状态、边界、异常、身份和顺序；
- 解析语言和框架入口；
- 把 Java Bean、前端事件、组件监听等入口转换成统一 IR 入口；
- 对未解决项、外部依赖和不支持结构明确失败。

它不负责最终数学化简，也不生成最终 PERS。

### 统一 IR

统一 IR 至少要明确：

- 入口身份和参数；
- VO、state、局部对象和共享对象的身份与字段；
- 环境读取和边界响应；
- 真实外部调用、参数、返回值、异常和发生顺序；
- 生产侧写入和消费侧读取；
- 组件监听、模板条件或容器调度已经适配后的入口关系；
- 可达函数、类型、跨文件连接和未解决项；
- 来源位置和观察范围。

统一 IR 不得包含无法定位的猜测，也不得把未知实现填成 `null`、`0`、空集合或固定答案。缺少语义时，场景入口必须在进入内核前失败。

### 归一化内核

内核只接收统一 IR，负责：

- 符号化求值；
- 条件、值、状态和对象身份归约；
- 异常和失败路径保持；
- 真实边界及其参数、返回值和顺序保持；
- 生成最终生产 PERS 和消费 PERS。

内核不读取 Java、JavaScript、TypeScript、Vue 或小程序源码，不猜测框架调度，不补齐缺失函数体，不把场景名称写入归一化规则。

## 已验收的正式入口

Java 使用 `source`，已闭合的独立 JavaScript 和 TypeScript 使用同一个 `module`，Vue 生产和消费使用 `scenario`。参数和输入条件见[CLI 参考](../../usage/cli.md)，覆盖范围见[CLI 回归](../../tests/README.md)。场景适配器使用规范工程接入内核，规范工程格式是模块间交付，不是另一条公开 CLI。

AI 阅读和闭合业务源码，不依赖额外预处理工具。语义改写以[设计种子](../skills/normalizer-preprocess/references/seed-coverage.md)为准。语言模块和内核处理、校验已交付输入，不替 AI 猜缺失语义。

## 验收边界

每个场景必须分别报告：

1. 原始工程是否被场景预处理完整理解。
2. 统一 IR 是否生成且入口、边界和观察范围闭合。
3. 内核是否从统一 IR 产出了最终 PERS。
4. 最终 PERS 是否与独立 expected PERS 一致。

源码运行、页面渲染、Java 原程序对照和日志是辅助证据，不能替代第 2、3、4 项。

## 尚未验收的能力

通用框架装配、复杂多文件连接、任意独立 JS 异步调用，以及通用模板解释不在当前 CLI 的承诺范围。有设计但尚未执行的种子列在[测试目录](../../tests/e2e/catalog.yaml)的 `pending` 中。
