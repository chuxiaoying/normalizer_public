# 模拟堆与业务出口的内容投影

本文规定业务归一化的目标合同。模拟执行负责对象、身份、别名及字段变化；最终 PERS 负责分析入口的业务观察。内部需要使用的信息不因此自动成为最终输出。本文不表示当前生产内核已经支持所有投影。

## 观察时点与职责

内部函数返回对象时，只把 heap 引用交回调用者，继续模拟。只有分析入口的最终返回形成 R。RPC 等边界发生时，其参数按该端口的观察合同形成 S；已有 VO／外部对象写入等 S 的职责仍然保留。

```java
Box make() {
    Box box = new Box();
    box.value = 7;
    return box;
}
Box entry() {
    Box box = make();
    rpc.send(box);
    box.value = 9;
    return box;
}
```

在 send 观察参数内容的合同下，本次调用的参数内容为 `{value:7}`，入口 R 的内容为 `{value:9}`。两者来自同一个模拟对象的不同观察时点。最终文档可以最后统一生成，但参数值必须按调用时的 heap 求值，不能被随后写入污染。

单纯创建 Box、写入 value=7 并最终返回，在此内容合同下的结果为 `R: value.record("value", 7)`、`T: []`、`S: []`。分配动作本身不作为业务副作用；不为这个对象在 T 中声明公开的新身份，也不把它的内部字段初始化转为 S。

模拟层仍必须准确处理两个对象是否相同。源码中的引用比较、别名写入、循环分配、构造及异常顺序可能影响最终业务值，不能因出口观察内容就忽略它们。比如两个新对象的比较结果是 false，可以直接成为 R，无需再公开被比较的两个身份。

## 由边界合同选择内容

预处理与边界声明负责给出完整的可观察结构、字段类型和实际编码规则。投影依据这些声明及已求得的对象类型，不反射遍历整个 heap，不任意调用 getter，也不只选择容易计算的字段。未知 getter 的行为应先由闭合语义或真实端口合同解释。

对于已经声明的业务内容观察，使用以下统一值表示；同一类型不能按 fixture 的写法偏好选另一份黄金。

| 已声明的观察类型 | 规范值表示 | 必须保留的区别 |
|---|---|---|
| 普通 DTO／VO 的对象内容 | 按可观察字段及其声明类型递归形成 `value.record(...)` | null 对象、非 null 对象中的 null 字段、所有约定字段 |
| List／数组内容 | 元素按原顺序形成有类型的 vector | null、空序列、重复元素、顺序及元素内容；不额外套 `items` 字段 |
| Java String 的完整内容 | nullable `vector<i32>`，每项为原 UTF-16 单元 `0..65535` | null、`[]` 空串、补充字符的两个单元、孤立代理项；不额外套 `units` 字段 |
| 已明确采用 Unicode 标量的 `text?` | 现有完整文本值 | 保留该类型已声明的值域，不擅自将任意 Java String 视为此类型 |
| Date 的 epoch millis 观察 | `value.record("millis", ...)` | null、完整有符号 long 毫秒值；不附加未经声明的时区或格式字段 |

String 单元向量与普通列表由来源及输出观察类型区分，类型证据不能省略。内部使用 i64 单元时，须依据原字符值域等值转成 i32。不得通过替换孤立代理项或将其转成 null 来迁就文本实现。当前 `value.text_from_utf16` 无法无损表示这类单元，因此不能把它作为完整 Java String 的出口投影。

### 可空复合值的目标类型

目标 PERS 的类型注解统一用后缀 `?` 表示整个宿主值可以为 null，递归应用于已有结构类型。`vector<i32>?` 是可空的 UTF-16 单元向量；`vector<vector<i32>?>` 是非空引用的列表，其每个字符串元素可以为 null；`vector<record<key:vector<i32>?,value:vector<i32>?>?>` 的列表元素还可以是 null 对象。空向量 `[]`、null 元素和 null 列表是三个不同的值，不能用空向量、虚构对象或内部引用代替 null。

这明确的是目标类型与正确黄金，当前生产类型解析器尚未支持所有可空复合值。测试 fixture 的内部模拟可以继续使用可加载的引用和 heap 字段；目标 PERS 的纯 T 状态类型及内容表达应按业务观察如实声明。不得把目标类型支持不足解释成可以删掉输入、弱化预期或开始本阶段的生产实现。测试守卫的结构通过也不代表生产类型检查通过。

### Map 内容与顺序

声明观察键值内容的 Map 使用已有纯值 `map<K,V>` 及 `value.map_empty`、`value.map_put`、`value.map_get_or` 等运算。Java `Map<String,String>` 的内容类型为 `map<vector<i32>?,vector<i32>?>`，Map 本身可空时再在最外层加 `?`。目标键按完整内容相等；同内容的不同 String 引用是同一个键，null 键不同于空字符串键。最后一次对同一键的写入覆盖旧值，未写入的键和 null 值必须保留。不为迁就现有标量键限制而把业务字符串改成测试用十六进制键，也不把 Map 任意包装成 `entries` DTO。

Map 的内容观察不包含 HashMap 偶然的枚举顺序。需要输出规范键序时，null 排在非 null 前，UTF-16 向量按单元数值的字典序排列，相同前缀的短向量在前。该规则只排列已确定的键值集合；不能交换可能同键的符号写入，不能改变最后写入覆盖语义。源程序若观察插入顺序或遍历顺序，该顺序仍须由相应的有序结构合同保留，不能套用无序 Map 的内容合同消去。

生产的 Map 键类型与排序目前仅支持更窄的域，完整 UTF-16 向量键属于实现缺口。正确测试先声明这一目标并保留独立源码证据，本阶段不补生产实现。

### Set 的成员内容

无序 Set 的完整内容复用 `map<K,bool>`：每个成员对应一个值为 `true` 的键，成员关系使用 `value.map_has`。来源类型与边界声明仍标明这是 Set 的成员投影，不把任意业务 Map 当成 Set。Java `Set<String>` 使用 `map<vector<i32>?,bool>?`，同内容的 String 合并为一个成员；重复添加和不同添加顺序不改变结果。

null 集合、空 map、包含 null 键的 map，以及包含 `[]` 空字符串键的 map 是不同内容。键序沿用 Map 的 null 优先与 UTF-16 单元字典序；孤立代理项原样保留。这个无序内容合同不适用于源程序已经观察的迭代顺序。最终 R 或字段 S 直接使用可空成员 map，不额外输出 `is_null/items` 或 `whiteList_null` 等内部编码。

真正由业务边界声明的十六进制、URL 或其他编码属于输出值的语义，按其算法计算；为测试方便引入的显示编码不是另一种任意可选的规范代表。已有明确观察范围的用例须逐条核对输入和预期，不能仅凭字段名批量改变合同。

对于已有入口对象或环境返回对象，出口投影可能需要读取其可观察字段。这些读取仍是 E，并须处在实际到达该观察点的条件内。此前已写入的字段由模拟状态转发，不能重新取得一个不相关的入口值。输出对象的内容可以包含依赖 E 的符号表达式，不要求先知道具体数值。

## 状态、调用与特殊边界

S 中用来定位已有 VO／外部对象的 target，与其字段 value 的内容投影职责不同。不能因为字段值采用内容表示，就删掉写入目标、别名造成的影响、发生条件或异常前已完成的写入。

每次 RPC 参数投影独立绑定于本次调用的状态。相同参数内容的两次调用仍是两次真实边界事实，响应也不能合并。共享纯 T 可以表达内容计算，但不能变成执行式分配或写入日志。

已有端口若明确观察引用保留、回调或参数写回，必须核对其真实合同。不能为方便内容投影把它悄悄改成只读值 RPC。调用前参数内容、调用后写回和最终 R／S 分别对应自己的时点，异常写回也应保留。需要公开引用关系的真实业务边界须另给具体用例和合同，不能从普通 new 推导出所有输出都需要对象图。

### 循环内容的支持边界

分析入口最终 R、RPC 参数或其他可观察 S 的完整内容投影包含循环引用时，中止归一化并明确报告不支持循环内容出口，不输出成功 PERS 或截断对象。不新增公开 fresh-reference、对象编号或循环内容语法。归一化 abort 是分析失败，不是源程序抛异常，不能伪造为 Java 的 NPE 或其他 throws。

内部 heap 继续完整模拟对象身份、别名与环。内部创建自环后只返回 `n.next.value`，最终内容为 7，仍正常归一化。共享对象、循环语句、new、保留原尾部都不是 abort 的理由；检测出口环应区分当前投影路径回到祖先与不同路径共享同一个对象。

`child.next=child; owner.next=child; return child` 的非空 owner 路径含循环出口；owner 为 null 的源路径仍是 NPE 且没有 owner 字段写回。头插链表在原尾为 null 时无环，在原尾回指 owner 或本来有环时才含循环内容。不能将整类链表改为预期拒绝，也不能静默限制原尾输入。

## 测试与实施边界

- heap／模拟层用例继续验证新对象独立、别名传播、字段变化、引用相等和内部函数返回。它们验证内部计算，不把 heap 编号当作业务 PERS 结果。
- 业务归一化用例验证完整的最终 R、E、S、纯 T 和异常，并按对应时点核对所有约定内容。相同业务内容不能仅因内部新建／复用对象不同而采用不同输出形式。
- 引用比较会影响业务结果的源码仍须覆盖。例如对引用相等的计算最后返回 Boolean，黄金应验收该 Boolean 方程及实际副作用。
- 已有身份断言逐条审查：内部模拟需要的验证保留；业务出口上超出已确认内容合同的断言需明确调整依据；真正有身份观察的边界不得静默降级。禁止批量删除断言或用 actual 生成 expected。
- 检查结构通过、辅助 heap 执行正确和源码对照通过，都不等于生产内核已完成出口投影。正式验收仍是完整实际 PERS 与唯一独立黄金直接相等。

当前 Allocate 已能在模拟 heap 中创建、初始化和绑定对象，局部读写及部分消去已有实现。`no_local_escape` 对仍含局部引用的出口报错，直接缺口是这些出口的内容投影尚未接通，不能笼统表述为内核不会处理 new。目标是完成上述有类型、有时点的投影，不增加公开 fresh-reference 语法。
