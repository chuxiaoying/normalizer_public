# 归一化内核交付合同

发布物应可复现、可校验、可回退。稳定的用户入口是 [`implementation/tools/normalizer`](../../../usage/cli.md)，`normalizer-normalized` 是其内部执行器；正式输出和内部诊断表示的区别见[最终 PERS 机器接口](../business-pers.md)。

以下是交付验收要求。仓库提供构建和回归入口，本页不提供发布地址或一键发布命令。

## 交付内容

交付包应包含目标平台的 CLI、对应源码提交、支持的输入与语义版本、依赖许可证、校验和及使用说明。兼容性依据版本化 schema 与最终输出合同，不依据开发环境的目录结构。

## 准入

在待发布提交上运行[构建检查与完整业务回归](../../docs/validation.md)。Java、TypeScript、Vue 的已登记用例和 PERS 结构校验都由同一个正式回归入口执行。记录实际命令、工具链、目标平台和退出结果；局部测试、零用例、忽略失败或来自其他源码提交的日志不能代替完整准入。

新增规则必须遵守[统一定形规范](../../../design/chapters/第八章%20·%20统一定形规范.md)。发布不得反填 expected、输出内部行为 IR、删场景或缩小观察范围以取得绿灯。

## 发布与回退

交付 manifest 应记录源码 SHA、平台、制品 SHA-256、输入/输出 schema、语义版本和验证范围；回退使用原始制品及其同版本合同。发布地址和凭据由部署环境提供，不把个人服务地址写成产品合同。

发布自动化必须按以上合同单独验收。
