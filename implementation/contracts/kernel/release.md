# 归一化内核交付合同

发布物应可复现、可校验、可回退。稳定的执行入口是 `normalizer-normalized`；正式输出和内部诊断表示的区别见[最终 PERS](final-pers.md)。

## 交付内容

交付包应包含目标平台的 CLI、对应源码提交、支持的输入与语义版本、依赖许可证、校验和及使用说明。兼容性依据版本化 schema 与最终输出合同，不依据某个开发机目录或 workbench 插件树。

## 准入

发布同一源码提交前执行依据设计建立的完整回归准入，确认编译、最终 PERS、独立行为证据及多语言补充测试满足各自职责。记录实际命令、工具链、目标平台和退出结果；局部测试、零用例、忽略失败或不同 HEAD 的旧日志不能代替完整准入。

新增规则必须遵守[规范形式合同](normal-form-contract.md)。发布不得反填 expected、输出内部行为 IR、删场景或缩小观察范围以取得绿灯。

## 发布与回退

交付 manifest 应记录源码 SHA、平台、制品 SHA-256、输入/输出 schema、语义版本和验证范围；回退使用原始制品及其同版本合同。发布地址和凭据由部署环境提供，不把个人服务地址写成产品合同。

旧 `scripts/release.sh`、`deploy.sh` 和 workbench setup/test 流程已退役。本文定义交付要求，不宣称存在已接通的自动发布通道；发布自动化必须按以上合同单独验收。
