# 扩展语义与内核边界

扩展语义是 AI 预处理交付的闭合、类型化计算定义，不是动态插件或任意 evaluator。完整职责见[三模块架构](../../docs/architecture-three-modules.md)与[规范输入设计](../normalized-semantics.md)。

## 分工

- 固定基础操作由内核语义版本定义；业务输入不能注入 Rust/Python 回调、交换律或无异常公理。
- 标准组合定义与业务组合定义可复用已有基础操作，依赖必须闭合；不能只保留库或方法名作为黑盒。
- 框架装配、反射目标和本地业务行为在规范源码或扩展定义中显式化。排序、编解码、解析、格式化等通用计算可以使用合同匹配且可计算的操作，保留完整输入域、结果、失败和可观察效果。比较器或回调中的业务逻辑仍须显式闭合。内核不按业务类名、框架名或测试项目选择规则。
- 外部端口必须有真实交互依据，并声明参数、响应、异常、状态影响、引用观察和调度合同。内部 helper 不因缺源码或归约困难而变成端口。

## 循环的两条规范化路径

原始 Java 循环由 AI 预处理先按可观察语义分类，内核不从运行时副作用反推循环属于哪一类。

- 已闭合的纯筛选、映射、计数、存在性和累积使用当前[遍历合同](../normalized-fold.md)及其种子。可证的纯数值递推使用实际的 `T.op: fold`；泛化 `fold_until` 是[设计目标](final-fold-pers.md)，不是已接通的输入。
- 有外部调用、状态写入或异常传播时，必须保留各次真实发生及其顺序、条件和完成值。当前有界重试将调用逐项发布在 S；泛化有序状态历史与带索引的调用族仍是[索引状态目标](final-indexed-state-pers.md)。
- 循环无法闭合、调用目标未知、迭代域或副作用顺序无法证明时，必须报告缺口。不要用虚构的 `$loop`、`$streamMapper` 或 `$streamPredicate` 补全结果。

## SQL、合法外部调用与 out of source

- SQL 查询、筛选、投影、聚合和排序由预处理交付为关系输入与关系表达式。表名和列名是关系语义的根元素，查询结果继续沿集合或有序关系归约，不能把 SQL 文本再包装成一个 `sql_exec` 端点交给内核猜测。
- SQL 写操作只有在预处理交付了明确的效果合同后才进入有序行为。合同至少要说明目标关系、写入字段、顺序、异常和部分完成状态。证据不足时拒绝输入，不把写操作伪装成查询关系。
- **Out of source**：对入口可达的调用，如果没有可归约的源码或闭合语义定义，只有真实、合法并已声明合同的 external call 才能继续；调用本身必须进入 S。普通对象/接口入参（例如 `Fee fee`）和 TypeScript/JSDoc 函数签名都不是外部边界声明。多态的具体目标能由规范源码封闭时，仍应沿实际目标归约。
- 不符合上述条件的无源码调用不受支持。预处理应报告缺失，不能伪造实现或端口；若无效目标到达内核，必须 Panic，报告 `[NORM-OUT-OF-SOURCE]`、入口及未闭合目标，不产出 PERS。不得把未知调用的结果当做 P/E、默认值、无定义的 R 函数或普通 S 写入。
- 已声明的状态、资源字段或关系可以是 E 中的观测根；这是有明确定义的输入声明，不允许借 E 绕过无源码调用限制。真实边界调用的正常值和失败可由表达式或 throws 观察，但取值动作仍记录在 S。

## 验收

扩展语义必须参与统一的值、条件、状态及递推归约。标记 pure 不构成完整定义或正确性证明。行为对照与独立完整最终 PERS 预期分别验证；不允许输出程序式 IR 或仅更改 expected 来消除失败。

旧默认插件发现、workbench 插件安装和 source rewrite 脚本流程已退役。保留的历史材料只用于提取 feature，不构成新能力接入方式。
