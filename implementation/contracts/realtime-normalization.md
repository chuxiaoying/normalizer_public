# 执行期间的实时归一化

归一化入口从参数的符号值开始执行。局部变量名标识栈槽。求值时读取槽里的表达式，字段读写通过对象身份查找堆内的值。内部调用带入实参、建立自己的局部作用域，正常完成时把值交还调用者。

## 分支与函数完成

当条件的真假都可达，两侧分别在各自的路径条件下执行。共同后续语句可以继续时，合并仍可继续的状态。相同值直接复用，有差异的值按条件组成 CASE，使用数学层化简。已 return 或 throw 的分支保留在完成状态中，后续语句只对仍可执行的路径生效。异常按类型进入可匹配的处理器，未捕获的异常随函数完成传播。

例如先令 left 等于 a，在 a 小于零时写入负 a。执行到下一条共同语句时，读取 left 得到 CASE(a < 0, -a, a)。若另一个分支提前返回，该分支的返回值进入函数完成状态；只有另一分支继续执行。业务数值遵循 IR 的 number 语义。

## 堆、外部操作与投影

- 读取字段时按当前路径确定最近可见的写入。某对象只在 amount > 0 时创建和赋值，只要读取也发生在该条件内，就能使用字段值。
- 真实的外部调用在发生时写入有序 S。每次调用产生独立的完成符号，后续值、条件和异常引用对应的 E。在两个条件都成立的输入上，必须保留实际的先后关系。
- 宿主状态写入同时更新执行状态和业务可见的 S。局部对象的内部写入只通过可观察出口体现，例如作为 SQL 的参数。最终 R 来自执行完成状态，最终 S 来自执行期间的操作序列。
- Java 已声明的非空 `@EntryState` 对象可写入直接标量字段。通过已绑定同类型对象读该字段时，按实际身份条件使用最近适用的写入；不把相同字段值当作身份，不把不同路径当作不同对象。若给定 `@Nullable` 形参的字段访问失败，保留异常之前的 S，只阻断其后的写入。普通形参不能充当未声明的写入目标。见[写入与别名的顺序对照](../../design/examples/topics/state-and-aliasing/java-state-alias.md)。
- 出口投影校验表达式来源、完成域、对象内容与事件绑定，并按业务来源命名。判定不出观察结果的输入应在正式入口给出诊断。已覆盖的语法、预处理标记及边界见[业务合同](business-pers.md)。

## 对照实现和用例

执行入口在 `kernel_input.rs`，值和控制流在 `kernel_execution.rs` 和 `kernel_input/source_control.rs`。堆字段、效果序列、正常与异常完成的共享操作在 `realtime_state.rs`。最终入口投影位于 `kernel_input/business_entry.rs` 和 `business_event.rs`。以上路径均相对 `implementation/packages/normalizer/crates/pipeline/src/`。

PayableService.recordPayable 的设计关注同一守卫下的局部堆读取、端口返回作为下一次 SQL 的参数、SQL 写入顺序及异常路径。Vue 的 onLoad 设计关注异步等待前后的宿主观察和状态写入。
