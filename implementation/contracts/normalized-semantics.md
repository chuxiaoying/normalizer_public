# 规范工程与扩展语义设计

本文定义终态设计及语义边界；目录示意不等于当前工具格式。可执行输入见[规范项目](../../usage/kernel-input.md)，最终输出见[最终 PERS](kernel/final-pers.md)，正确性义务见[行为语义](behavior-semantics.md)。

## 1. 目标与职责

normalizer 接收语义闭合的规范 Java 工程。AI 负责把真实工程、JDK、第三方库和框架的复杂写法转换成稳定的基础语义。normalizer 负责按明确语义计算、组合和归约，不继续猜测原代码模式。

建设期可以完善引擎基础能力。能力版本固定后，新的业务工程只能增加规范代码和业务语义定义，不应要求新增引擎插件、Rust 回调或针对类名的规则。基础语言确实缺少目标范围内的行为表达时，作为语言合同缺陷单独处理，不能伪装成普通业务适配。

AI 不直接替代全部符号计算。它识别“这一段在做什么”，引擎计算“这一段与其他分支和状态组合后意味着什么”。

## 2. 规范输入的准入合同

### 2.1 闭合性

所有可达函数必须属于以下之一：

| 函数种类 | 必须交付 | 引擎处理 |
|---|---|---|
| 普通 Java 函数 | 完整、符合子集的函数体和类型 | 正常符号执行 |
| 语义函数 | 类型正确的结构化定义，依赖最终闭合到固定基础操作 | 展开、组合或保留带完整定义的摘要 |
| 外部端口 | 外部交互依据、签名、端点、结果及失败约定 | 记录调用 S、绑定返回 E，不真实访问外部系统 |

“无依赖”指无未定义的分析依赖，不是删除外部业务交互。原 RPC 查询不能直接改成入口参数，否则会丢失 S。源码缺失不能作为认定边界的依据。

Java 声明与语义定义必须一一绑定到准确的方法签名。没有方法体且没有有效绑定就是错误。不能使用空函数或 `return null` 给分析器垫底；原程序真实返回 null 除外。

### 2.2 Java 子集

- 保留基本表达式、局部赋值、对象/字段操作、分支、普通函数调用、明确的正常与异常退出。
- 禁止原始 for/while/do-while/foreach；同时检查直接和间接递归，不能只检查语法关键字。
- 调用目标必须明确。确实有多个可能目标时交付条件分派，不能任选一个实现。
- 反射、代理、框架装配、Stream、Iterator、复杂闭包和 JDK/API 调用由预处理消解或转换成已定义语义操作。
- 类型、泛型实例、字段布局、对象初始关系、隐含配置须显式提供；动态配置作为已定义的环境读取保留。
- 语义函数定义之间形成无环依赖；基础遍历操作内部的迭代属于操作的固定定义，不是用户递归函数。
- 首版入口建议限定同步、有限集合业务计算。未建模的线程交互、异步调度、非终止计算应报告范围缺口，不能偷偷改成同步顺序流程。

规范输入不依赖原始循环模式推断；有限遍历用完整固定语义表示，不能用样本长度展开。

## 3. 语义语言：值与行为分开

### 3.1 值表达式

值表达式只依赖显式输入，不读写隐藏状态、不访问外部系统。基础词汇包括算术逻辑、记录/字段、条件、字符串，以及集合关系操作。

依据[业务类型合同](pers/schema.yaml)，普通 Java 整数（含 long）在业务域中是精确整数。源码明确表达的窄化、回绕或宿主浮点行为不能冒充普通业务算术。文本单位、空值、顺序、重复元素和比较器也必须按源码语义保留；不能将有序列表换成集合。

math 表达式的化简只在已确定的正常求值域内进行。可能抛异常的库操作须由行为层表达正常/异常出口后，再使用对应的正常值表达式。例如 substring 的空接收者、非法索引不能因表达式采用总函数形式而消失。

### 3.2 行为表达式

一次行为的含义是：

```text
输入参数 + 初始状态 + 外部响应
    → 正常完成或异常完成 + 最终状态 + 有序外部行为
```

核心操作至少包括顺序、条件、状态读写、外部调用、正常返回、抛出和捕获。异常前已发生的副作用不能被清空；finally 等原始行为要在翻译后保留。

对象身份由引擎统一管理。两个变量指向同一对象，不能在转换时被复制成两个独立值。值快照与可变引用要有不同表达。需要记录外部参数时，按真实观察时点处理；不能把所有传参都当成立即深拷贝。

纯度与读写范围应由定义检查或推导，不能信任 AI 自行声明的 `pure: true`。有外部调用或隐含状态读取的函数不能进入纯函数合并规则。

### 3.3 基础操作与组合定义

| 层次 | 谁定义 | 是否随业务增加 |
|---|---|---|
| 固定基础操作 | normalizer 语义版本 | 冻结后不因新库而增加 |
| 标准组合函数 | 版本化语义库，定义由基础操作组成 | 可以复用，仍受闭合检查 |
| 业务组合函数 | AI 预处理产出 | 可以增加，无需修改引擎 |

AI 不得通过 YAML 添加任意 Rust/Python evaluator，也不得自行宣告交换律、恒等律、无异常等优化公理。能够表达含义与能够进一步化简是两件事。未知参数下保留标准语义操作是合法结果；无定义的业务黑盒不是。

## 4. 集合与循环的承接

### 4.1 简单集合运算

使用 filter、map、count、sum、first、exists、sort、distinct 等固定操作。纯且无异常的谓词/映射才可使用允许重排的关系化简。原循环有提前退出或异常时，不能先求完整个集合再截取结果。

原代码示例：

```java
long total(long[] amounts, long limit) {
    if (amounts == null) return 0L;
    long sum = 0L;
    for (long amount : amounts) {
        if (amount > 0) sum += amount;
    }
    if (sum > limit) PaymentPort.alert(sum);
    return sum;
}
```

转换后的示意：

```java
long total(long[] amounts, long limit) {
    if (amounts == null) return 0L;
    long sum = Meaning.positiveTotal(amounts);
    if (sum > limit) PaymentPort.alert(sum);
    return sum;
}
```

语义定义示意：

```text
positiveTotal(amounts) = sum_i64_wrap(filter(amounts, a => a > 0))
```

`PaymentPort.alert` 必须声明真实端口；`Meaning.positiveTotal` 必须绑定完整定义。SDK 的编译声明不是函数实现证明，也不能让普通 native 方法自动成为受信操作。

### 4.2 有状态的有序遍历

设计固定的 foldUntil 类操作，输入为有限序列、初始状态、单步处理。单步处理接收元素、序号与当前状态，产生新状态及继续/停止/异常标记。若原 Java 含方法 return，需明确它是结束遍历还是结束整个方法，由调用者传播完成标记。

单步处理本身无循环，捕获的外部数据必须显式列为参数；共享对象读写进入状态语义。它可以调用已声明端口。

- 已知有限数据：参考执行器可以具体执行用于验证。
- 符号集合：输出精确的有序遍历表达，不必枚举每一项。
- 只有可检查的条件满足时才化简成 sum/first/exists。不能从一次迭代的样本行为推定任意次数行为。
- 循环内外部结果按调用位置和迭代实例区分，例如 E(callsite, iteration)，不可复用同一个 E。
- 调用次数、先后、首次失败停止、异常前副作用必须可表示。

禁止用 unknownLoop、任意脚本执行或递归宏隐藏尚未理解的循环。任意 while 不一定都能变成有限 fold；表达不了时应列缺口。基础语义层不是万能的闭式公式求解器。

## 5. 交付文件与检查

拟议目录：

```text
normalized-project/
  project.yaml       # 入口、原代码指纹、Java 子集/语义版本、显式能力清单
  src/               # 无原始循环、依赖闭合的 Java
  semantics/         # 类型化语义函数定义
  boundaries.yaml    # 原端点到规范调用的映射及合同
  origins.yaml       # 规范节点 → 源码位置或 JAR 方法/字节码位置
  evidence/          # 转换证据、比较结果、未解决项
```

语义文件拟议字段：稳定 ID、版本、参数/结果类型、结构化 body、显式捕获、正常/异常完成方式、状态读写、端口调用、来源和假设。最终 schema 和操作命名尚需设计；不要把本文示意直接当作工具已支持的格式。

输入检查覆盖全部可达定义，不只入口表面：循环/递归、未绑定调用、类型冲突、缺失定义、未声明端口、隐含依赖、未支持操作、无依据的前置条件。预处理 worklist 保留独立的可达分母和动态目标缺口，不能只验收 AI 自己选择生成的部分。

来源位置、语义版本、引擎版本、证据状态参与缓存有效性。诊断至少包含 code、规范节点、原始位置、问题、所需资料或可接受修复动作。缺少资料不能被表示成业务上的 null/false。

## 6. 输出合同

- P/E/R/S 的业务含义保留；异常单独表达，并按观察范围保留异常对象字段。
- R 与 S 的自由输入最终来自 P、明确的 E、明确初始状态和常量；集合元素/遍历状态是绑定变量，不是伪造的新输入。
- 最终 S 是有条件与因果约束的结构化边界事实，包含出口状态、调用及调用时观察；输入行为语句不直接进入 S。有限循环可用纯历史 T 和索引调用族表达，不能强行摊平成无序列表。
- T 只作表达共享或显示缩写，必须携带可展开定义。仅输出 `method_contract("A::m")` 不算完成边界归约。
- 内部语义函数和子任务不因为难展开就变成外部端口。
- 已精确建模但尚未简化，与语义未知严格区分。分别报告结构闭合、转换证据、输出简化程度；一个 success 不能覆盖全部状态。
- 定义和行为结构需要新版本输出合同；旧格式兼容只在不丢信息时进行。

## 7. AI Skill 与工具分工

Skill：划定观察边界 → 阅读原始来源 → 显式化装配和调用目标 → 选择基础语义 → 生成组合定义 → 核对空值、异常、别名、顺序、停止条件 → 提交来源和验证材料 → 根据诊断修正。

工具：收集证据、解析/索引、检查闭合与类型、运行固定语义参考执行器、执行 normalizer、比较结果、输出定位诊断。工具不需要重新发明全 Java 的语义逆向器。

没有证据时保留缺口，不靠“符合常识”补业务行为。前置条件必须来自真实合同或明确的分析范围；范围收缩必须报告。

## 8. 验收义务

语义操作使用独立真值与法则验证，覆盖异常、状态、顺序、错误输入拒绝和固定版本确定性；原工程转换使用相同输入与外部响应对照返回、异常、可观察状态与调用。有限测试不宣称普遍等价证明。

正式回归使用小而完整的 feature fixture，Java 主线同时覆盖解析器和内核；多语言补充解析及语言特有规则，不复制全部内核矩阵。完整业务页面、欠费单 handler 及其大型 oracle 不属于常规必过门禁。fixture 不得删掉目标特性所需的可达计算，内部 helper 不得改成假端口。

完整 PERS 断言采用统一正则规范及稳定命名，独立推导唯一 expected，不按测试项目或 expected 的偶然风格选择改写规则。规范排序只应用于语义域允许的变换；状态、调用、CASE 首匹配和观察获取依赖必须保留。详见[统一正则规范](../../design/unified-canonical-form.md)。

Java 源内的局部语义声明只交付已识别的类型化操作。缺少绑定符、未知操作或未知累加操作在声明所在处报错，不保存一份未识别的程序文本供内核猜测，也不发布 PERS。
