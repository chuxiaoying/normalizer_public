# 业务 PERS 与实时在线归一

正式结果回答业务入口的四个问题：输入从哪里来，依赖哪些环境值，在什么条件下产生哪些有序的外部操作，最终返回什么或抛出什么。多语言模块将各语言的输入整理为同一套有类型的 IR，执行内核只根据这套 IR 演算。

## 类型来自声明

- [业务类型合同](pers/schema.yaml)列出 `number`、`money`、`date`、`bool` 与 `text`，以及具名记录和受支持的集合类型。`void` 描述没有返回值的正常完成。
- Java 的普通整数映射为无固定位宽的业务 `number`。例如 `int amount` 和 `int today` 都映射为 `number`。变量名称、所在列和用于比较的目的不能改变来源类型。来源类型本身表示金额或日期时，由对应语言模块负责映射。
- Vue/JS 的数值输入同样采用 IR 的数学 `number`。其值可按大小全序比较，运算保留数学结果；NaN、正负无穷和宿主浮点舍入超出业务合同。两个入口都可将“合计超过额度时取额度”归一为同一个取小值表达式。
- 入参绑定属于当次调用。Vue `onLoad` 的 `today` 就是这样的固定入参，等待前后相同；不把该结论用于可变宿主状态。
- 小数位数以源码或业务合同为准。金额和 `number` 不强制保留两位，未声明舍入时不自动插入 ROUND；显式舍入位数与文本显示格式是不同要求。舍入中点方向不能由位数推出。
- 对整数输入做整数运算，保留整数域。业务整数 `2147483647 + 1` 得 `2147483648`。源码依赖显式位运算、截断等行为时，必须另行闭合其语义。
- 普通业务类型默认非空。允许空值才额外标记 `?`。标记决定可接受输入，比较、解引用、返回及异常要在同一输入域上验证。

## 从预处理到输出

原生 helper、分支、对象构造和字段访问应沿源代码解析。只有缺少可执行语义的局部才需补交，例如外部端口身份、关系查询或库函数的纯算法。保留实际读取时点、调用顺序与异常传播；不得从最终答案补回输入。输入是对象不代表对象方法有源码。无源码目标只有满足[外部调用合同](kernel/semantic_extensions.md#sql合法外部调用与-out-of-source)才可以作为 S.call；其余到内核时 Panic 并提示不支持，不产生 PERS。

执行时直接传播 P/E 表达式，维护栈、堆、有条件的有序 S 和函数完成状态。在可继续执行的汇合点及时合并，函数级汇合保留提前返回和异常。出口只投影已闭合的执行状态。公开符号要追溯到原始业务入口；例如无参 Vue 渲染读取 `arrears.status.loading` 属于既有状态 E，语言适配器的中间形参不能成为 P。

## 示例如何成为回归

每个入口分别核对原始源码、预处理差异和完整最终 PERS。无法闭合的输入单独验证诊断阶段和原因。文档中的理想结果是待验证预期：存在歧义时，用能区分两种解释的输入或外部调用顺序校验；确定预期有误后同步修正文档与回归。变更实际输出不能作为修订预期的依据。

## 从现有内核到完整业务入口

沿用[实时执行设计](realtime-normalization.md)的求值、分支汇合与完成区，以及[跨语言输入合同](normalized-source-contract.md)的宿主语法和共享扩展分工。以下是建设顺序与验收标准。各层完成的标志是原始示例经过文档所述的预处理后，能从正式入口得到正确结果。

| 顺序 | 可交付能力 | 实现边界 | 用哪些输入检验 |
|---|---|---|---|
| 1 | 可复现的输入与独立预期 | 按实际差异生成规范源码；以原始入口身份选择函数；比对完整 YAML。拒绝有独立断言 | 14 篇示例的 16 个成功输出和 1 个预处理拒绝 |
| 2 | 预处理标记与局部注释语法解析 | 语言模块识别声明与源码位置，共享扩展解析器解析块正文；绑定与类型校验后，交付统一 IR | 同一聚合从 Java 与 JS 得到相同的关系结构；错位标记、未绑定名称、未知指令应定位到原源码 |
| 3 | 标量、调用与路径归约 | Java 原生表达式与 helper 进入执行器；数学层保留无界整数与布尔约束；渲染层从完成区取 R | 加一跨越整数上界；同一多返回函数分别命中三个分支；联立条件的解和相邻非解 |
| 4 | 来源、类型、对象与文本 | 语言层绑定参数、声明标记和有定义的纯操作；堆保留对象身份；出口投影可观察字段，解析歧义才加 P/E 限定 | 入参和实例字段同名；本地构造记录；可空输入与两种 Unicode 空白字符 |
| 5 | 局部扩展、关系来源与有序边界 | 语言层定位方法内的扩展，共享解析层将扩展连同前后原生语句降至同一 IR；内核组合关系、执行有条件的 S 并生成 E 完成值 | 空集和多行求和；排序首次命中；INSERT 跳过/成功/失败；UPDATE 匹配零行或多行 |
| 6 | 有界重试、异常与异步 | 固定上限沿控制流执行；按调用发生次序分配完成值，分开正常返回、捕获与传播；按程序实际时点读取可变宿主观察；调用不变量保持固定 | 三次重试逐次成功或全部失败；Vue 同步消费和异步生产；调用不变量在等待前后相同、两次请求分别失败 |
| 7 | 删除重复执行主链 | 逐项定位正式输出仍依赖的旧行为记录、兼容投影与载体；移除已由在线状态完整承担的生产路径；诊断只能读取执行证据 | 所有入口可直接解释，关闭诊断不改变输出；新增同构变体，改变输入或顺序时输出应相应变化 |

含标记的用例先验收第 2 步的输入与 IR 交接。第 4、5 步可在标量链验证后独立推进。第 6 步的完成值和异常传播依赖共享的边界操作。各步跑相关反例和首批套件；最终验收同时检查没有静默跳过局部 IR、按类名硬编码答案、从 expected 注入输入语义，或用渲染层重算业务逻辑。

## 预处理标记与局部注释的验收合同

输入是 AI 交付的规范源码。多语言模块保留声明归属、所在函数、作用域和源码位置。声明标记补足绑定信息；局部指令占据一条实际语句的位置，按所在分支和执行次序生效。类型、变量和调用目标须与周围原生代码一起解析。

| 首批输入语法 | 应交付给统一 IR 的信息 |
|---|---|
| Java 字段的 `@EntryState`、JS 声明的 `@entryState`；前端 `@entryInputs`、`@componentProp` | 分别绑定已有状态根、宿主输入和原组件属性入口。同名形参与字段保持不同来源；`@entryInputs` 的声明位置不提前实际读取。 |
| Java 的 `@External` 和方法签名、前端的 `@external`、`@callback`、`@param`、`@returns`、`@rejects` | 建立端口、参数、返回及异常类型。遇到实际调用才记录 S 并绑定该次完成值；声明本身不触发调用。 |
| Java 的 `@normalizer.annotations.Nullable`；JSDoc 的 `@type`、`@typedef`、`@property` | 解析参数的可空性和宿主类型声明，保留记录字段。普通类型默认非空；文本 intrinsic 按被引用的声明解析为有定义的纯操作。 |
| Java 与 JS 的 `/* @normalizer-ir … */` | 宿主解析器提取原位置的块；共享语法负责赋值或累加、关系筛选与排序、`sum`、`first … else`、区间 `count`，以及写入的 `returning affected_rows / atomic / throws`。行别名、列和外部变量分别绑定，IR 保留操作与完成合同。 |

**本里程碑独立验收三件事。** ① 对实际交付的 Java/JS 切片检查入口身份、声明绑定、操作数、类型和源位置；同一个局部指令在等价输入下应得到相同的类型化操作。② 用变体区分语义：交换同名字段与参数、改变排序键、将调用移入条件分支；用拼错保留标记、贴错声明、未绑定列名和缺失完成合同检查诊断。普通业务注释照常处理。③ 通过正式入口核对完整 PERS，包括调用是否真正发生、S 顺序和异常条件。只有最终字符串相等，不能单独证明前两项。

原始 Mapper 的 `@Select`、`@Insert`、`@Update`、`@Param` 是 AI 建立局部关系语义的来源证据。首批示例经过 diff 后交付的是原位置的关系或 SQL 写入合同，验收时以实际交付文本为准。

## 模块边界与退役条件

- **语言适配与共享扩展。** Java 的声明、注解和语句位置，以及前端模块的组件入口、宿主绑定和等待位置，各由其语言模块读取。两端遇到相同的关系、外部调用、读取或写入语义时，交付同一套类型化 IR 节点。局部扩展无法分析必须在其源位置诊断。不能让注释在解析时消失，也不能要求预处理预先算出条件和 R。
- **统一 IR。** 保留入口身份、声明类型、来源路径、局部操作和控制流。真实参数与适配器引入的参数分别记录。长期目标是语言模块直接交付这份 IR；当前前端借 Java 签名把语义递交给内核的载体可在两条语言入口都接通后退役。
- **在线执行和投影。** 执行器维护符号值、对象身份、分支条件、堆写和带顺序的 S／完成值。两个可能别名的对象不能因为有两个参数名就判成不同。投影只做业务来源命名、内容展开和序列化，不能靠重播行为再求 R。执行器直接交付符号存储、顺序事件与完成状态，投影只消费这些结果。
- **独立判据。** 每个主要能力都有一个改变结果的反例。例如把阈值改一、让重试第二次成功、让异步等待前后读取的可变状态不同。相同结构换掉方法名或局部名应保持结果。结构化 YAML、源码可解释的行为和在线架构三者分别验收。对重复分支和深调用记录运行时间、峰值活动路径和表达式规模，以同一输入和构建比较。
